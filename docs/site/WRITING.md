# 文档写作规范

本页约束 `content/` 下所有面向读者的中文正文。它把三个技能的要求落到本站：自然中文表达规范负责措辞与文体，ux-writing 负责页面职责与信息取舍，final-state-writing 负责只描述当前状态。改稿前先读一遍，改完按第五节的清单自查。

页面里的代码、标识符、默认值、参数名、链接和构建标记属于接口事实。措辞可以重写，事实按原样保留；拿不准的句子保持不动，比改错更有价值。

## 一、每页先交代读者处境

四种页面各有自己的第一段，读者读三行就应该知道自己在哪、读完能做什么。

| 体裁 | 第一段写什么 | 不写什么 |
| --- | --- | --- |
| 教程 | 这一课在前一课基础上多做哪件事，做完能观察到什么 | 接口全貌、机制原理 |
| 指南 | 什么情况下需要动手，解决的是哪一个具体问题 | 概念综述、历史沿革 |
| 概念 | 要解释的现象或容易混淆的区别，以及它影响哪些实际决定 | 操作步骤、字段清单 |
| 参考 | 这组符号的用途与导入路径，调用者需要自己承担什么 | 入门讲解、后续规划 |

参考页不要用无主语的短句开头。读者点进来时手里只有一个符号名，第一段要替他把符号和场景接上。

> 改前：目录保存数据，运行映射在实际访问主体时解析驱动。
>
> 改后：主体目录保存身份与主观资料，与具体驱动分开。`ActorStore` 在真正访问某位主体时才按记录里的驱动名称建立实例，因此同一份目录可以配规则主体，也可以配模型主体。

教程页要让读者一眼看到落点，并说明沿用哪一份前面的产物。指南页先给判断条件，再给命令。

> 改前：本页将一个实验计数器接入共享存储，验证声明、初始化、服务取得和退出流程。
>
> 改后：下面这个插件给环境加一个计数器，把它写进共享存储，并让另一位消费者读到。它同时演示插件如何声明依赖、申请初始化、取得服务和在退出时释放资源。先完成[基础安装](../start/installation.md)。

## 二、把动作写出来

中文里连续的名词会把关系压掉，读者看不出谁对谁做了什么、在什么条件下成立。遇到这种情况就展开成动词句。

- 被压成名词的动作要还原：`验证低风险类型判断替换` → `先用风险较低的办法替换类型判断，再验证程序是否仍然正确`。
- 省略关系的长名词串要补回连接词：`主体并发配置` → `主体并发的配置` 或直接写 `配置主体并发`，看句子实际在说什么。
- 一句话里出现三个以上名词性短语时，拆成两句。

## 三、不用抽象工程词

下列词在正文里默认不用；确有必要时，写出它指的实际动作、对象和完成条件。代码标识符、原文引述和用户确认过的术语不受限制。

`合同`、`闭合`、`冻结`、`夹具`、`回放`、`对齐`、`落地`、`打通`、`承接`、`沉淀`、`收口`、`赋能`、`抓手`、`闭环`。

`合同` 是本站出现最多的一个，它通常指某件事的规则、条件或要求，直接写清楚即可。

> 改前：游标失效时按来源的版本合同重新读取。
>
> 改后：游标失效时，重新读取该来源，并按新返回的版本继续。

> 改前：运行合同中的有效容量与激活上限应与实际计划一致。
>
> 改后：`RunContract` 里记录的容量与激活上限，应当和计划实际使用的值一致。

`闭环` 说明的是“能被验证的一整套过程”，把过程本身写出来。

> 改前：完成“执行—读取—继续”的最小闭环。
>
> 改后：完成一次执行、读取结果、再从完整步骤继续运行。

## 四、句子和段落

- 句长随内容变化。交代条件或因果关系时用完整长句，给出结论或动作时用短句。
- 不连续使用同一种句式，也不为每段配一句概括。
- 少用“它”“这”“其”连续指代。上下文里可能出现两个对象时，重复名称。
- 不用“值得注意的是”“综上所述”“换言之”“简单来说”这类固定衔接。让后一句自然承接前一句。
- 不用“不仅……更……”“既……又……”把单层信息包装成两层。
- 段落能讲清楚关系时就用连续正文。清单留给需要逐条执行的步骤，表格留给需要按同一列反复比较的多行内容。
- 只描述当前实现。不要写“不是 A 而是 B”、不要写被放弃的做法、不要为已经正确的写法补免责声明。

## 五、交付前自查

1. 遮住英文原词和源码，只读中文，是否仍然知道每句话在说什么。
2. 第一段是否回答了“这页解决什么问题、我读完能做什么”。
3. 是否引入了原文和源码都没有的数字、评价、因果或承诺。
4. 是否把某页已经讲清楚的字段表、参数表又抄了一遍。重复的应该删掉，只留链接。
5. 章节标题是否说明了内容，而不是只有一个名词。
6. 改动是否保持了原有篇幅量级；不要为了显得完整而扩写。
7. 运行站点构建并检查内部链接与锚点，确认改名标题没有打断别页的跳转。

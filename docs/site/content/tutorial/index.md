# 循序教程

这条路线从一个小型交流研究出发：先用规则确定主体与步骤，再给主体加入对话、资料读取和行动，最后学习模型认知、记忆与运行检查。每一课都说明要操作哪个程序，以及如何从保存下来的事实确认结果。

## 按手上的问题选一条路线

先完成[第一次运行](../start/quickstart.md)，再选下面任意一条。规则路线全部在本地执行；模型路线先用确定性提供方把完整驱动跑一遍，接入真实服务的配置另外做。

| 路线 | 顺序 | 学完后能做什么 |
| --- | --- | --- |
| 编写第一份实验 | [运行计划](first-plan.md) → [主体](actors.md) → [轮次对话](conversation.md) | 安排主体、机制、阶段与测量 |
| 让主体取得资料并行动 | [信息读取](files.md) → [行动](actions.md) | 完整读取授权资料，检查行动结果 |
| 认识模型主体 | [模型驱动](llm.md) → [记忆](memory.md) | 理解完整输入、工具循环与三项记忆策略 |
| 读懂和继续运行 | [结果](results.md) → [恢复](recovery.md) → [观察](observation.md) | 读取实际工件，从完整步骤创建新运行 |

## 命令在哪执行，代码块怎么用

终端命令都在安装好的源码仓库根目录执行。`runs/hello` 放首次规则运行的产物，`runs/conversation` 放交流实验的产物，模型组合另外用一个新目录。

每一次 `--output` 都指向尚未存在的目录；重做某一课时换一个运行名，读取命令里的路径也要一起改。带文件名的完整程序可以保存后直接运行；标为“替换片段”或“装配片段”的代码要放进该页说明的已有程序。公开示例的源码链接指向[本站构建提交](../start/version.md)，方便核对细节。

看到预期输出之后，再做页面末尾的小修改。每次修改都保留原来的结果，这样能比较变化来自哪一项研究条件。现在从[创建自己的运行计划](first-plan.md)开始。

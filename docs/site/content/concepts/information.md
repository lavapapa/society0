# 信息、授权与分页

信息接口要回答三个问题：主体能发现什么、能读到什么、读到一半还能不能接着读。这三类判断决定主体能发现、读到和续读什么，你给主体看什么、看到什么粒度，最后都要落到这里。规模变大之后，分页和按范围读原文仍然要让主体拿得到完整的相关材料。

## 发现、读取、执行各判一次

`Information` 把绝对路径路由到提供者，`Actions` 按资源引用找到可调用的模板。权限函数分别接收三类操作：

| 操作 | 判断内容 |
| --- | --- |
| `discover` | 能否发现目录、资源或行动 |
| `read` | 能否读取对应正文 |
| `invoke` | 能否执行指定资源上的行动 |

行与字段的授权也由提供者负责。例如，对话历史通过 SQL 条件限定收件人。能看到一个目录，不等于能看到里面每一行；页面的 `total` 应当是实际授权范围内的总数。

Runtime 给 Driver 绑定主体，工具调用使用这个身份。机制根据当前事实重新判断资格，模型参数里写的名字不会被当作操作身份。

## 目录项和业务记录有什么区别

根目录返回的是挂载入口，目录项带 `kind="directory"`。进入 SQL 资料路由之后，普通的 `list` 或 `query` 返回业务记录，记录原有的 `kind` 字段保留其业务含义。`list_files` 则提供文件投影的条目。

`Query` 描述字段、过滤、排序、页长和游标，具体支持到哪一步由提供者定义。SQLInformation 可以把正文列表示成可读路径和字节数，先返回轻量元数据，再按需读全文。需要真实调查、花费资源或改变环境的操作，应该通过行动表达。

## 游标为什么会失效

分页要求续页仍然对应同一个选择范围，所以游标通常绑定运行、主体、Moment、查询条件，以及有关数据或权限的版本。注册表发生变动时，还要算上路由或行动的登记代次。

举例来说，读完推荐的第一页之后，一条新帖子改了排名，旧游标指的就不再是同一份排序的下一段。这时调用者重新请求第一页，或者固定到一个完整步骤上做分析。与业务无关的 Thread 诊断写入不该让业务页失效；提供者声明自己实际依赖哪张表，就能把版本变化的影响缩小到这些表上。

`Moment` 描述访问语境，`revision` 描述数据版本。给请求填一个过去的时间，不会自动建立过去的数据库快照。要固定读取历史，请用[完整步骤只读视图](complete-steps.md)。

## 单页装不下时怎样读到完整原文

有页数上限的返回里带 `total` 与 `next_cursor`。按文档范围读的返回里带 `total_bytes` 与 `next_offset`。顺着这些位置继续读，直到取完整个集合或整段正文；超过单页预算的记录，用原文引用继续取得。

字节偏移可能切开一个 UTF-8 字符。读取端先拼接原始 bytes，再解码文本或 JSON。资料可能更新时，沿用返回的预期版本；版本过期之后重新定位，避免把两个版本拼成一份正文。

分页限制的是单次结果的大小，完整总数怎么算、过滤和采样怎么做，仍然取决于提供者的查询方式。显式请求完整大值，也保留它实际物化的成本。实践从[读取教程](../tutorial/files.md)开始，自定义 SQL 路由见[信息指南](../guide/information.md)。

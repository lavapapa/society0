# 信息、授权与分页

信息接口把“主体能发现什么、读到什么、还能继续读什么”变成明确合同。规模增长后，分页与原文范围读取仍应保留主体取得完整相关材料的能力。

## 一、三个资格分别判断

`Information` 将绝对路径路由到提供者，`Actions` 按资源引用找到可调用模板。权限函数分别接收三类操作：

| 操作 | 判断内容 |
| --- | --- |
| `discover` | 能否发现目录、资源或行动 |
| `read` | 能否读取对应正文 |
| `invoke` | 能否执行指定资源上的行动 |

提供者还负责行与字段的授权。例如，对话历史通过 SQL 条件限定收件人。可以看到目录，并不意味着拥有其中所有行；页的 `total` 应为实际授权范围内的总数。

Runtime 给 Driver 绑定主体，工具调用使用这一身份。机制根据当前事实重新判断资格，避免把模型参数中的主体名当作操作身份。

## 二、目录和记录有什么区别

根目录返回挂载入口，目录项带 `kind="directory"`。进入 SQL 资料路由后，普通 `list` 或 `query` 返回业务记录，记录原有的 `kind` 字段保留其业务含义。`list_files` 则提供文件投影的条目。

`Query` 描述字段、过滤、排序、页长和游标，具体支持范围由提供者定义。SQLInformation 可以把正文列表示成可读路径和字节数，先返回轻量元数据，再按需读全文。需要真实调查、花费资源或改变环境的操作应通过行动表达。

## 三、游标为什么会过期

分页要求续页仍对应同一个选择范围。游标通常绑定运行、主体、Moment、查询条件和有关数据或权限版本。注册表变动还涉及路由或行动的登记代次。

例如，读取推荐第一页后，一条新帖子改变了排名，旧游标就不再表示相同排序的下一段。调用者重新请求第一页，或选择固定完整点进行分析。无关 Thread 诊断写入不应使业务页失效；提供者通过声明实际依赖的表，缩小版本变化范围。

`Moment` 描述访问语境，`revision` 描述数据版本。给请求填过去的时间不会自动建立过去的数据库快照。固定历史读取使用[完整点只读视图](complete-steps.md)。

## 四、字节预算与完整原文

有限页面返回 `total` 与 `next_cursor`。文档范围返回 `total_bytes` 与 `next_offset`。按这些位置继续读取，直到完整集合或正文结束；超过单页预算的记录用原文引用继续取得。

字节偏移可能切开一个 UTF-8 字符。读取端先拼接原始 bytes，再解码文本或 JSON。资料可能更新时，沿用返回的预期版本；版本过期后重新定位，避免把两个版本拼成一份正文。

分页限制单次结果大小，完整总数计算、过滤与采样仍取决于提供者的查询方式。显式请求完整大值也保留其物化成本。实践从[读取教程](../tutorial/files.md)开始，自定义 SQL 路由见[信息指南](../guide/information.md)。

# 概念与边界

这一组页面讲运行内部的分工：一件事由谁负责，身份在什么时候有效，时间又怎样对应。带着自己遇到的疑问直接跳到对应那篇最省事；第一次上手请先按[教程](../tutorial/index.md)的顺序操作，只想查参数就翻[参考](../reference/index.md)。

## 共享环境里谁维护什么

- [共享环境与机制](environment.md)：为什么两个对话平台可以共享主体，又分别维护自己的事实？服务依赖与数据依赖怎样配合？
- [主体与激活](activation.md)：一个持久主体怎样获得一次临时 Session？步骤、业务时间和 Moment 分别在哪里使用？
- [并发的三个层次](concurrency.md)：主体并行、请求并发和进程计算各解决什么问题？

## 主体能看到和记住什么

- [完整会话与增量认知](cognition.md)：已经提供的材料怎样保留？新材料的位置和呈现确认如何保存？
- [信息、授权与分页](information.md)：发现、读取和执行的资格怎样区分？游标为什么会过期？
- [记忆与检索](memory.md)：经验、写入时间和可重建索引怎样关联？三种记忆行为如何分别配置？

## 一次运行留下了什么

- [完整步骤与恢复](complete-steps.md)：当前状态、完整步骤、可执行分支和只读分析分别支持哪些操作？
- [仿真与研究证据](research.md)：规则与模型假设如何进入实验？验证软件行为与得出经验结论分别需要哪些依据？

这些边界会落到具体的研究设计上。主体处于开放等待时，步骤可以正常结束，而未完成的决定默认会拦住发布；预览推荐与真正呈现给主体，效果不一样。读专题时带着自己机制里的一个实际问题，读完之后按文末给出的指南去装配。

# 共享环境与机制

一次 Society0 运行里，所有主体共用一个环境。环境内部的规则与事实由机制插件负责，主体通过信息和行动接口参与其中。哪些规则放进机制、哪些留给驱动，这道分工就在这里划开；把两边的职责分清楚，才讲得通一个主体的选择怎样改变另一位主体随后面对的世界。

## 时空可组合性带来了什么启发

**Society0 Next 在共享环境、显式依赖和资源生命周期这三处设计上，参考了 [DeepSeek Harness（DSH）](https://github.com/deepseek-ai/deepseek-harness) 的时空可组合性理念。** DSH 的 everything-is-a-plugin 架构由 [Cordis](https://github.com/cordiverse/cordis) 支撑。相关论文 [*A Programming Paradigm for Spatiotemporal Composability*](https://arxiv.org/abs/2608.25512)（Yifan Shi、Wei Zhang、Tianyi Cui，2026）讨论了这套设计，其[官方论文仓库](https://github.com/cordiverse/paper)提供摘要与材料。

这里的“空间”指组件之间的依赖与组合关系，“时间”指组件从安装到移除的生命周期；仿真的业务时间由 Schedule 表达，地理空间由领域机制建模。论文用可撤销副作用（revertible effects）说明移除组件时怎样把它的副作用一并撤销，用 reactive coeffects 说明依赖怎样被声明并得到响应式管理，这些机制用在了 Cordis 的配置协调与热重载上。

Next 采用这套思路的方式是：插件通过声明依赖来共享服务，通过可以注销的注册和明确的资源所有权管理生命周期，不同机制在同一个环境里组合起来。已经实现的范围限于静态 `includes` 展开、schema 与服务这两张依赖 DAG，以及作用域清理。Cordis 的动态重配与任意热替换、论文给出的形式化定理保证，以及让已经记录的交易事实可以反向撤销，都不在 Next 承诺之内。

## 同一批主体可以同时参加多个机制

在[对话教程](../tutorial/conversation.md)中，四位主体同时参加 `work` 和 `commons`。两个机制分别保存配对和消息，借用同一份 ActorDirectory，共用同一个 StageStore。`work` 的发信行为影响其收件箱，`commons` 保持自己的当前轮与历史。

一个具名插件可以提供多个服务：对话机制提供 `mechanism`，信息插件提供 `information` 与 `actions`。使用方按 `(插件名, 服务名)` 引用它们，装配时靠这个名字定位；主体身份仍然保存在目录里。

业务事实归领域机制所有，合法的写入方式也由它规定。Driver 决定要申请哪个操作，处理器在真正写下去的那一刻核验资格，同时更新事实、当前投影和必要的索引。规则驱动与模型驱动因此受同一套约束。

## 为什么声明分成两张依赖图

考虑“先登记参与者，再建立对话成员，同时让主体驱动读取对话材料”的情况。初始化数据的先后与服务借用的先后，分别由两张图表达：

| 声明 | 它回答什么 | 例子 |
| --- | --- | --- |
| `schema_requires` | 数据初始化前需要哪些插件的数据先准备好？ | 对话成员外键依赖主体目录 |
| `requires` | 安装和使用服务时借用哪些提供方？ | 驱动工厂借用认知输入服务 |
| `includes` | 此配方静态包含哪些子插件？ | 社交配方包含内容、关系、推荐等叶插件 |

`compose` 先建立或恢复共享存储，再安装服务。两张依赖图各自检查有没有缺项和环；`includes` 展开之后，名称必须唯一。从已有的完整点恢复时，持久数据取自所选状态，服务重新装配一遍，初始记录不会被重新插入。

业务执行顺序由 Schedule 与 Phase 给出，例如“先配对、后发信”写在阶段列表中。服务安装的早晚只决定资源什么时候可用，每一步先做什么仍要研究者自己写明。

## 谁负责关闭资源

创建资源的插件登记关闭动作，借用资源的消费者声明依赖。挂载 Information 和注册 Action 都会返回注销函数，可以和资源关闭放在一起托管；退出时先撤回入口，再释放资源。

关闭一次运行时，先排空 Runtime，再结束 worker，最后按相反的顺序关掉普通资源。这样正在写入的任务能得到保护，不会出现模型请求或记忆作业还在跑、底层连接已经先断开的情况。安装到一半失败，已经登记成功的部分同样会被撤销。

一个可以重复使用的插件因此要说明三件事：自己保存哪些事实、借用哪些服务、创建哪些需要关闭的资源。具体实现从[插件指南](../guide/plugins.md)开始；选择 preset、叶插件和同名实例的装配方法见[组合指南](../guide/composition.md)。

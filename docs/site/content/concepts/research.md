# 仿真与研究证据

Society0 把环境规则、主体能看到的资料、作出的决定和结果一起放进一次可以检查的运行里。仿真跑出来的差异要变成一个关于现实的结论，还得交代这些设定对应现实中的什么、跟什么做了比较，以及观察到的差异稳不稳。这一页说明这几件事分别需要什么材料。

## 先把环境和要观察的东西定下来

先写清社会情境、主体能取得的资料、可以执行的行动与行动后果。例如研究消息可信度时，需要说明消息来源、可见范围、补充信息、是否允许交流，以及可信度在何时测量。

随后区分具备感知和决定能力的主体，与帖子、组织记录、图节点或流程槽位这类对象。每个对象都成为独立的模型主体，会引入额外的行为假设；只有当前研究确实需要它自主判断，才赋予它相应的驱动。

把干预条件写进机制或配方，把指标写进 Results。社交推荐中的候选池、权重、筛选条件和呈现数量都会影响主体接触到的信息，应作为实验条件保存。

## 规则主体和模型主体各自带来什么假设

规则主体适合确定性机制、基线与对照，它的行为假设以 Python 逻辑呈现。模型主体适合语言理解、经验、身份与访谈这类任务，输出同时依赖模型、提示、完整输入、工具与请求参数。

两类驱动通过共同的信息和行动入口参与，这样环境约束容易保持一致。比较它们时，还要核对实际输入与可行动作是否相当。缩短历史、隐藏工具或调整预算都可能改变主体行为，不能直接解释成单纯的计算优化。

模型给出的理由可以作为定性材料。要归因到某个机制上，需要对照、消融、重复运行，或者采用其他适合这个研究问题的识别方法。

## 四层证据，各检查各的

| 层次 | 典型问题 | 可用材料 |
| --- | --- | --- |
| 软件行为 | 动作是否执行？恢复后事实是否一致？ | 确定性消费者、逐值比较、完整工件 |
| 提供方接入 | 端点是否接受参数并正确返回工具与向量？ | 真实请求与响应、失败诊断 |
| 模型内观察 | 在既定条件下产生了什么差异？ | 共同历史、处理条件、Results 与 Thread |
| 现实有效性 | 这些差异能否解释或预测现实？ | 数据口径、校准、现实标签、样本外评估 |

用脚本写成的离线提供方可以验证协议与持久化链路，真实模型请求则进一步验证具体端点。两者各自服务于上面相应的层次，需要哪些经验层面的验证，由研究者自己判断。

## 让结果以后还能被解释

每次运行保存源码、依赖、公开配置、业务时间和预算身份。分析时回到完整步骤，保留主体、阶段、原文与指标之间的来源关系。中途干预从共同的可信点建立独立运行，比较时限定在共同完成的范围里。

失败与未完成同样属于研究记录。输出截断、硬预算耗尽和业务拒绝各有不同的原因，解释结果时保留这些区别。恢复之前先判断错误从什么时候开始影响事实和认知，再选择还能接着用的完整步骤。

第一次研究宜从主体少、步骤少的 pilot 开始，把实际输入、行动、记忆与测量都走一遍。具体机制按[内置能力指南](../guide/builtin.md)与自己的领域代码确定。

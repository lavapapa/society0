# 仿真与研究证据

Society0 帮助研究者把环境规则、主体信息、决定和结果放进可检查的运行。研究结论还需要说明这些设定怎样对应现实、比较了什么，以及观察到的差异是否稳健。

## 一、从环境与可观察量开始

先写清社会情境、主体能取得的资料、可以执行的行动与行动后果。例如研究消息可信度时，需要说明消息来源、可见范围、补充信息、是否允许交流，以及可信度在何时测量。

随后区分具备感知和决定能力的主体，与帖子、组织记录、图节点或流程槽位等对象。每个对象都成为独立模型主体，会引入额外行为假设；只有当前研究确实需要自主判断时，才赋予它相应驱动。

把干预条件写进机制或配方，把指标写进 Results。社交推荐中的候选池、权重、筛选条件和呈现数量都会影响主体接触的信息，应作为实验条件保存。

## 二、规则与模型各引入什么假设

规则主体适合确定性机制、基线与对照。其行为假设以 Python 逻辑呈现。模型主体适合语言理解、经验、身份与访谈等任务，其输出同时依赖模型、提示、完整输入、工具与请求参数。

两类驱动通过共同信息和行动入口参与，便于保持环境约束一致。比较它们时，还需核对实际输入与可行动作是否相当。缩短历史、隐藏工具或调整预算都可能改变主体行为，不能直接解释为单纯计算优化。

模型给出的理由可以作为定性材料。若要归因于某个机制，需要对照、消融、重复运行或其他适合研究问题的识别方法。

## 三、四层证据分别检查

| 层次 | 典型问题 | 可用材料 |
| --- | --- | --- |
| 软件合同 | 动作是否执行？恢复后事实是否一致？ | 确定性消费者、逐值比较、完整工件 |
| 提供方接入 | 端点是否接受参数并正确返回工具与向量？ | 真实请求与响应、失败诊断 |
| 模型内观察 | 在既定条件下产生了什么差异？ | 共同历史、处理条件、Results 与 Thread |
| 现实有效性 | 这些差异能否解释或预测现实？ | 数据口径、校准、现实标签、样本外评估 |

离线脚本提供方能验证协议与持久化链路。真实模型请求进一步验证具体端点。两者各自服务于相应层次，研究者再决定需要哪些经验验证。

## 四、让结果能被重新解释

每次运行保存源码、依赖、公开配置、业务时间和预算身份。分析时回到完整步骤，保留主体、阶段、原文与指标之间的来源关系。中途干预从共同可信点建立独立运行，比较共同完成范围。

失败与未完成同样属于研究记录。输出截断、硬预算耗尽和业务拒绝各有不同原因，解释结果时保留这些区别。恢复前先判断错误首次影响了哪些事实和认知，再选择可继续使用的完整点。

第一次研究宜从少量主体和少量步骤的 pilot 开始，检查实际输入、行动、记忆与测量闭环。领域方法与论文改编可使用[研究 skill](../resources/research-skill.md)；这些指南提供设计方法，实际环境机制仍按[内置能力指南](../guide/builtin.md)与自己的领域代码确定。

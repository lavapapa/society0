# 最小概念地图

[第一次运行](quickstart.md)那一课已经留下了痕迹：一份工厂创建两位主体，调度排出两个时点，每次决定都存进一张表。这一页沿着这条真实发生过的链路，把最常出现的几个词放回它们所在的位置，方便你读后面的教程和参考。

## 从配置到完整步骤

```text
配置 → build(config) → RunPlan
                         ↓
                    compose 插件
                         ↓
Schedule → StepPlan → Runtime → Phase → 激活主体
                         ↓
                    发布完整步骤
```

`RunPlan` 把这次运行用到的 `RunContract`、插件和调度入口连在一起。`Plugin` 声明共享环境中的一部分，例如主体目录、轮次对话或结果存储。`compose` 先把数据建好，再安装服务；`Schedule` 随后把一份份步骤计划交给 `Runtime`。

首次运行用的 `SequenceSchedule` 给出业务时间 1、2，每步执行一次 `decide` 阶段。阶段激活 Alice 和 Bob，等两位都返回，再把值收进 `StepResult`。一步的全部工作结束之后，才会出现可以用于恢复的完整身份。

## 主体在链路里的位置

| 名称 | 在例子中的工作 | 下一层解释 |
| --- | --- | --- |
| `ActorRecord` | 保存 Alice 的身份与驱动标签 | [主体与激活](../concepts/activation.md) |
| `Driver` | 执行规则函数，或组织完整模型决定 | [主体与驱动教程](../tutorial/actors.md) |
| `Session` | 给本次激活绑定主体、时间、信息与行动入口 | [激活的作用域](../concepts/activation.md) |
| `Information` | 读取主体被允许取得的资料 | [信息与分页](../concepts/information.md) |
| `Actions` | 执行机制登记的业务操作 | [行动教程](../tutorial/actions.md) |

环境里所有主体共享机制保存的事实。Alice 给 Bob 发一条消息，Bob 的收件箱就跟着变；谁有资格发消息、消息按什么规则写进去，由对话机制维护。把 Driver 换掉，规则主体和模型主体就都能通过同一组信息与行动接口参与进来。

## 时间与记录回答的问题不同

步骤编号回答“已经完整完成了多少步”；业务时间回答“模型中现在是什么时候”。一个步骤可以代表一轮讨论、一个日期，也可以是你明确约定的时间跨度。`Moment` 把业务时间与阶段名称合在一起，给主体交互确定当前语境。它们的关系见[主体与激活](../concepts/activation.md)。

| 记录 | 回答的问题 |
| --- | --- |
| 机制状态 | 环境里实际发生了什么？ |
| `Thread` | 主体与模型进行了哪些完整交互？ |
| `Memory` | 主体保存了哪些可再召回的经验？ |
| `Results` | 本次研究记录了哪些指标、表和决定结果？ |

规则示例直接把结果记下来，不会建立模型 Thread。模型与记忆各有自己的服务和生命周期。实时诊断可以显示正在执行的工作；要恢复，或者固定一份历史来分析，都从[完整步骤](../concepts/complete-steps.md)出发。

带着这张地图进入[创建自己的运行计划](../tutorial/first-plan.md)，把主体、规则与测量写进自己的程序。需要深入理解某个问题时，再从[概念目录](../concepts/index.md)选一篇阅读。

# 按任务使用指南

跑通[首次运行](../start/quickstart.md)之后，指南按你手上要解决的问题组织：把研究机制装进共享环境、给主体接上资料和模型，或者运行结束后恢复、导出和排查故障。标为“完整程序”的文件可以保存后直接运行，标为“装配片段”的代码要放进已有计划；命令都在所选 Next 源码仓库根目录执行。

## 把机制装进共享环境

从第一个机制开始，逐步接入持久事实、运行服务和主体输入。

| 要完成的任务 | 入口 | 完成后检查 |
| --- | --- | --- |
| 为研究新增数据表和领域服务 | [编写插件](plugins.md) | 服务能取得，退出时资源释放 |
| 使用常用配方、替换服务 | [组合插件](composition.md) | 运行清单反映实际展开图 |
| 多种驱动复用一份人口资料 | [主体目录](actor-directory.md) | 持久标签解析到实际工厂 |
| 让主体接收多个信息来源 | [组合认知](cognition.md) | 每个来源保留独立位置与完整原文 |
| 向主体公开表和文档 | [信息入口](information.md) | 授权、总数及字节续读一致 |
| 安排阶段、时间和恢复次序 | [调度](schedule.md) | 完整步骤和业务时间对应 |

## 给已有的环境加能力

参与者能做什么由领域机制决定，模型、文件等资源为这些行为提供执行条件。

- 需要空白实验、伙伴对话或社交传播：[内置机制](builtin.md)，再进入[社交推荐与曝光](social.md)。
- 要让主体用模型作决定、还要单独配嵌入：[模型服务](models.md)；用账户额度接入见[订阅](subscription.md)。
- 要让主体保存笔记、执行命令：[工作区与 Shell](workspace.md)。
- 要放进大批不再改动的原始材料：[数据集](datasets.md)。
- 想减少互不相关工作之间的等待：[三类并发](parallel.md)，先分清要并发的是主体、网络请求还是进程计算。

## 运行之后的恢复、展示与排查

先看观察接口确认这次运行发布了哪些完整步骤，再决定继续恢复、做只读分析还是导出展示。

[存储与恢复](storage.md)讲怎么从完整步骤建立新分支、什么时候可以清理资源；[结果教程](../tutorial/results.md)通过 Python 分页读取运行保存的指标和原文；安装、装配或运行时出错，按[排查指南](troubleshooting.md)定位第一次失败发生在哪一步。

想直接从一个能跑的计划开始，先看[可执行示例](examples.md)。参数、返回值这类精确内容查[接口参考](../reference/index.md)。

# 按任务使用指南

先完成[首次运行](../start/quickstart.md)，再按正在解决的问题选择一条路径。指南中的完整文件可保存运行；标明“接线片段”的代码需要放入已有计划。终端命令均从所选 Next 源码仓库根目录执行。

## 一、搭建环境

从一个机制开始，将持久事实、运行服务和主体输入逐步接入共享环境。

| 要完成的任务 | 入口 | 完成后检查 |
| --- | --- | --- |
| 为研究新增数据表和领域服务 | [编写插件](plugins.md) | 服务能取得，退出时资源释放 |
| 使用常用配方、替换服务 | [组合插件](composition.md) | 运行清单反映实际展开图 |
| 多种驱动复用一份人口资料 | [主体目录](actor-directory.md) | 持久标签解析到实际工厂 |
| 让主体接收多个信息来源 | [组合认知](cognition.md) | 每个来源保留独立位置与完整原文 |
| 向主体公开表和文档 | [信息入口](information.md) | 授权、总数及字节续读一致 |
| 安排阶段、时间和恢复次序 | [调度](schedule.md) | 完整步骤和业务时间对应 |

## 二、选择能力

领域机制决定参与者能做什么，模型与文件服务为这些行为提供执行条件。

- 需要空白实验、伙伴对话或社交传播：[内置机制](builtin.md)，再进入[社交推荐与曝光](social.md)。
- 需要模型决策与独立嵌入：[模型服务](models.md)；账户计划额度接入见[订阅](subscription.md)。
- 需要主体笔记和命令处理：[工作区与 Shell](workspace.md)。
- 需要大批不可变材料：[数据集](datasets.md)。
- 需要减少独立工作的等待：[三类并发](parallel.md)，先区分主体、网络请求和进程计算。

## 三、运行与交付

运行后先确认完整步骤，再选择分析、恢复或展示路径。

[存储与恢复](storage.md)说明新分支和资源清理；[工作台](workbench.md)将实际完整工件转换为静态 HTML；遇到安装、装配或运行错误时，按[排查指南](troubleshooting.md)定位首次失败边界。

想从现成计划开始，查看[可执行示例](examples.md)。研究问题、实验设计和证据解释交给[研究 skill](../resources/research-skill.md)组织；准确参数与返回值查阅[接口参考](../reference/index.md)。

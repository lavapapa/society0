# WorkBuddy 研究者流程试验 · 2026-10-03

本轮通过普通会话，以研究者口吻逐步提出请求，检验公开 Society0 skill 的首次使用流程。用户教程保存在 `../workbuddy-walkthrough.md`；本文件记录观察、障碍、修复和复测范围。

## 一、范围

沿安装或更新、选择入门路径、学习原理、设计小实验、检查配置、复制修改、运行、检查保存结果、分析的顺序推进。每一步核对用户是否知道下一步，AI 是否准确完成任务，页面与真实实验资料是否对应。保留旧会话与实验，新会话使用独立实验目录。

起点：公开 main 为 b5a1d24，WorkBuddy 5.7.3，已有 Society0 安装和旧实验。此次属于已有安装机器上的新会话验收，不能等同首次干净安装。使用应用当前默认模型，具体名称以截图和会话记录为准。

## 二、观察

### 2.1 自动操作输入

原生 Computer Use 粘贴出现旧剪贴板文字，直接输入丢失中文，设置值后发送按钮未启用。尚未发送错误内容。改用此前用户授权的 Open Computer Use；这属于操作工具问题，单独记录，不归为 Society0 skill 缺陷。

Open Computer Use 输入后仍出现文本与编辑器状态不同步。切换到旧任务再返回新任务，草稿恢复为正确的单条安装请求，发送按钮启用；核对后提交成功。截图 `../images/workbuddy/01-install-request.png` 保存了发送前状态。普通用户手动输入的体验未受此自动操作试验验证。

### 2.2 安装入口

发送：“帮我安装这个项目的 Society0 skill：https://github.com/lavapapa/society0 ，然后带我入门。”新会话为“安装并入门 Society0 skill”，独立工作目录 `/Users/marvin/WorkBuddy/2026-10-03-21-41-22`，界面模型名 Space-Bunny。

AI 自行识别已有安装，拉取公开仓库并确认一致。其后重复检查文件、在错误工作目录重试校验、提前查看 Python 环境及 runtime-quickstart，约两分钟尚在准备入门回答。这些观察涉及宿主安装行为与模型执行选择，尚不能全归因于 Society0。未发送额外技术纠正。

### 2.3 Luna 入门小试验

独立 gpt-6-luna，无会话历史，收到“第一次用 Society0，想先理解它，再试熟人转发对信任的影响，先带我开始，不运行”。实际只读 Society0 的 SKILL.md 与 researcher-onboarding.md（另读本机通用指令）。回复解释模拟用途与边界，结合研究现象提供入门选择和三个后续问题；没有启动安装或运行。它同时给出四个方向和三个后续问题，入口略有重复，但阅读负担与动作范围合适。本试验仅验证入门这一轮。

### 2.4 已有证据对应的小修订

领域文档目录明确适用阶段，让关键词只在需要领域方法时用于选文档；首次运行段落统一为“初始化检查后以小试运行验证服务与过程”；工作台指南用“可接触十条、实际注入三条”的例子说明机制资料与会话的区别，并要求机制模块呈现边界内资料。这些修改依据此前实际转换脚本和试验记录，尚待新的工作台行为复测。

### 2.5 原理学习与实验请求

安装确认耗时 2m24s。用户收到四种入口与四个后续问题，随后发送“先讲讲 Agent 能看到什么，用个生活例子解释”。30 秒后得到群聊例子，但又扩展到 Python 调用、内置 FoV 名称及实现细节（截图 `03-learning-response.png`）。第一轮安装回复还把默认解释器的导入失败表述为机器未装引擎；本机实际上有其他 Python 环境中的安装。

对应修订：引导将安装结果收敛为短确认并把技术细节留到需要时；日常例子讲解按研究者选择再展开代码；技术起步要求把导入失败限定在当前解释器并检查已有环境。

继续发送“我不太懂代码。先做个最小的例子，看看熟人和陌生人转发同一条消息时，Agent 的信任评分有什么不同。先让我检查配置。”这属于普通用户的理解反馈与下一阶段请求，没有提供实现方法。

### 2.6 引擎安装入口

WorkBuddy 按 runtime-quickstart 尝试 `pip install society0`，失败后自行改为对 `/tmp/society0-audit` 做可编辑源码安装。2026-10-03 核实 PyPI 项目页与 JSON 接口均为 404。仓库 README 一直采用源码安装，技术起步页中的发布包选项有误。已把该页统一到官方仓库源码安装，说明复用已有检出或克隆到持久目录；可编辑安装应保留源码目录。新的 WorkBuddy 流程目前仍使用原指南，保留它自行恢复的证据。

配置请求等待 5m16s 后仍停留于依赖安装，已生成六个 Agent 的两组实验源码与模型配置说明，没有配置工作台。通过界面停止该回复，再以普通用户口吻发送：“安装等了很久。先让我在内置浏览器的工作台里检查配置吧，运行环境请你自行处理。”这是一次用户催办；没有代写实验或提供技术解法。指南已明确配置页面可先交付，展示草稿与初始化检查结果分别标明，生成器依赖标准库。

### 2.7 配置工作台与复制变更

工作台请求耗时 1m49s。AI 找到现有 miniforge 环境，生成了配置工作台，但最后打开的产物是代码文件；点击 `workbench.html` 文件卡片后才显示实际页面。当前左栏只有整体、环境与两组概览，缺少独立 Agent 入口，普通消息环境被归为“制度实体”。指南已补充逐个 Agent 入口、分组语义与最终预览状态要求。

在环境配置中把消息时间 22:00 改为 23:00，右栏正确显示一条差异；读源文件确认仍为 22:00。自动复制被宿主内嵌预览限制，模板显示手动复制框。通过全选、复制、退出全屏、在同一会话粘贴，内容完整送达，未直接替 WorkBuddy 改实验。截图 04–06 保留配置页面、差异和手工复制步骤。这是一条已验证的正常恢复路径，教程记录具体操作。

首批 skill 修订以 21442b4 推送 main。本次 WorkBuddy 会话仍使用起点版本，尚未将新指南带来的效果计入本轮验证。

复制变更请求在 1m18s 后完成。检查源文件与实际页面：v001 保持 22:00，v002 为 23:00，版本下拉可切换，差异清空。AI 同时断言时间变化对研究“没有任何影响”，超过当前证据；同一变量的组间对照虽保留，消息刺激变化仍可能影响判断。此项保留为后续分析质量观察。

### 2.8 附件配置与真实试运行

经本地文件选择器附加预先授权的模型配置文件，未将凭据写进提示词。发送“模型配置在附件里。请先估算 v002 这次小实验的费用，预计一元以内就试跑，并把结果更新到工作台。”AI 读取配置后估计典型约 0.50 元、保守情景约 0.61 元，做完零 tick 检查后开始试运行。报价来自配置附件，尚未与账单核对。

启动阶段两次发生路径错误：后台命令工作目录与预期不同，随后启动脚本对父目录的计算又多退一级。AI 自行修复，期间提前声称试运行已经开始。对应指南补充后台命令明确工作目录或绝对路径，确认产生实验记录后再报告开始。两次路径失败均在真实调用前，后续 `pilot-001` 已产生真实线程与资源记录。

`pilot-001` 最终为 `failed=false`、两轮完成，六个主体测量成功。实际保存用量为 24 次 LLM 调用、11,732 输入 token、1,726 输出 token，7 次 embedding 调用。熟人组评分为 2、2、2，陌生人组为 1、2、2。按所给 LLM 费率换算约 0.057 元；缺少账单和 embedding token 用量，AI 将其称作“实际费用”不准确。

### 2.9 工作台证据与分析

第一份结果工作台生成了 Agent 快照，却没有左栏 Agent 入口；会话为空。发送“我想逐个查看每个 Agent 在各轮能接触的信息、真实会话和评分。请补齐工作台并打开给我检查，先不要再运行实验。”后，AI 增加六个主体与十二个线程会话，但将第二轮评分表放进第一轮，且把全局记忆检索结果写进每轮机制说明。

继续用普通用户反馈：“请检查各轮资料是否对应当时：第一轮为何已有第二轮评分？会话缺失的原始输入也请明确标注。先不重跑实验。”AI 2m31s 后移除第一轮评分，补充第二轮输入缺失说明。实查引擎记录：查证线程保存六条消息；测量线程仅保存一条模型输出，请求事件只有消息数等元数据。工作台须展示缺失范围，现有记录无法恢复原始输入；记忆提炼的附加调用也不能据此称为完整会话。此次没有修改引擎或重跑实验。

第二次修正后仍有边界问题：机制卡正文仍声称第二轮注入内容可在右栏确认，与原始输入缺失说明矛盾；可接触资料仍被放到另一个标签，默认机制卡仅有解释。配置初稿没有独立 Agent 入口，普通消息环境标为制度实体。这些未作为通过项。

AI 初次分析把“理由反复提到官方通知”解释成权威信号盖过关系信号，又建议比较熟人转发的辟谣消息和未获背书消息来验证关系作用。现有比较不能支持该机制归因，后续设计同时改变纠正信息且没有改变熟悉度。指南补充观察与机制假设的区分，以及后续对照的变量、固定条件和检验目标。

修订经独立 Luna 审阅后，补清成功提炼才关闭线程，以及会话范围示例；示例在实际十二条线程上执行通过。`9f08d69` 推送 main 后，向 WorkBuddy 发送：“请更新 GitHub 上的 Society0 skill，按新版指南重新整理工作台，并分析现有结果：哪些是观察，哪些是假设，下一步怎样对照？先不重跑。”此步骤是显式更新后的复测，与前面的原版使用分开记载。

更新后 AI 明确读取新版工作台与分析指南，分析开始区分观察与假设，并纠正辟谣条件混杂。不过仍出现“4 组各 8 人，共 24 人”的算术错误、把重复后差异消失当成原结果为噪声的证明、用任意固定分数基线推断模型在判断。用户式追问后生成 `result-review-v002.md`；报告又给出“每组至少 8 个”的无依据建议。最后反馈要求撤去该阈值，并继续补齐无运行版本的逐主体入口、机制卡内资料与可接触状态判定。新版指南对应收紧示例结构与分析交付核对，未把这些反馈后的结果记为零干预成功。

### 2.10 预览恢复

内嵌 HTML 一度仍显示页面，但自动操作无法切换控件，原生截图也出现局部空白。原生与 Open Computer Use 都试过，未据此认定模板渲染失败。关闭旧 HTML 标签，再点击对话中的文件卡片后，原生接口重新读到页面控件；版本、运行、Agent 与轮次均可切换，截图恢复完整。教程记录关闭后重新打开这一用户可执行的路径。

### 2.11 Luna 独立完整流程试验

无历史的 Luna 在独立临时目录处理两个 Agent 的同类研究，提供已有解释器和预先授权的模型配置文件，费用预期低于 0.2 元。此测试与 WorkBuddy 默认 Space-Bunny 分开记载，未把主智能体的实现直接交给 Luna。

首次试验获得两个评分但运行失败：自行简化了配套示例，省略记忆，显式线程未关闭，保存检查点时报错。维护者反馈后，第二次重新阅读修订指南并补回记忆流程，但在暴露阶段因 `max_tokens=128` 截断一个主体的输出而失败；四次 LLM 调用已完成，尚未进入记忆提炼。两次均未通过完整流程验收。补充低成本起步优先减少规模、保留示例各阶段输出上限的说明，以 `87873f7` 推送 main。失败记录保留。

第三次限定复测使用新配置 v003，重新阅读收紧后的低成本指导，沿用完整流程。独立读取产物确认 `failed=false`、完成两轮，8 次 LLM 调用与 3 次 embedding 调用均无错误；两名 Agent 各写入一条记忆，显式线程均关闭，次轮测量成功且记录记忆检索。三次 LLM 用量按提供费率合计约 0.0324 元；embedding token 与账单未核实。此结果证明维护者反馈后的修复能够完成该案例；无历史、无额外反馈的完整复验及 Luna 产物视觉交互仍待进行。

## 三、验收

本轮已通过真实界面完成已有安装确认、学习、实验配置、修改提议复制、生成新版本、附件接入模型、真实试运行、查看保存结果和请求分析。WorkBuddy 的实验与转换文件均由其 AI 修改，维护者通过自然语言提出反馈，并只读核对产物。配置、复制、新版本、逐主体与逐轮结果的截图已加入教程。

最后一轮工作台复核确认：v001 无运行也有六个 Agent 入口；v002 可选初始化检查和完成的试运行；机制卡内可切换资料表；第一轮不显示第二轮评分；第二轮显示评分、理由和原始输入缺失范围。原始试运行未改变。仍保留几项产品细节问题：普通消息环境的“制度实体”标签、个别说明把 FoV 称作唯一入口、宽表格依赖横向滚动。模板生成与 starter 的八项测试通过，skill 校验与差异空白检查通过；独立 Luna 审查提出的问题已修正。

总体判定为“完成一轮带反馈的全流程试验，交付教程初版与 skill 修订”。现有证据支持该案例能够被修复并完成；尚未证明新用户在干净安装、效率模型和短提示下可一次完成。后续应从最终公开版本做无历史复验，避免把维护者的额外指导当作 skill 自身效果。

分析环节仍需要独立研究方法审阅。最终报告撤去了无依据的最低样本数，但对记忆检索标记、测量成功、规则基线的研究含义仍有扩大解释的风险。原始测量输入未保存属于当前引擎证据范围，页面已经标明；若产品要求逐调用原文可追溯，需要另行明确引擎记录改动的范围。本轮没有修改引擎记录机制。

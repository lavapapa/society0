# 社交功能迁移检查：2026-10-19

本页保存当时的检查与版本语境。Next 后续按[当前基础环境合同](../core-next/basic-env-migration.md)验证；旧版对照、算法副本及其待办已退役，当前科研有效性由使用方设计和评估。

本次检查回答：社会网络研究能否转向 Next，以及哪些旧版行为还需要单独确认。比较对象为 stable/4.1 的 `4ff2df7` 与 Next 的 `903ddc2` 加本次工作树修改。判断分为功能是否存在、相同输入下结果是否一致、LLM 实际接收的信息是否一致三层。

## 一、结论

Next 已有发帖、点赞、评论、转发、关注、通知、拓扑、推荐、热门、曝光、语义检索与恢复等实现。固定动作脚本的逐笔结果比较通过；继续面向 Next 完善研究流程有充分依据。对“所有社交实验产生基本一致的研究结果”的判断，仍须考虑认知输入和默认配置差异。

本次先运行旧引擎对照和七个社交专项文件，结果为 94 项通过、3 项失败。三项失败均源于对照脚本调用已移除的 `Social.rank`。改为公开的 `await Social.recommendation`，从返回值读取排序与评分后，对照文件 23 项全部通过。原比较协议和旧引擎记录保持原样。两次检查合计覆盖的 97 项均已通过；本次没有调用付费模型。

## 三、研究差异

### 3.1 相同配置需要明确写出

旧版 `use_embedding_similarity` 默认 True，Next 默认 False。比较同一研究时须明确语义推荐是否启用，并使用相同的模型、向量、初始图、评分参数和时点含义。Next 启用语义推荐需要同时提供 embedding 与向量资源。

`time_decay_hours` 的名称和说明容易误导：现有公式使用 `tick - created_tick`，为 `exp(-时间差/参数)`。参数实际对应指数衰减时间尺度，实验如何把 tick 换算成小时需要自行定义；其数值也不等于半衰期。插件配置页应按实际公式解释。

### 3.2 认知输入会影响 LLM 行为

旧信息流按照 `feed_content_preview_chars` 和 `feed_max_chars` 截断。Next 社交认知来源发送新帖完整内容，后续以变化的元数据更新，并保留 Thread。排序相同也可能给模型提供不同的信息量，从而改变决策。

Next `SocialPerception` 在新帖实际保存到输入后登记曝光；单纯构建或预览保持只读。同一主体再次激活时，已见帖子通过游标管理。旧新对照脚本覆盖显式 `recommended_feed` 与热门行动，尚未覆盖两版完整 LLM 感知流程的曝光逐次比较。研究中的“浏览量”须注明采用哪个呈现事件定义。

### 3.3 有配置字段不等于有生效机制

Next 模型仍声明 `feed_content_preview_chars`、`feed_max_chars` 及 `TrendingConfig` 的若干字段，当前社交实现未读取这些字段。旧版的 `calculation_window_ticks`、`inject_into_feed`、`injection_count` 也未找到实际消费者。将它们画成可调且有效的插件参数会误导研究者。

`social_media.enabled` 在旧版影响初始化分支，Next 配方没有读取它。Next 的插件启停应由实验装配控制，界面需要对应真实配方中的开关。后续清理应删除闲置配置或为明确研究需求实现消费者，再补行为检查。

## 四、模型依赖

`pyproject.toml` 的 llm 安装组选用 `pydantic-ai-slim[openai]`，另含 Authlib、httpx2、aiolimiter 和项目内 `society0-filesystem`。`kernel/llm.py` 实际通过 Pydantic AI 的 Agent、Tool、Agent.iter 推进模型调用。Society0 自己保留仿真驱动、领域行动、Thread 记录与用量管理。

`society0-filesystem` 是本仓库 `native/society0-filesystem` 的原生文件工具组件，为智能体读取与搜索实验资料服务。它进入 llm 安装组，导致安装 LLM 能力时同时需要这一组件；模型服务协议由 Pydantic AI 及其提供方接口承担。

pi-ai 当前没有接入。`docs/core-next/technology-decisions.md` 与 2026-10-04 的模型选型研究说明了选择 Python 进程内复用、避免额外常驻 Node 进程的理由，并将 pi-ai 列为协议参考。本次未找到用户确认替换 pi-ai 的依据；应将用户原定选择与当前源码的差异单独确认，后续迁移范围取决于这一决定。

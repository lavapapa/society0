# 存储生命周期

完整步骤描述符是恢复权威。生命周期操作以已有 root、changeset 和不可变工件为基础，继续使用 SQLite 原生恢复及备份。本文约定离线压实、独立导出和孤儿清理的范围；具体格式与写入协议见 storage-contract.md。

## 一、独立恢复

`StageStore.restore(source, destination, step=...)` 同时承担选定完整点的独立导出和检查点链压实。它按原链恢复 SQLite，再以原生 backup 创建新 root，保存新 run_id 与来源 run_id/step。目标从选定完整点开始，后续步骤形成自己的变化链。源目录删除后，目标继续具备读取、追加完整步骤、分叉和再次恢复的能力。

目标保留选中时点 SQL 中的全部权威事实，包括累计 Thread、Memory 和业务历史；目标不保存选中点之前的逐步恢复身份。历史记录查询仍由对应 SQL 表提供。所有被源完整链声明的文件依赖按相对路径复制一次；重复声明必须具有一致长度。同一步或多个步骤复用一个不可变文件不会增加复制次数。

这个机制缩短后续恢复链，同时复制新 current 与新 root。冷压缩块位于 SQLite 内时，也随整个库进入两份文件。旧工作区快照只要曾被保留完整身份引用就继续复制；本阶段不从插件当前指针猜测历史文件的可达性，也不声称消除该项占盘。文件系统 clone/reflink 属于后续有实测证据才采用的物理复制优化。

## 二、孤儿清理

`StageStore.collect_orphans(path)`，由调用方显式执行。它先取得该运行的独占 writer 锁，验证格式、完整描述符链身份以及全部被引用文件存在性；失败不删除任何文件。活动 writer 持锁期间拒绝清理，避免删除正在准备但尚未发布的组件。

清理仅作用于该运行的 artifacts 和 changesets 目录。保留所有完整描述符引用的文件；其余未发布临时文件或准备孤儿可被删除。root、current、描述符、其它目录及其它运行保持完整。中途故障最多留下一部分尚未清理的孤儿，不影响任何完整身份。清理同步受影响目录并返回实际删除的相对路径。

离线验证允许工作量随保留的历史身份和工件数量增长；该操作不进入步骤提交和实时查询路径。未完成步骤留下的工件若没有完整身份引用，属于此次显式清理范围，调用方应在诊断留存完成后执行。

## 三、验收

恢复验收比较重复引用文件的复制次数及完整字节，验证源删除后独立读取、继续发布和再次恢复，并检查目标仍保留 Thread 可追溯资料。孤儿清理验收覆盖活动 writer 拒绝、多个完整身份的旧依赖保留、未引用文件清除、缺组件及身份错误时零删除。

后续空间报告同时统计 current、root、changesets 和 artifacts 的逻辑长度与实际分配块数。压实链长、复制次数和物理占盘是不同指标，报告分别给出，避免把恢复链缩短解释为全部历史数据减少。

# Society0 Core 实施规格

本规格把 [PRD](PRD.md) 转为可以分工实现的接口与验收边界。共同接口由贯穿消费者和故障试验约束；模块合同记录具体参数，本文记录跨模块责任。接口每次调整须同步消费者与直接测试。[能力对照](capability-parity.md) 管理旧语义，[TODO](TODO.md) 管理实现进度；规格中的验收要求不代表实现已经完成。

## 一、组合

一次运行拥有一个共享环境。环境由插件主机中相互依赖的服务组成，主体激活按需取得带身份和时点的访问作用域。初始化不枚举每个主体能够接触的全部对象，也不为每个主体建立完整文件树。

### 1.1 主机和生命周期

`Plugin(name, requires, install)` 的 name 是本次组合内的实例名，同一实现可建立多个名称不同的实例。`PluginHost` 在安装前完成名称、依赖和环检查，按依赖顺序安装。安装器通过 `provide(name, value)` 发布服务，通过 `require(plugin, service)` 使用直接依赖，通过上下文管理器和清理回调注册资源。运行结束、部分安装失败和取消均逆序释放资源。

服务名在所属插件内唯一。实际服务注册发生在安装器内，服务冲突可能在安装后才发现，因此必须清理此前已取得资源；预检的保证适用于插件依赖图。初版不支持运行中装卸，资源生命周期不承担领域写入的撤销。

### 1.2 代码边界

`society0.kernel.plugins` 只管理组合，`society0.kernel.interaction` 管理引用、作用域、信息和行动合同。持久化、时间、模型与记忆进入相应基础插件模块。公共入口在能力对标完成后切换；开发中旧入口保留为语义比较源。

机制插件持有自己的类型和索引定义，可注册信息提供者和行动定义。通用 Core 不包含市场、行业、经济或社交推荐的业务规则。

## 二、交互

共同合同覆盖结构化规则驱动和 LLM 工具驱动。二者通过相同的身份范围查询信息、提交意图、取得反馈，文件与 shell 是该合同的一个呈现层。

### 2.1 引用与作用域

`Ref(namespace, kind, key)` 为不可变值，namespace 对应机制实例，kind 由机制定义，key 为稳定字符串。引用无需加载对象；对象消失由提供者返回明确的不可用结果。路径是引用的呈现，可以改变目录布局而保留领域引用。

`Moment(time, phase)` 保存可序列化的模拟时间和阶段。`InteractionScope(actor, moment)` 由运行时创建，封装有效标记；退出后继续查询或执行抛出作用域失效错误。LLM 的参数中不接收 actor 或研究者权限，工具闭包绑定已有 scope。研究者访问以明确的外部 scope 表达。

访问策略接口为 `allows(scope, operation, ref)`，operation 使用 discover、read、invoke 等有限公共动词，机制按自己的关系和角色事实返回结果。目录枚举先应用 discover，再计算该范围的数量；知道路径仍须独立通过 read。行动发现与执行分别检查 invoke 和业务条件。

### 2.2 信息接口

`Information` 注册按目录前缀负责的信息提供者，目录本身按需枚举。提供者实现 `list(scope, path, limit, cursor)`、`read(scope, path, offset, size)`，数据集额外实现 `query(scope, path, query)`。文档读取返回内容和总字节数、下一位置、版本及来源；列表和数据集返回 `Page(items, total, next_cursor, revision)`。不存在读完首屏即无法继续取得原文的默认路径。

数据查询的首批公共表达覆盖字段选择、范围过滤、排序、分页、最近记录和可复现抽样；提供者明确支持哪些操作，按底层索引执行。大集合不能先转成列表再执行 limit。SQL、向量检索与文档原文保留适合自己的物理布局。逐一实现定制读取工具的职责转为实现一次提供者接口。

一次读取使用短作用域的一致版本，返回版本和完整恢复水位。需要稳定分页时游标绑定该版本；版本无法保留则明确返回已过期并提供重新开始方式。持续追加数据使用独立序号游标，读到末尾仍可继续取得新增记录。不得跨模型网络等待长期持有 SQLite 读事务。

### 2.3 行动接口

`Action(name, target_kind, description, parameters, handler, terminal=False)` 是按类型注册的模板。`Actions.find(scope, target, query, limit, cursor)` 根据目标与范围返回候选，`describe(scope, name, target)` 按需取得完整参数，`invoke(scope, name, target, arguments)` 验证参数、当前访问和条件后调用处理器。注册量由行动类别数决定，不随所有对象的笛卡尔积增长。

行动反馈包括 completed、accepted、rejected；无法维持步骤一致性的执行异常作为故障向调度传播。accepted 可携带持续过程引用，终止行动须 completed 才结束主体决定。发现不能替代执行时的再次判定。跨机制的原子业务改动由同一权威事务涵盖，事务内不得等待模型。调用标识与已执行结果由 Thread/驱动记录，用于区分模型重复调用和传输重试。

### 2.4 工作区与 shell

共享材料以只读信息挂载呈现，主体工作区保存其本人创建的文件。文件操作不隐式写入世界事实。工作区持久化按文件或块增量处理，激活结束可以释放解释器，后续重建保留文件及必要的 shell 会话语义。

shell 优先集成已有实现，小试验比较 Bashkit Python 与 just-bash 的按需加载、管道、查询、私有工作区和解释器驻留成本。通用 data 命令可把分页、过滤和抽样下推到信息提供者，输出供 jq 等现成工具继续处理；普通 head 读取大虚拟文件是否会全物化必须实测。首版不得自行实现 bash 或任意脚本到 SQL 的编译器。

## 三、运行

运行时负责把主体的决定放在明确的时间和事实边界上。调度的完成条件、持久化的完成条件与模型正常结束相互连接，同时保留独立的诊断信息。

### 3.1 主体与时间

主体记录持续身份、驱动配置和主观状态引用。Driver 接收绑定的交互会话并返回 completed、waiting 或 incomplete 结果。规则与 LLM 驱动均可暂停和再次激活；LLM 通过少量 meta tools 发现行动和读取材料，完整 Thread 保存所有实际输入与输出。

Step 调度运行顺序阶段，Phase 调度显式声明阶段参与者、共同可见版本和行动安装顺序。读取批次使用共同版本或明确的顺序可见语义。并发模型响应的完成先后不自动定义业务写入顺序，同一主体同时仅有一个激活写者。墙钟等待由模型连接管理，模拟时间由调度推进。

### 3.2 权威状态与完成发布

权威状态使用 SQLite 表、短事务和规范写入连接。插件在初始化时注册自己的表和索引，共享连接可以原子修改多个机制。冷正文与热投影拆表，减少数据库页、变化捕获和 Python 工作集合。查询连接只读并及时释放事务。正文可以使用压缩块或封存文件，向量索引作为可重建派生资源，小型临时工作集保持 dict。公开信息的文件路径与物理存储布局分别设计。

SQLite Session 的原生 changeset 保存完整步恢复增量。小字段输出的 changeset 可以很小，捕获过程仍会保存被更新行的原始列值；因此巨大正文同余额一行会放大内存，结构拆分是组件设计要求。外键使用数据库的约束与原生 changeset 应用语义。进程故障、重复恢复、删除、跨事务回滚、模式冻结和混合产物引用分别验收，具体协议见 [存储合同](storage-contract.md)。

初始数据库根与完整步增量形成恢复输入。每个完整 step 发布恢复身份，无需等待另外的十步检查点周期。当前数据库可以包含运行中已提交的进展，恢复链以完整步发布记录为准。分叉生成可写的新数据库及配置身份，其初次复制和历史应用成本单独测量。跨介质正文引用必须在完整发布前可达，当前实现的文件由 Runtime 收集并统一交给 complete。根压实、保留策略与可达清理需有实际消费者及独立恢复验收。

### 3.3 Thread、认知与产物

Thread 的元数据、追加事件和压缩正文块进入同一权威数据库。物理模型请求保存完整消息水位及请求参数，响应保存提供方原文。默认请求水位固定大小，重建请求按该水位取得完整消息；不得在每轮保存一次不断增长的消息序号数组。读取某段正文通过固定原始块定位，tail 以有限正文和可续读引用控制响应开销。

同主体、同 moment、同认知阶段的续激活通过持久 Thread 索引定位。内存 cursor 可加速当前进程，恢复后的身份由权威记录决定。提供方 session、工作区、已封存输出及行动回执使用可恢复引用；新 shell 会话需要消费旧输出时，通过该 Thread 的产物关联索引取得原文，避免重扫历史或重新执行行动。

自动召回、自动提取写入、主动记忆行动分别配置。记忆正文、所属主体、时间、重要性、状态和向量来源属于权威事实；检索结构由这些事实重建。提取结果、向量写入和成功回执的失败窗口通过持久 pending 状态及幂等消费验收。同一批的不同主体保留独立正文、向量和归属。访谈默认执行测量，incomplete 激活不得生成成功经验。

### 3.4 失败与并发

默认阶段顺序执行，显式声明互不冲突的阶段可以并发等待 Driver。完整阶段准备结果可由多个主体共用；SQLite 读事务必须在模型等待前释放。领域规则需要确定顺序时，计算结果按该顺序提交，网络返回先后不替代调度规则。

领域处理器在部分写入后异常、Thread 权威写入失败和未知发布结果均使当前步骤停止。无一致性破坏的 provider incomplete 可以由明确的调度合同选择收集并继续其他主体；结果中必须保留 incomplete、原因及实际动作，不能标为正常完成。默认策略仍终止该步。取消须等待已开始的调用和任务退出，之后才能关闭资源或恢复。

CPU 计算首先下推成熟原生组件。封存块的压缩可使用有限在途字节的线程流水线，Python 密集计算的进程方案需把编码、传输和进程组 RSS 一起测量。公共接口语言与更换计算实现分别决策，详见 [语言决策](language-decision.md)。

### 3.5 验收映射

引用、scope、权限与动态行动首先通过两个主体、两个机制的直接测试，覆盖过期引用、目录数量、执行前条件改变、同一目标多行动和关闭后访问。插件主机通过独立失败清理测试。存储原型通过独立进程故障与固定活动集合增长试验。后续 Driver、Thread、Memory、Schedule 每个实现提交都在能力表填写新入口及测试；旧测试通过只提供旧能力基线。

每组能力的实现责任、预定测试与阶段见 [实施验收映射](acceptance-map.md)。作者先建立失败用例，完成直接验证后由非作者审查；确定性能力、真实提供方兼容和大规模性能分别留证。任何接入如果需要重建全量 World、复制每主体共享材料或裁剪完整认知输入，都应返回对应接口重新设计后再推进。

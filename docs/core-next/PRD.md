# Society0 Core 与插件系统 PRD

本文定义新版的产品目标、语义合同与分阶段验收。能力逐项对照由 [capability-parity.md](capability-parity.md) 管理，执行状态由 [TODO.md](TODO.md) 管理，试验数据放在 `research/core-next/`。本文件中的拟定接口由小型试验和独立审查逐步收敛；通过旧版测试不代表新版已经实现相应能力。

## 一、目标

新版支持研究者把多种机制组合成一个共享环境，以信息与行动接口连接主体，以可替换驱动产生意图，以可替换调度推进时间。领域插件拥有具体机制，公共层承担稳定身份、插件组合、资源生命周期和一致的交互合同。

世界对象、主体、累计历史和行动空间可以增长，运行时应按本次工作集合加载数据。研究者能够在运行中查询已发布状态、进度和 Thread，并在运行结束后分析全部保留产物。完整恢复边界必须覆盖世界状态、主体状态、Thread 与记忆。

### 1.1 用户与完成条件

机制作者通过少量公共接口实现信息、行动和环境过程，复用数据访问、权限、持久化与运行观察。研究者组合有依赖的插件、配置主体驱动和调度，完成初始化、运行、观察、恢复和分叉。模拟主体通过环境授予的信息和行动能力参与世界。

完成标准是能力对照表所有有效语义具有新版实现、直接测试和端到端证据；默认入口使用新 Core 与插件系统；旧单体运行路径清理；所有未覆盖内容明示，不能以一个展示样例替代完整能力对标。产业专属机制不进入通用 Core。

### 1.2 保持的原则

所有主体共享一个环境，插件实现其内部机制。身份与对象引用跨插件稳定，存储与计算的分区保持同一个世界的业务含义。插件可以依赖公共能力及其他插件提供的服务，组合依赖和业务执行顺序分别定义。

主体的信息范围、行为能力、正常推理空间、完整 Thread 与逐笔结果质量属于约束。性能改善不得通过静默裁剪、强制收尾、减少有用工具或人为降低原有预算获得。达到实际限制须明确标为未完成或失败。

旧接口、旧存储格式、旧 Environment 类和旧内部结构可调整。废弃的 SimEngine、YAML 调度、旧 socket 推送无须恢复。新版无需兼容层；成熟且语义成立的实现可以提取复用，避免重写已有数据库与运行库能力。

## 二、公共合同

公共概念服务于具体的跨插件协作。接口先满足贯穿情景及能力对照表，避免引入没有实际消费者的通用框架。

### 2.1 对象、信息与访问

对象引用提供稳定身份，读取引用无需加载完整世界。信息视图是机制向特定主体提供的材料，可以是事实记录、声明、传闻或预测。文档与数据集共用发现、读取、检索和继续读取合同；时间、来源和对象关联保持可追溯。

访问范围由运行时绑定主体和时点。发现、读取和行动调用分别判定，复用角色、参与关系、空间关系等领域事实。目录名称、数量和失败说明也属于可能可见的信息。社会制度上的权利、系统访问资格和行动结果由对应语义分别表达。

插件信息提供者声明数据结构、定位和分页能力。公共层提供文件视图及通用查询工具。大集合的目录枚举与读取须按需推进，禁止初始化时构建每个主体乘以全部对象的完整文件树。

### 2.2 行动、意图与反馈

行动定义包含名称、目标类型、参数、说明和执行入口。定义按类别复用，具体对象和情境在发现或执行时绑定。发现、详细说明、执行是少量稳定入口；返回候选后仍在执行时判断当前条件。

行动结果区分受理、完成、业务拒绝与执行故障。持续过程由环境机制推进并产生后续反馈。终止行动须成功才结束相应回合；业务失败反馈保留继续决定的机会。跨机制的共同生效范围及允许延迟的后果必须明确。

已经提供的信息可以直接读取；消耗时间、预算或引起外部反应的调查属于有后果的行动。查询接口不应隐式提供研究设定之外的全知信息。

同一模型响应含多个调用时，已经成功的行动保持一次执行语义，其他调用的参数错误或提供方重试不得重放成功项。行动发生部分写入后意外退出须使当前步骤失效，普通业务拒绝通过无修改的正常结果反馈。

### 2.3 主体、认知与工作区

主体持有持续身份与主观状态，驱动实现接收信息、提出请求、处理反馈、暂停和结束。LLM、规则及其他驱动可以分别实现。LLM 使用文件及命令界面，规则驱动可以使用同一语义的结构化服务。

可访问、实际读过、主观相信分别表达。工作区保存主体笔记、脚本和分析产物；世界事实写入经过领域行动。内存、文件和数据库是实现选择，主体数不强制对应进程数、数据库文件数或完整运行时副本数。

自动召回、提取写入和主体主动使用记忆分别配置。完整 Thread 的逻辑内容保留；OpenViking 的摘要层可以辅助发现原文，不作为默认裁剪会话的理由。记忆写入与恢复边界保持一致。

记忆提取完成、正文与向量写入、完成回执之间分别设置恢复验收；已经保存的提取结果可继续写入，重启不得重复发起提取或重复创建记忆。主体读取覆盖本次激活应当可见的已完成记忆。

### 2.4 时点、调度与观察

时点包含模拟时间及所处执行阶段。状态版本用于区分同一时点内已经发生的变化。固定 step 与分阶段调度为首批时间插件；同批一致观察和顺序行动可见性由调度合同明确表达。

同一时点重复激活延续信息会话和主观状态，用独立游标呈现新增内容。墙钟网络等待不自动增加模拟时间。动态激活支持有界并发、同主体串行、信号合并、明确取消及未完成结果。

运行观察区分进度、可查询状态与可恢复状态。读取状态返回其版本与完成边界；外部观察可使用研究者范围，不改变模拟主体的信息范围。观察开销按请求范围计算。

Thread 目录及追加读取是独立的观察能力。客户端到达当时末尾后保持续读位置，之后可以取得新增条目；固定快照分页与持续追加读取分别验收。慢客户端按持久化游标继续读取，运行端无需为每个客户端积累推送队列。

## 三、工程设计

Core 以少量共同合同连接插件。下面的层次是依赖关系与责任划分，具体文件组织在试验后确定。

### 3.1 Core 与插件层次

Core 管理对象和主体身份、插件依赖、服务注册、生命周期及运行范围。依赖排序优先使用标准库图算法，资源清理使用上下文管理器。重复插件、缺失依赖和循环依赖在安装前发现；安装器内动态注册的服务冲突导致本次安装失败并释放此前资源。

基础插件提供持久化、信息视图、访问规则、资源池与产物访问。主体插件提供规则驱动、LLM 驱动、Thread 和记忆。时间插件提供 step、阶段调度和动态激活。环境机制插件提供通用样例环境、通信及旧版内建机制的等价能力。

依赖以显式服务或插件标识表达。插件退出释放其运行资源，已经产生的世界事实遵守运行恢复语义。初期实现配置时组合、启动和关闭；是否需要运行中加载替换，须有具体情景与一致性验收后另行启用。

### 3.2 存储与文件界面

优先使用 SQLite 的事务、索引与查询能力承载需要关系定位和一致修改的数据。JSON/JSONL 适合配置、追加或派生产物，向量索引适合语义检索，dict 适合小型当前工作集合。文件视图按需连接这些数据，避免把所有信息重新保存成一份文本世界。

必须通过试验确定状态发布、完整恢复与分叉的具体方案。对照每步事务、明确阶段提交及版本化读取的成本，记录长读事务导致 WAL 保留、历史版本增长、跨存储发布和恢复的边界。不能以手工实现数据库 WAL、页缓存或任意脚本查询优化器替代成熟实现。

文档范围读取、集合分页与内部物化分别测量。字节块读取能力不自动等于按记录定位能力。对外返回数据量有限时，底层扫描和分配仍须有证据。主体工作区复用共享底层，仅持久化自身材料及必要历史引用。

### 3.3 并发与性能

网络调用采用资源池中的异步并发。释放 GIL 的原生计算可使用有界线程池，纯 Python 重计算比较进程方案及其序列化成本。插件复用总资源预算，防止各自创建连接、线程与缓存造成乘法增长。

并行任务使用明确的输入范围及状态版本，按业务规则安装结果。共享可变状态的冲突不能由任务完成顺序偶然决定。压缩、解析、渲染和分析先以有限数据块验证；报告墙钟、CPU、峰值内存、读写字节和排队成本。

首版采用 Python 公共 Core 与插件接口，计算和存储优先调用成熟原生组件。TypeScript 保留用于已有工作台及必要的独立工具适配；重计算若需新增自有原生代码，以 Rust 批量接口实现。选择与切换条件见 [语言决策](language-decision.md)。

固定活动集合、扩大历史，是长期复杂度的核心验收。必要的索引查找可有对数成本，热路径不得退化为累计历史线性扫描。索引、当前投影与事实由同一规范写入入口维护。

### 3.4 已有资产复用

旧模型配置与提供方适配、完整工具回合、Thread 格式、记忆语义、激活合并和现成测量用例首先进行适配可行性审查。能脱离单体 World 的代码提取成插件实现；直接依赖全量 World 的部分按新合同重构。保留能力通过新入口使用的证据，避免仅包一层插件外壳。

OpenViking 研究见 [openviking-study.md](openviking-study.md)。其 URI、目录、原文与派生层以及检索组织作为重点参照，直接依赖与可选集成由试验选择。该项目的快照和文件访问性能不自动成为 Society0 的恢复与性能保证。

## 四、阶段与验收

阶段的验收产物是可执行规格、可复现试验和能力证据。详细任务、负责人及勾选状态由 TODO 维护；每个实现任务先增加失败测试，保存红灯与绿灯结果。

### 4.1 P0：能力与小型试验

固定旧版有效能力与源码测试证据，核对 OpenViking 当前实现，建立确定性基线。试验覆盖插件依赖与失败清理、身份范围下的信息读取、动态行动、SQLite 与追加产物的状态边界、长历史查询以及并行计算。输出选择依据和仍未证明的风险。

### 4.2 P1：可执行核心

实现插件组合、主体与对象身份、信息与行动合同、私有工作区和规则驱动。通过两个具有依赖关系的机制插件完成同一环境的交互，证明无需创建巨大 World 或按主体复制世界。旧版运行路径在开发期间作为对照，最终公开入口切换后清理。

### 4.3 P2：运行与能力对标

接入 step 与阶段调度、动态激活、LLM、完整 Thread、记忆、模型服务、持久化、恢复、分叉、产物及实时查询。将旧内建环境拆成适当插件，逐项执行能力对照测试。多核只作用于已有可证明隔离的计算路径。

### 4.4 P3：验收与交付

执行确定性全量、真实 LLM/embedding 短程、独立进程故障恢复、长历史增长和多主体压力对照。独立审查覆盖失败中间状态、插件依赖、查询范围、跨插件写入以及主体输入完整性。修复后重新运行受影响测试和全量验收。

交付包含新入口文档、插件开发范例、从完整产物进行分析的例子、能力映射和验证报告。版本、依赖、锁文件和发行说明保持一致；明确实现完成、合并、推送与部署的不同事实。

## 五、测试设计

验收同时覆盖仿真语义、故障恢复与增长成本。每个结果说明验证条件，不能把测试数量等同于真实研究有效性。

### 5.1 确定性规格

插件拓扑、依赖服务、初始化失败及逆序释放；两个主体不同信息范围；目录发现与正文可读区分；同一对象的动态行动条件；失败终止行动；异步过程反馈；同一时点重复激活；完整 Thread；记忆三个开关；同主体互斥与跨主体并发；输出截断、服务错误及取消的未完成分类。

### 5.2 数据与恢复

在每个提交/发布边界注入失败，通过独立进程重新打开，检查恢复只引用完整状态。数据、主体认知、Thread 与记忆必须属于同一恢复身份。覆盖分叉、长读、查询时运行继续、游标续读、结果表分页，以及新配置创建新运行。

### 5.3 性能与主体效果

分开测环境计算、上下文构建、模型与记忆、持久化、观察和恢复。以固定活动集合扩大历史，以固定历史扩大活动集合，再扩大单份资料。记录扫描量、调用量、物化字节与进程组内存，避免仅用耗时阈值判断。

动态行动与文件入口应与旧输入能力进行任务对照：主体能找到信息、取得完整明细、正确调用行动并完成对应研究任务。工具定义更少或返回文本更短仅是过程指标。真实模型结果保留完整来源与产物，不用自动摘要掩盖遗漏。

### 5.4 真实服务与资源

真实测试从用户授权的位置读取可用提供方，选择较新且低成本的模型，并先做小请求确认工具、结构化输出和嵌入参数。产品和公开文档保持提供方中立；凭据只进入测试运行环境，不进入提交、日志或产物。无密钥的确定性测试可独立运行。

新版是否完成由逐项能力与验收证据共同决定。小型试验失败时调整对应设计，再继续有依据的实现；运行中等待和尚未完成的阶段保留在 TODO，持续推进。

# 规模与覆盖

本文解释 [PRD](PRD.md) 的代码预算和验收范围。预算是保留全部有效能力后的设计估算，覆盖全部自有层；实测计数、执行状态和覆盖率按各轮报告中的源码身份读取。选型基线见 [计数工件](../../research/core-next/runtime-selection/code-size.json)，实施测量见 [规模记录](../../research/core-next/acceptance-20261004/code-scale.md) 与 [能力复审](../../research/core-next/acceptance-20261004/capability-review.md)。

## 一、基线

统一采用物理行，包含空行、注释和文档字符串，排除依赖、生成文件、研究工件及运行数据。接口移入插件后仍计入维护量，库实现交给依赖后的部署成本另行报告。

### 1.1 计数范围

基线分别记录 Python/Rust 库、工作台、示例、技能资产和测试。kernel、资源管理与内置插件属于库的子集；配置、锁文件和文档另承担维护责任。计数明细及来源由 [选型时计数工件](../../research/core-next/runtime-selection/code-size.json) 保存，后续测量沿用同一范围。

行数用于估算维护量，测试数量用于说明执行范围，分支覆盖说明哪些代码实际运行；三者分别报告。当前测量见 [实施规模记录](../../research/core-next/acceptance-20261004/code-scale.md) 和 [执行与覆盖](../../research/core-next/acceptance-20261004/status.md)。

### 1.2 可减少的责任

替换范围来自现行实现中的通用协议和资源管理：模型请求格式与响应转换交给 SDK，HTTP 传输交给 ASGI，任务收束交给 TaskGroup，帧定位交给 SQLite 主键索引，帧解压交给原生 zstd。重复包装与旧接口也可删除。每项删除须有正式消费者测试，提供方管理中保留的产品语义继续计入维护量。

完整上下文、行动回执、记忆开关、主体邮箱、跨工件完整身份及研究结果仍由 Society0 负责。通过减少这些能力获得的代码下降不符合本轮目标。Authlib 接入也会增加账户管理和端点适配，须抵扣删除收益。

## 二、预算

预算按责任相加，避免以“小 Core”掩盖适配层和插件规模。平台与插件允许共享内部实现，统计时每段代码归属一次。

### 2.1 库的分解

语义 Core 预算 **1,200–1,800 行**，包含 Ref/Moment、主体作用域、信息与行动路由、插件装配及步骤状态机。模型、shell、向量库和具体机制均为可选消费者，Core 不加载这些依赖。

固定平台、公共适配和能力插件合计预算 **5,700–7,200 行**。其中，存储、正文、恢复及查询预计 1,700–2,200 行；模型、认证、Driver、Thread、Memory 与认知组合预计 2,100–2,600 行；Workspace、Rust 桥、观察、结果、CLI 与运行入口预计 1,900–2,400 行。这一组包含大量内置插件，分类依据是责任归属，全部纳入总量。认证的估算已计入其中：标准协议使用 Authlib，应用仍需约 150–250 行账户与刷新协调、约 40–80 行 Responses 特定接线；这些局部数字也是待实现验证的预算。

Plain、RoundRobin、Social 等具体内置机制预算 **1,000–1,500 行**，以选型基线的完整语义为起点。产业机制继续属于外部环境仓库，其代码不属于 Society0 库，也不用于证明本库规模下降。

以上合计 **7,900–10,500 行，规划时取约 8,000–10,500 行**。相对选型基线的预计降幅见原计数记录。下界依赖公共适配确实删去重复逻辑；上界也属于预算，任何一项未达到删除条件，都应调整估算并解释。当前没有证据承诺整套库达到两三千行。

### 2.2 完整维护面

按选型时工作台、示例及 skill 的基线不变估算，全部产品与使用资产约 **11,500–14,000 行**。前端也随合同更新，它的规模需在实施后重计；这里没有将其移出维护范围来制造减少量。

测试预算保留选型时已有的语义资产，并为认证、流终态、消息格式、分片和取消组合预留约 2,000–4,000 行新增或重写工作量。后者与替换旧 fixture 会重叠，因此不把简单相加作为最终测试行数承诺。衡量目标是风险覆盖和可维护性。

规模验收在各阶段使用同一计数口径，对照实际差异和能力矩阵。实际规模与预算差异见 [实施规模记录](../../research/core-next/acceptance-20261004/code-scale.md)。若超过预算，先检查重复职责、无消费者抽象及成熟组件接入边界；正确性和能力完整性优先于行数指标。

## 三、覆盖

保留 [能力矩阵](capability-parity.md) 的全部 **78 项有效能力**及 [验收映射](acceptance-map.md)。下列四组恰好覆盖全部能力；重新选择库以后，旧测试证据属于旧实现基线，新实现需重新验收。

### 3.1 既有能力

主体、机制与调度 A/B/E/S 共 **23 项**：检查同主体串行、共享时点、阶段顺序、机制 hooks、部分安装、重复取消与失败清理。TaskGroup 正常结束仍须检查应用登记的步骤失效状态。

模型、记忆与资源 L/M/R 共 **27 项**：检查最终完整请求、自然结束和未完成的区分、工具回执、物理重试、资源归属、记忆三个开关的八种组合及跨主体 embedding 逐项对应。保存后再次发送 SDK 消息，核对 opaque 内容及 namespace；订阅与 API profile 分别覆盖。

文件、结果、持久化与观察 N/O/P/Q 共 **23 项**：检查逐字节范围和全读、稳定页与精确总数、权限变化、慢客户端、准备中状态查询、独立进程恢复、完整点分叉、工件发布失败窗口及删除来源后的分析。Session 大行、seek table、WAL 长读及巨文件 copy-up 单列资源测试。

运行入口、示例与工作台 U 共 **5 项**：从干净安装运行最小组合，使用真实生成的产物打开、分页、导出并恢复；纯规则安装不依赖 LLM、向量库或 shell。macOS 与 Linux 的原生依赖都需实际验证。

### 3.2 新增合同

认证覆盖动态 client ID、PKCE/OIDC、用户配置凭据保存、刷新并发、刷新失败、账户切换、授权撤销与额度耗尽。服务参数在运行前校验，禁止隐式删参数和收费回退。真正账户的订阅资格、模型可用性与额度关系在未来真实验收确认；离线响应替身无法证明这些事实。

模型终态覆盖 completed、incomplete、failed、error 及无 completed 的 EOF。工具片段出现时保持未执行，确认该 profile 的明确成功终态后才允许行动。领域 terminal action 与传输成功分别判断。其他提供方按实际 SDK 映射验证，避免套用 Responses 字符串。

文件投影覆盖 UTF-8 边界、跨片记录、空文件、单巨记录、目录分页、完整重组、版本变化、工作区恢复与读取后权限变化。信息读取效果需以主体真正找到资料并完成行动对照，不能用请求字节更少替代结果。

## 四、证据

本轮试验回答“公开接口能否承担该职责”，正式实施回答“整套 Society0 是否保持能力并改善资源成本”。两类结论按各自证据范围使用。

### 4.1 选型证据

[模型研究](../../research/core-next/provider-selection-20261004.md) 与 [终态试验](../../research/core-next/provider-terminal-offline-20261004/README.md) 保存 SDK 协议和响应终态的选型消费者。[存储研究](../../research/core-next/storage-selection-20261004.md) 保存编码、恢复和检索候选的比较，[运行研究](../../research/core-next/runtime-selection-20261004.md) 保存任务生命周期、文件投影和 HTTP 选型试验。各报告按当时源码与输入解释，产品组合另行验收。

### 4.2 产品验收

每个能力 ID 均须对应责任实现、正例与关键负例；核心状态机、恢复与新适配的关键失败边界有显式用例。实施时采集源码及分支覆盖，报告未覆盖代码的具体风险。实际执行、覆盖率、平台消费者和剩余边界见 [独立验收记录](../../research/core-next/acceptance-20261004/status.md) 与 [能力复审](../../research/core-next/acceptance-20261004/capability-review.md)，后续状态由 [TODO](TODO.md) 维护。

性能对照固定同一输入和运行合同，分别扩大历史、活动集合、单对象和并发，测整进程组 RSS、临时磁盘、CPU、IPC、读取/物化字节及连续步骤斜率。选型小样、完整业务步骤、真实服务链和主体效果分别形成证据，适用范围写入各自验收报告。

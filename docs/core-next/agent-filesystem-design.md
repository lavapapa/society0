# 文件交互与主体插件：实施规格

本文是文件交互、主体扩展和时间安排下一轮调整的详细规格。产品目标由 [PRD](PRD.md) 管理，执行状态由 [F01–F08](TODO.md) 管理，研究事实见 [准备研究](../../research/core-next/filesystem-preparation-20261005/research.md)。本文定义文件入口与调度合同；阶段验收以 TODO 中对应代码和测试证据为准。准备阶段的探针证明局部能力，产品验收使用正式公开入口。

## 一、边界

主体共享一个环境，机制拥有各自的数据与规则。主体通过自己的文件视图观察可见信息，通过 Actions 影响共同事实；调度确定何时参与，Runtime 负责执行和完整步骤发布。

### 1.1 文件与存储

全部主体可见的持久资料具有可发现的文件路径，包括机制资料、认知材料、记忆原文、主体笔记和已登记的输出。资料可以按需生成，SQL、zstd 正文、向量索引和小型运行期 dict 继续承担各自的物理存储职责。共享资料不复制为每主体独立实体文件，文件修改权限不授予世界业务写入资格。

模型界面的信息入口收敛为 read、ls、find、grep，并保留 bash。模型顶层使用统一文件工具。内部 Information 的发现、范围读取和 SQL 查询服务继续被文件适配、规则驱动和外部观察复用。

### 1.2 成本与原文

分页、分块与搜索预览都保留完整原文路径、版本和继续读取位置。默认返回预算约束一次传输；不得将命中上限解释为不存在更多结果。精确计数、任意全文扫描、无索引抽样、巨文件整读和超长单行的真实成本单独报告。

固定活动规模时，文件装配、短元数据读取和阶段调度的工作量不随全部历史增长。全文 grep 显式扫描所选范围，其工作量可以与范围内原文字节数成正比。对“最新若干条”须沿数据库排序索引读取，避免先生成全部历史文件。

## 二、文件接口

四个文件工具与 bash 消费同一套主体绑定的逻辑文件身份。搜索对象是原始资料，传输分片、base64 编码及 manifest 不构成原文的重复副本。

### 2.1 命名空间

| 路径 | 内容与权限 | 权威来源 |
|---|---|---|
| `/world/<mechanism>/` | 主体有权观察的环境资料，只读 | 机制注册的 Information 视图 |
| `/context/` | 本主体本次实际认知材料、已召回记忆及使用说明，只读 | 主体扩展与 Thread 中的原始记录 |
| `/workspace/` | 主体创建、修改、删除的笔记及研究文件 | 现有 Workspace 索引与正文工件 |
| `/results/` | 本主体已登记的命令输出、查询结果和动作回执，只读 | 持久工件与 Thread 归属索引 |

逻辑文件可用原文入口及显式分片入口表示，同一地址在各工具中保持同一对象身份和文件类型。大文档的 metadata 说明原文位置、原始字节长度、版本、媒体类型和分片入口；大小阈值不应令模型猜测同一路径究竟是文件还是目录。专用范围读取与 shell 整读共享此原文身份。

记忆插件在主动访问开启时挂载 `/context/memory/records/`，允许列举和读取全部当前可见的主体记忆，包括本次未召回的条目；语义召回仍由记忆能力提供。主动访问关闭时，完整目录和主动记忆行动共同关闭，本次自动召回的材料与既有 Thread 原文继续可见。自动召回、自动写入与主动访问三个开关保持独立，避免文件入口绕开原有主动记忆策略。

`/context` 的文件化不自动删减既有输入。系统说明与必要初始认知仍按实验合同进入模型消息，文件指向相同原文；变更注入方式须做同任务效果对照。规则驱动可直接消费结构化认知材料。

### 2.2 工具合同

| 工具 | 主要输入 | 结果与边界 |
|---|---|---|
| `read` | path；可选 offset、size、encoding、expected_revision | 默认读取开头；字节偏移及 UTF-8/base64 精确续读；返回总长度和下一偏移。复用既有原文范围接口 |
| `ls` | path；可选 limit、cursor | 有权限的直接子项、total、next_cursor、revision；列目录不读取大正文 |
| `find` | pattern、path；可选 cursor、limit | 对逻辑文件路径做 glob 匹配，持续遍历可取全；成熟 glob 匹配器负责模式，不遍历传输副本 |
| `grep` | pattern、path；可选 glob、literal、ignore_case | 返回原文文件路径、版本、行／字节定位和结果文件；文本边界在成熟搜索器内连续处理 |
| `bash` | script | 组合读取、处理和私有文件操作，保留 action 命令；输出通过 `/results` 持久回读 |

read 的 offset 保持原文字节语义，避免每次为了行号重新扫描完整前缀。文本的行号由搜索结果附带；任意行号跳读若需要索引，必须先有真实消费者和成熟实现依据。超长单行不会以“整行装不下”为由丢失原文读取路径。

主体身份从 Session 绑定，模型不传 actor。枚举、统计、检索命中与读取均受同一授权范围约束；每次访问重新判断当前资格。已实际看到的内容继续留在完整 Thread，撤销权限后的新读取按最新资格执行。版本变化返回明确的过期结果，禁止拼接不同版本冒充同一原文。

find 和 grep 在开始时固定所选挂载的已声明数据及权限依赖水位，目录页、正文段及结束校验使用同一水位。搜索中相关依赖变化使整次结果失效，部分结果保留为诊断，不能声称完整命中数。无关 Thread 追加不在世界查询的依赖集中。需要稳定长搜索时显式选择完整点视图；版本标识本身不保存历史快照，也不跨网络等待持有数据库读事务。

路径 glob 优先采用标准库匹配能力；文本匹配优先使用 ripgrep 的独立 Rust 库。跨文档分别建立 Reader，禁止把两个文档首尾串接形成虚假命中。二进制通过 read 的 base64 路径保留；默认 grep 的文本范围由文件元数据明确。

### 2.3 搜索与结果

采用现有 Rust/Python 桥连接原文范围读取；grep-searcher 通过 Reader 消费连续字节，grep-regex 负责模式匹配。每个块是一段连续原文，不自行设计正则跨块重叠算法。Python 回调按块发生，原生搜索在工作线程运行，模型事件循环仍可处理取消和状态读取。

搜索结果逐条写已有工件流，预览包含总命中数或明确的未完成状态、结果路径和继续读取位置。完整搜索完成后再声明精确总数；取消和资源失败保持诊断，不发布成功结果。持久结果在完整步骤内登记，恢复后无需重新执行原行动取得旧输出。

成功工具调用已经物化并返回引用的结果正文，视为主体在该时点取得的私有记录；预览之外的已物化部分同样属于该结果，撤销源权限后仍可按主体归属回读。认知中的“模型实际读过哪些部分”另记读取水位。结果内尚未物化的 document_ref 继续是受版本与权限约束的源引用，读取时重新授权；源版本失效必须明确报错，不能读取同路径的新内容代替旧文档。恢复保留结果本身的不可变正文及其原引用语义。

普通单行正则的缓冲仍可能随最长行增长；多行模式可能整份读取。首期公开 grep 提供明确的逐行匹配合同，保留原始 read 与 bash 全内容通路；额外正则方言按实际消费者验收。搜索不承诺任意模式和任意超长单行均为固定内存。

Bashkit 现有 FileSystem.read_file 返回完整正文。对原文路径运行 cat/head/jq/grep 可能整读选定文件，head 的输出较少不代表输入较少；对显式分片路径操作的读入由片大小约束。专用 read 和 grep 通过范围／Reader 路径改善相同逻辑资料的访问成本。两条路径的命中、原文和版本须对照一致，整读成本在工具说明和性能报告中公开。保留 Bashkit 原有管道／stdin 处理能力，不自行替换其命令解析器或静默截断输出。后续只有上游成熟流式接口经验证可用时，才调整原生 shell 的成本边界。

### 2.4 数据集运算

SQLInformation 的注册声明生成可读 schema 文件：字段含义与类型、对象 Ref、正文路径、可过滤和排序字段、时间口径、查询示例以及版本／成本说明。读取 schema 不额外创造逐领域工具；机制作者补充业务字段含义。

结构化筛选、排序、抽样继续下推数据库。首期保留一个通用 shell `data query` 命令消费现有 Query 合同，返回或登记可通过 read 取得的结果文件；它作为计算入口写入说明文件，退出模型顶层工具列表。其名字是否随命令整理调整不构成功能变化。不得通过分析任意 grep/jq/sort shell 脚本，自写通用 SQL 优化器。

例如“最近二十次价格”使用已声明时间排序字段加 limit；“随机十笔”保留 seed 与总体数量；“余额超过某值”使用注册字段过滤。简单文件管道仍可处理已选资料。普通 JSONL 全表导出提供完整范围，跨页版本一致性由原有水位检查；固定历史分析使用完整点视图，避免长 SQLite 读事务跨模型等待。

无索引的均匀抽样仍需扫描候选键；明确报告成本。主体要求任意全文或全表输出时保留能力并按实际数据量计量。结果文件、正文引用和字段元数据必须能恢复到其原始对象，不能只给一个无法定位的摘要。

## 三、主体插件

Driver、认知扩展与领域机制都使用已有 Plugin 的服务装配。普通 Python 对象仍可独立单测，正式持久运行由插件声明依赖并提供驱动工厂。

### 3.1 装配与恢复

保留 `Driver.run(session) -> DriverResult` 的小合同。内置规则和 LLM 插件分别提供命名的 factory 服务，Actor 插件消费这些服务引用；第三方驱动只需实现同一协议并经普通 Plugin 提供 factory。共享模型、Thread、Workspace 和扩展服务在安装期取得，驱动按激活创建或借用，休眠主体无常驻解释器。

ActorRecord 保存 driver 名称、配置与主观状态，恢复从冻结代码重新装配 factory。运行开始前核对已有主体引用的驱动名称可解析；不持久化 Python 闭包，不维护第二套全局注册中心。RuleDriver 从调度模块迁入主体驱动模块。

### 3.2 激活扩展

使用标准异步上下文管理器和 AsyncExitStack 组合一个有序扩展序列。扩展可准备结构化认知材料、建立主体作用域、收束成功结果并清理；Thread 身份与实际经历水位属于通用激活上下文。规则、LLM 和第三种驱动消费同一能力合同。

Memory 扩展分别控制自动召回、自动写入和主动行动。LLM 的提取策略使用完整 Thread，规则策略使用明确提供的实际经历；无记忆配置的规则运行无需 Thread、向量或模型依赖。提取发生在 Thread 最终关闭前，incomplete、取消和失败保持既有成功记忆边界。waiting 与 interview 的处理依据现有运行合同逐项对照。

先采用共享记忆存储叠加不同认知策略。独立 Memory 存储实例需要命名空间时由真实消费者驱动；不能把服务改名当作表和动作已经隔离。公开工厂应能接收提取策略，避免示例重新包装整个 Memory 类。

结构校验由 jsonschema 承担，结构化模型提取优先使用已安装的 Pydantic AI。领域输入水位、物理调用留证和完整步骤依赖继续使用既有服务。扩展接入后删除 LLMDriver 的 memory 专属参数、成功水位键和分支，删除相应示例转发壳。

## 四、时间

时间、步骤、阶段和调度分别承担可理解的职责。固定步长与复杂阶段是同一运行中可以同时存在的两个维度。

### 4.1 公共概念

模拟时间是世界中的日期或时刻；step 是一次完整发布与恢复的序号；phase 是该 step 内的业务阶段；schedule 决定下一次执行的时间及阶段安排。早晨接收信息、主体决定、集中结算可以属于同一个日步。

调度与执行使用以下独立合同：

```python
@dataclass(frozen=True)
class StepPlan:
    time: object
    phases: tuple[Phase, ...]

class Schedule(Protocol):
    async def next_step(self, completed_step: int) -> StepPlan | None: ...
```

Runtime 保留唯一 `run_step(number, time, phases)` 执行与发布入口。runner 从插件主机分别取得 Schedule 和 Runtime，取得计划后执行；清单和计时从显式配置及 Runtime 获取，避免访问调度器的 runtime/phases 私有结构。

### 4.2 内置与扩展

内置 `SequenceSchedule` 接收明确时间序列与阶段序列，覆盖固定日期／步长和每步有序阶段。一个阶段直接使用单元素阶段序列。基于状态选择下一时点的机制可提供同一 Schedule 服务，阶段内参与者选择与议程处理继续使用已有阶段函数。

Schedule.next_step 为规划读取，不在完整步骤之外推进权威游标或发布工件。内置序列按 completed_step 定位下一项；自定义状态变动放入 Runtime 执行的阶段并随完整步骤恢复。冻结时间范围，恢复时按完成身份选择下一计划，防止重复或跳过时点。

首期不引入 SimPy。需要事件队列、过程挂起和资源争用的真实机制出现后，可以独立接入调度插件；届时须明确队列恢复、墙钟模型等待与完整步骤的映射。运行协议由不包含 runtime/phases 私有字段的第三方调度消费者验收。

## 五、验收

规格先于实现，失败用例先于替换。每个接口调整都有贯穿使用的消费者，测试量不替代风险覆盖；实现与独立验证由不同智能体承担。

### 5.1 正确性

| 风险 | 必须失败先行的验收 |
|---|---|
| 分片改变搜索结果 | 中文词、ASCII 词跨压缩块／文件片界；同文档多种表示只命中原文；不同文档不跨界匹配 |
| 文件入口遗漏能力 | read/ls/find/grep/bash 得到同一原文、对象身份、版本和权限；结果、记忆、冷资料均可发现与续读 |
| 数据集变为盲猜 | 空数据集也可读取 schema；最新、过滤、排序、抽样、完整重组与旧查询结果一致 |
| 取消／权限变化 | 读取 A 后修改 B、目录分页后撤权、结束前版本变化使整次搜索失效；错误不伪装为无匹配；已取得结果与仍未物化的源引用分别验收 |
| 主体扩展绑定 LLM | Rule、LLM 替身、第三种 Driver 经插件共享扩展；同 Moment、三个记忆开关、多扩展顺序与失败清理；未被召回但可主动访问的记忆能够发现和读取 |
| 调度只是包装 | 自定义 Schedule 不提供 runtime/phases；正常、失败、重复激活、恢复仍由 Runtime 唯一发布 |
| 提取规则漂移 | 结构、数量、长度、importance 和空白策略有明确接受边界；一次纠正、截断和调用预算保持可解释 |
| 恢复／动作重放 | 工具输出与动作回执可回读；失败写入和重复取消不发布完整点；恢复不重新执行已确认动作 |

使用 Hypothesis RuleBasedStateMachine 生成工作区增删改、权限／版本变化、读取、发布和恢复组合，断言权威状态、文件视图和完成身份一致。异步取消仍用显式屏障的确定性测试，避免将随机等待当作充分并发验证。

### 5.2 资源与效果

比较固定活动量下 1 倍／10 倍历史、固定历史下更多活动主体、单巨文档、巨行、空／高命中搜索及大量私有文件。记录 CPU、墙钟、进程组 RSS、读取原文字节、数据库扫描量、Python/native 复制、临时磁盘、IPC／回调次数。使用相同资料和任务比较新旧入口，不以更少工具、截断输出或更短提示作为收益。

最新记录查询应走排序索引且不读取未选正文；文件路径装配不枚举整个世界；原文范围读取随请求块变化。全范围 grep 与均匀抽样列为明确扫描操作，其资源曲线单独解释。多核首先使用原生计算及有界工作线程／现有进程池，权威写入保持单一拥有者。

独立 GPT‑6.1 Sol 在实现后执行相关、确定性全量、真实 Bashkit、两个机制与两种驱动恢复消费者。真实模型短测使用用户指定提供方和模型，保持完整输入、有效工具与既定预算，单独记录端点可用性和任务效果。原有真实订阅和长期复杂社会验收边界继续保留。

本轮完成标准是统一的文件使用体验、真实可组合的主体扩展及独立的调度合同都有端到端证据，同时明确说明剩余扫描、巨行和整文件操作的成本。任务顺序及完成状态只在 TODO 维护。

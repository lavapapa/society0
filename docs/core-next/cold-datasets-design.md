# 不可变批次正文

该设计面向大批导入与不可变数据集，将正文从当前数据库和新根的重复副本中分离。普通 Thread 小消息继续使用同库块。完整步骤的唯一发布权威保持 StageStore 描述符。

## 一、存储

一个明确导入批次封存成一个 SQLite 工件，使用原生主键表保存 ordinal、原文长度和独立 64 KiB JSON/zlib 块。复用现有有界字符串编码，初版不增加字典训练或组索引。临时数据库使用单事务构建、关闭连接后 fsync 文件、原子改名并同步目录。完成这一步后，规范 writer 在同一事务插入数据集头与文件依赖，调用方可用 attach 回调同步把引用写入机制的热状态。失败的未引用文件留作离线孤儿，完整恢复不包含它。

`Datasets.import_rows(name, rows, attach=None)` 返回数据集身份引用；`page` 提供总数、连续游标与有限响应字节，大值返回完整范围引用；`read_payload` 按 ordinal 与偏移解压必要块；`get` 是调用方明确选择的全文读取。授权由持有引用的机制和 Information 提供者负责，数据集服务不增加另一套任意 SQL 查询接口。工作量由本批行数和正文长度决定，热读使用主键范围。

## 二、恢复

不可变工件在同文件系统恢复时以原生硬链接建立目标目录独立入口；EXDEV 时显式复制，其他链接错误向上报告。可变 current 和 root 始终使用原生 backup。来源删除后目标工件继续有效，目标对工件的写入属于违反封存合同。链接不会把来源目录变成运行依赖。

restore 与只读完整点准备共享一个物化函数：从 root 应用所选完整链并收集相同的工件引用。restore 生成新身份、新根和可写运行；prepare_readonly 生成一个带来源身份的 current 与读取元数据，省去可写新根，禁止作为恢复源和 writer 打开。Observation 保持稳定的来源完整点派生身份与既有游标合同。

## 三、验收

TDD 先验证一批一文件、Unicode/类型/顺序逐值、大正文跨块与尾部范围、页预算和游标连续性；导入迭代器失败、封存失败、登记失败分别验证零业务引用及旧完整点仍可恢复。恢复测试核对同 inode、模拟 EXDEV 的复制路径、源删除后再读取和继续恢复，以及完整点工件与孤儿清理边界。

正式消费者将数据集引用写入自己的热状态，通过 Information 读取页与原文范围。只读准备回归 Observation 的身份、进程失败、关闭、完整点换页等现有测试。有限真实子集先比较所有 current/root/artifact 文件数、fsync 数、逻辑长度、按 inode 去重后的分配量、读取和恢复成本；通过后从既有转换库做全根试验，避免再次解析旧 World。

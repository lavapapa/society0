# 不可变批次正文

该设计面向大批导入与不可变数据集，将正文从当前数据库和新根的重复副本中分离。普通 Thread 小消息继续使用同库块。完整步骤的唯一发布权威保持 StageStore 描述符。

## 一、存储

一个明确导入批次封存为单份不可变 SQLite 工件。records 表按 ordinal 保存记录在连续原文中的字节起点与长度；blocks 表按整数主键保存独立标准 zstd 帧。每块原文至多 64 KiB，小记录共享块，巨记录跨块，记录之间保持独立身份。在线单值和冷批次连续原文共用同一 ChunkWriter，RapidJSON 推送与 backports-zstd 同步压缩，SQLite 原生索引负责定位。

工件经 prepare_artifact_file 完成数据库关闭、文件同步和目录发布，再在同一规范事务登记 datasets 头及文件依赖。attach 回调可在该事务把引用写入机制热状态。引用含 artifact，定位整份工件；所有完整点、恢复及回收使用共同的工件登记。失败形成的未引用文件留作离线孤儿。格式身份由 datasets.py 的实现规定；格式改变后建立新运行，历史工件由其产生版本读取。

`Datasets.import_rows(name, rows, attach=None)` 返回数据集身份引用；`page` 提供总数、连续游标与有限响应字节，大值返回完整范围引用；`read_payload` 按 ordinal 与偏移解压必要块；`get` 是调用方明确选择的全文读取。授权由持有引用的机制和 Information 提供者负责，数据集服务不增加另一套任意 SQL 查询接口。导入工作量由本批行数和正文长度决定。页查询按 ordinal 主键范围，正文范围由字节起点直接换算块号，再按 blocks 主键定位，工作量由所请求记录和块数决定。导入成功消费全部记录后封存尾块；消费或写入失败时关闭私有工件并向上传播原异常。

## 二、恢复

不可变工件在同文件系统恢复时以原生硬链接建立目标目录独立入口；EXDEV 时显式复制，其他链接错误向上报告。可变 current 和 root 始终使用原生 backup。来源删除后目标工件继续有效，目标对工件的写入属于违反封存合同。链接不会把来源目录变成运行依赖。

restore 与只读完整点准备共享一个物化函数：从 root 应用所选完整链并收集相同的工件引用。restore 生成新身份、新根和可写运行；prepare_readonly 生成一个带来源身份的 current 与读取元数据，省去可写新根，禁止作为恢复源和 writer 打开。Observation 保持稳定的来源完整点派生身份与既有游标合同。

## 三、验收

验收核对一批单工件、Unicode/类型/顺序逐值、大正文跨块与尾部范围、页预算和游标连续性；导入迭代器失败、封存失败、登记失败分别验证零业务引用及旧完整点仍可恢复。恢复测试核对同 inode、模拟 EXDEV 的复制路径、源删除后再读取和继续恢复，以及完整点工件与孤儿清理边界。

正式消费者将数据集引用写入自己的热状态，通过 Information 读取页与原文范围。只读准备回归 Observation 的身份、进程失败、关闭、完整点换页等现有测试。有限真实子集先比较所有 current/root/artifact 文件数、fsync 数、逻辑长度、按 inode 去重后的分配量、读取和恢复成本；通过后从既有转换库做全根试验，避免再次解析旧 World。

数据集使用基础 APSW、RapidJSON 与 backports-zstd 依赖。每次公开读取使用短期只读 immutable SQLite 连接，并在该作用域内使用标准 functools.lru_cache(maxsize=1) 保留一个解压块，相邻记录复用同块。作用域结束清空缓存、关闭连接；HTTP 的独立请求和首次打开沿相同索引读取，无需跨请求文件句柄池。每块 64 KiB 原文不构成物理 I/O 或整进程内存上限，SQLite 页缓存、压缩器、输入对象和全文输出分别计量。正文范围的字节身份以实际封存的 JSON 字节为准，全文读取恢复 JSON 值与原文字符串。

同源真实大根对照发现 seekable 容器的每次打开会解析整个帧目录，固定小页读取因而随批次总帧数增加；小样与单次 page 内的解压计数未体现这一总代价。逐记录单独压缩的候选又增加大量短帧及索引空间，故当前按批次连续封存共享块。实现使用 SQLite 原生索引和已有独立帧编码，正式 HTTP 请求保持独立读作用域。选型反证、逐值对照和后续完整测量保存在 [本轮能力复审](../../research/core-next/acceptance-20261004/capability-review.md)。最终资源结论按完整数据、实际消费者、首次读取与独立打开成本分别判断。

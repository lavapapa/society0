# 工作台数据

现有单文件工作台继续负责版本配置比较、运行与主体选择、原文会话、表格和图形呈现。新适配器读取正式运行产物，将明确选择的完整步骤转换为相同数据格式，渲染器无需重新实现。

## 一、范围

`export_payload([RunSelection(path, version, steps, actors), ...], title=..., question=...)` 返回现有渲染器所需的 study 和 versions。path 指向含 runner.json 的正式运行目录；version 是展示版本名称，steps 和 actors 显式选择步骤及主体。相同版本下的公开配置及实体选择必须一致，多个配置版本可分别保存其运行。空选择列表生成真正的空态。

适配器对每个运行物化一次所选最大完整步骤的只读视图，然后读取各个已保存 Results。逐行表、TableValue 的完整结构与 DatasetTable 的封存引用均通过 Results 的统一接口读取，导出按每页最多 1,000 行、1 MiB 的预算读取，页内共享封存块缓存；页项以 value 与 payload_ref 显式区分，巨记录通过原文范围接口拼回。Thread 以 actor、业务 Moment 和 publish_step 定位每个步骤的完整事件前缀，同一时点再次激活的后续事件不会进入更早步骤。

结果记录同时提供完整 JSON 原文与按字段展开的表格；嵌套单元格保留 JSON 文本。数值型阶段指标连接为所选完整步骤的曲线，横轴保留步骤与业务时间；布尔值、非数值和超出 JavaScript 精确整数范围的值仍在原文中显示。曲线不会使用当前选择之后的数据。

工作台的共享环境视角展示阶段结果；主体视角展示真实激活结果和 Thread 事件。原始请求事件仍以原消息水位记录其输入关系，不重复展开所有历史消息。累计行动与物理用量仅标在所选最大完整步骤，主体共享批次归属仍保持不可相加的口径。任意历史 World 投影和 FoV 的重建由相应领域接口提供，适配器不从结果字段推断这些内容。

## 二、成本

导出为显式离线操作。准备视图需要恢复完整点，并占用临时数据库和关联工件空间；视图在本次转换后清理。转换及单文件工作台会物化所选结果和 Thread 事件，内存与输出体积随所选原文规模增长。该路径适用于明确范围的演示和检查，大规模持续读取使用 Observation 的分页与范围接口。

输出保留运行目录、完整步骤、阶段、Thread 和事件序号来源。外部工件在 Thread 中保存的引用原样显示，工件二进制正文不自动嵌入 HTML；完整运行归档使用存储导出协议。单 HTML 包含所选展示数据和现有界面所需代码，可离线打开。

## 三、使用

先通过 `python -m society0.kernel.workbench --run RUN_DIR --version VERSION --steps 1 2 --actors alice bob --output data.json` 产生展示数据。再运行仓库已有的 `python skill/scripts/render_workbench.py --data data.json --output workbench.html`。RUN_DIR、VERSION 与主体名称按本次真实运行替换；多版本组合使用上面的 Python 接口。

工作台中的配置编辑生成待核对的修改请求，保存运行事实和启动新实验仍由正式运行入口负责。导出的数据范围、来源身份与完整点边界共同决定该页面能够支持的判断。

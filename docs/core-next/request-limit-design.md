# 共享物理请求许可

同一个运行可以配置多个决策、分析与嵌入服务。每个端点和配置继续保留自己的并发上限；运行级外部请求额度由调用者创建的一份原生 `asyncio.Semaphore` 表达，避免配置数量乘出无意的总并发。

## 一、装配

`ModelProvider`、`EmbeddingProvider` 及 `model_plugin`、`embedding_plugin` 接受可选 `request_limit`。给两个工厂传入同一个 Semaphore，即可让所有具名配置共用额度。对象由本次运行装配者持有，每个运行重新创建；服务关闭不修改其他服务的配额。未提供时保持已有各配置和端点限制。

```python
limit = asyncio.Semaphore(8)
plugins = [
    model_plugin(model_profiles, request_limit=limit),
    embedding_plugin(embedding_profiles, request_limit=limit),
]
```

## 二、作用域

端点许可取得后，在必需的物理请求留证之前申请共享许可，SDK 返回或抛错后通过原生 async context manager 释放。重试等待、缓存命中和微合批排队不持有该许可。模型调用先固定轻量 Thread 水位，取得配置、端点和共享许可后才加载该水位的完整历史；正文加载和必需留证均属于已获许可的请求准备。必需请求留证使用这次许可；留证失败时释放，排队期间取消不会计入已发物理尝试。一次嵌入物理批次取得一次许可，保留各原文和调用者的既有归属。提供方等待时间单列；共享许可等待加入既有队列耗时字段。

规范 SQL 写入、模型上下文与激活次数均沿原合同。此额度描述外部请求并发，不推断不同模型的 token 或费用等价，也不改变已有 max_turns 等主体预算。

模型重试释放本次完整消息列表后等待，再按同一水位重建。SDK 传输异常的已退出帧通过标准库清理，避免 traceback 在退避时持有消息列表；响应引用也在等待前释放。原始 Thread、完整请求重建和消息顺序均保留。SDK 自身可能持有数据，提供方返回值、工具配置以及调用者保留的对象也有独立驻留成本。许可约束获准请求的历史装载数，单个获准请求仍需要完整模型上下文。

## 三、验收

先验证两个模型配置与嵌入同时请求时的真实 SDK 活动数，再验证共享额度被占用时缓存仍可返回；等待许可的物理 worker 在关闭中取消并排空，其他运行中的请求保留其许可。微合批与重试分别按物理调用计数，配额对象不在逻辑和物理层重复获取。原文留证、重试分类及关闭协议复用现有直接测试。

正文使用规范 writer 的同步原生压缩；嵌入缓存仍按显式配置分别受条目与字节上限约束，共享请求额度不等于运行级缓存总上限。Memory 的 Chroma 派生索引及其驻留由所注入客户端管理，不属于此并发许可的内存承诺。

排队测试以受控许可和事件同步证明申请者尚未读取历史；退避测试使用可弱引用的消息列表，在无显式垃圾收集的情况下确认对象释放，并对后续追加消息隔离、重试全文和请求引用做严格比较。旧测试中两次 SDK 调用复用同一个 Python 列表的断言已改为原值和顺序比较，与按固定水位重建合同一致。

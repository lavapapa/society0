# 研究者入口修订

本记录保存 2026-10-04 首次使用审查后的实施规格与验证。范围为公开文档、规则运行例子和结果分析教程；既有模型与存储实现继续由原验收记录说明。

## 一、规格

首次使用沿一个实际执行链完成：明确源码身份和基础安装，运行两个规则主体的第一个时点，读取完整步骤的结果，再从该完整点创建新目录执行剩余时点。规则工厂明确接受 start/end；runner 继续负责恢复后步骤编号，研究工厂负责业务时间。连续两步与中途恢复后的业务时间、主体、结果值和顺序应相等。

分析教程消费 Observation 的结果引用、分页及大正文范围。分析先建立选定完整点的只读目录，结果保留步骤与阶段身份；旧 metrics.jsonl/steps.jsonl 路径退出现行教程。读取工作量随研究者明确选择的结果行和正文大小增长，完整点准备沿现有恢复链计费。

README 指向一份可执行起步页，LLM starter 保留其研究协议。需要记忆或向量检索的实验配置 embedding；普通 LLM 驱动按自身依赖装配。退役示例归档并标明原来源。长期文档保存职责、合同与证据入口，阶段状态和计数由带日期的验收记录提供。

## 二、概念

复用双机制对话例解释主体共享、机制命名空间、显式阶段及规范写入。服务依赖影响安装与步骤钩子的登记顺序；因果顺序由显式 Phase 表达。同 Moment 表示同一业务时点，各次 live 读取仍可见变化。进度、当前诊断、完整步骤分别用于监督、排查与恢复。私有文件承载笔记，行动回执描述业务结果，完整发布提供恢复身份。计算服务每次提交一个任务，机制作者显式决定任务边界。

## 三、验证

先运行失败用例重现规则工厂缺失显式时间范围、现行起步链和结果读取消费者缺失。随后原样执行起步页安装完成后的命令，比较连续与恢复结果，并将分析教程用于多页和大正文实际结果。相关现有 runner、starter、公开 API 与工作台消费者复验；本任务不访问凭据或调用真实模型。

失败记录见 [首轮失败](onboarding-red-20261004.txt)：规则工厂要求旧 steps 配置，缺少完整起步页，旧分析示例还依赖 pandas 和 JSONL 文件。新增消费者修后通过，见 [直接复验](onboarding-green-20261004.txt)。

[相关复验](onboarding-related-20261004.txt) 覆盖新增教程、runner、starter、公共 API 和现有工作台共 24 项。公开起步页安装后的命令原样执行；连续与恢复的主体、时间和结果逐值相等；分析教程保留跨页、巨型中文原文、空值、布尔值和大整数。安装过程沿既有干净安装证据，本轮未重新下载或安装依赖，未作真实模型调用。

退役顶层示例原样归档到 research/legacy-examples-v4，来源版本由目录说明固定。现行引用已切换到核心规则/双机制例子；领域材料中的旧 instruct/interview 调用名称同步改用 LLMPolicy。原样命令验证从已经安装的环境开始，示例源码由本树导入；它不替代公开仓库分支可取得性或新发行包的干净安装验收。完整仓测试、独立审查和提交由主控统一安排。

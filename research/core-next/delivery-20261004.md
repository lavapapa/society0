# Society0 Core 源码交付报告

本报告归并新版共享环境与分层插件实现的交付范围、证据及成本边界。当前产品冻结点为 `89ad172`，能力复核文档为 `4a7ae7a`，真实尝试历史归档为 `2440696`。最终合入身份、最新完整验收和发行记录待收口后填写；本稿尚不构成全部门槛通过的声明。

## 一、交付

Society0 以一个共享环境组织主体与机制。Plugin 声明 schema、初始化、服务和依赖；compose 汇集声明并建立状态，随后安装服务。主体身份与私有状态持久保存，Driver 按需激活。规则驱动和 LLMDriver 共享信息与行动接口；信息视图提供授权发现、分页查询和完整原文，动态行动按类型注册、按对象与当前条件发现及执行。CodeSchedule 的阶段明确控制时间与顺序，独立阶段的并发由显式配置选择。

完整会话、模型与嵌入请求、记忆正文和原向量、调用回执、结果与工作区均有正式消费者。自动召回、自动写入和主动记忆工具在每次激活分别配置。Bashkit 提供主体 shell，动态只读挂载连接共享资料，私有工作区按变更文件保存。外部观察与工作台读取实际运行事实和完整结果。研究者从正式插件工厂与运行入口装配运行，合同入口见 [实施结果](../../docs/core-next/implementation-result.md)。

持久化采用混合布局：规范 SQLite 事务维护当前状态、事实和索引，原生 Session 捕获变化，完整步骤集中发布恢复身份；不可变大正文按工件引用保存，Chroma 承担派生向量检索。运行中的进度与调用诊断可及时读取，恢复采用已发布完整点。行动处理器异常或取消会使共享步骤失效，驱动捕获异常也无法发布该步骤；正常业务拒绝按机制合同处理。

## 二、实现

公共接口与领域编排使用 Python，SQLite/APSW、RapidJSON、zstd/zlib、Chroma 与 Bashkit 承担相应原生工作。薄 Rust 文件系统适配器连接成熟 Bashkit ABI，提供动态共享读取和私有文件级增量。该选择保持机制扩展的短路径，并将大数据编码、压缩和存储交给已有实现；具体依据见 [语言选择](../../docs/core-next/language-decision.md)。

主体字段与数据集可按需读取，休眠主体无需常驻驱动解释器。查询下推到规范索引，页预算、总数、继续游标和正文引用保持完整信息可达；相关数据或权限变化会使旧引用明确过期，无关 Thread 留证不打断有效分页。并发阶段的行动按实际执行顺序写入，共享状态业务若要求固定次序，应选择串行阶段或明确隔离方案。

这次接口与磁盘格式允许破坏性重设。旧 World 入口和专属内部结构已退役，有效资源适配器、共享调度资产与旧领域算法参考保留。新格式不迁移旧检查点；旧基线仍可由固定源码身份复现。[78 项能力矩阵](../../docs/core-next/capability-parity.md)及[逐项复核](capability-review-20261004.md)记录保留语义、重设边界和当前消费者。

## 三、证据

两轮无作者历史的独立审查分别检查完整公开调用链与精确归档源码。第一轮识别的目录权限与部分行动失败发布问题已有直接修复和独立回归；[第二轮审查](final-review-r2-20261004.md)未发现新的产品阻断，并覆盖确定性、隔离实验及实际 pilot 工作台。两轮结果各自绑定原提交，随后模型会话参数、查询发现说明和可选温度策略的变化另有作者红绿与非作者复验。最终冻结源码的总复验结果将在下节登记，旧快照通过不自动转写为当前通过。

[旧新逐值对照](parity-report-20261004.md)在固定旧版 `96b1f3b` 与新版实际运行路径上，分别执行规则和确定性模型三步小世界及中途恢复。账户、顺序事实、全部决策材料、实际召回顺序、记忆原文和向量逐值相等；同版本连续与恢复的完整 Thread 及实际模型输入也逐值相等。协议文本跨版本允许变化，比较仍核对完整业务信息和工具原文。该小世界支持迁移语义判断，产业规则与随机模型效果继续由各自实验承担。

真实服务用于验参数、工具、记忆与跨进程恢复，主体效果另验自主发现、分页与行动完成。此前失败和各次部署身份完整保存在 [真实失败记录](real-failures-20261004.md)及其链接工件中；提供方限制、请求合同不匹配与主体工具使用结果分别记录。最新 V05/V06 待当前冻结源码运行结束后填写，其他提供方的 SDK 确定性测试不表述为真实网络通过。

## 四、性能

[性能综合报告](performance-acceptance-20261004.md)保存各负载的源码身份与原始口径。实际约 1.879 GB 状态展开为 1,448,471 条记录，全部记录及顺序验证相等；最终冷批次源目录约 226.54 MB，约为原整体 gzip 的 1.30 倍。完整导入约 59.49 秒、峰值约 335 MB，包含最大单条解析。独立进程范围与连续分页路径保持小工作集；同文件系统工件共享使本样本恢复成本较低，跨文件系统复制和同库历史不具有相同收益。

固定活动量扩大历史时，Thread、Social、资源统计的规范索引工作量维持既定范围。实际 1,000 主体、一个活动 shell、8 MiB 未改文件的连续激活没有新增正文工件。完整目录枚举、巨大单值改写与文件 copy-up 仍随所处理内容增长；自然数据边界和热字段拆分须由机制采用。

32 核服务器的 [X08](x08-runtime-parallel-20261004.md)分别测规则、完整 LLMDriver 和真实 Chroma 的确定性组合。原生 JSON 加压缩负载在线程下有明确收益，纯 Python 数值核可用进程降低墙钟，但增加总 CPU、IPC 与驻留。模型等待、记忆检索和领域计算分别计量，嵌套耗时不相加。[实时补测](final-realtime-20261004.md)写入四条完整 10 MiB Thread 正文，独立观察进程读取状态和追加水位；作者与非作者两轮事件循环最大间隔约 109/71 ms、观察最大响应约 1.28/1.08 ms，全部原文相等。这些短样本提供实际接口证据，尚未构成长时间尾延迟保证。

剩余主要成本包括完整模型历史的必要输入、Chroma 当前有效向量及历史临时索引驻留、changeset 链恢复、同库认知历史复制、巨大文件整文件读取和 copy-up。高活动并发下 LLM、Memory、Shell 的联合驻留，长期多读者 WAL 高水位，以及真实产业机制的资金、库存与业务索引，仍需对应负载验收。冷数据读取的低 RSS 不能代表整机内存预算。

## 五、使用

当前提供源码工作树安装及已验证平台轮子。基础规则路径保持轻依赖；模型、记忆、社交、shell 和不可变数据集按 extras 安装。原生文件系统轮子已在 macOS arm64 与 Linux x86_64 实际安装并验证文件写入、完整点及恢复；源码构建采用 Rust 1.95.0，安装已构建轮子无需 Rust。POSIX 锁决定当前运行范围为 macOS/Linux，Windows 尚无对应合同。

运行 SQLite 与 WAL 使用本地文件系统，网络挂载承载封存和传输。公开 PyPI 的 Core 与原生扩展配套发行尚未完成，源码可运行与公共发行分别确认。安装命令、依赖和平台说明以 [安装合同](../../docs/core-next/installation.md)为准。

CI 配置使用冻结依赖、全部功能 extras、本地原生包构建及实际 pilot 产物的 Node 验收。默认 Node 测试固定串行执行以避免测试服务端口竞争。配置复核和本机执行证据已保留，远端 CI 成功状态须由实际工作流记录确认。

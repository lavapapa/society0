# 文件与搜索资源验收

本轮以完整原文、真实 SQLite、ActorFiles 和原生 Reader 为测量对象。`performance.py` 在各独立进程完成初始化后计时，记录墙钟、CPU、进程峰值 RSS、源读取字节与回调、APSW SQL PROFILE VM steps、输出大小和磁盘增量。每次查询及搜索均以原文逐条校验；完整 JSONL 行号、字节位置与正文还由原生批处理测试逐项校验。RSS 包含进程初始化，磁盘增量包含 SQLite WAL，因此不可解释为纯操作增量。单次测量用于量级判断，尚未形成统计置信区间。

## 一、活动规模与历史

`performance-before.jsonl` 与 `performance.jsonl` 保留同输入 dev 构建前后记录。固定二十条活动文档，无关历史从一万到十万条，最新 N 查询、ActorFiles 构造、列表及范围读组合保持 3890 VM steps、640 源字节、十次读取，墙钟约 0.003 秒。固定历史增大活动主体至十个时，工作量随活动规模增长至 39080 VM steps、6400 字节及一百次读取。

查询本数据集的累计历史时，精确 total 的 COUNT 仍遍历索引：一万到十万条使 VM steps 从 301010 增至 3001010，墙钟约 0.003 至 0.015 秒。FULLSCAN_STEP 为零表示使用索引，不能据此认定总成本恒定。规范写者提供维护后的 `base_count` 时，相同查询保持 1020 VM steps。该路径的前提是计数注册与规范写入同步成立。

## 二、工作区

冷 Overlay 十页、每页五条的目录列表，在目录从一千增至一万文件时，原实现分别为 100970 和 1000970 VM steps、约 0.036 和 0.334 秒；接入已有 WorkspaceLease 索引页及规范维护的 workspace_counts 后，两者均为 1560 VM steps，约 0.001 秒。此结果适用于尚未修改的 Overlay。已修改 Overlay 的列表仍由 Bashkit 合并当前目录再分页，成本由该目录文件总数决定，尚无同等有界保证。

冷文件范围读走 WorkspaceLease blob range。热文件采用原生 Overlay 最近文件缓存；首次读取上层文件仍物化完整当前文件，后续范围读命中该缓存。当前工作区信息不会因分页或缓存被省略。

## 三、原生批处理

保持成熟 grep Searcher/Reader、匹配表达式与公开三参数异步 sink 合同，原生层按约 64 KiB 命中内容分批跨语言传输，再由 Python 顺序调用原 sink。单条超长行保留完整原文，可以超过批大小。取消路径继续取消当前回调并等待原生工作者排空。

同 dev 构建的 1 MiB 高命中输入产生 40329 条完整结果、5229255 输出字节，源读取恒为 1048554 字节及十九次回调。墙钟从 2.237 秒降至 0.111 秒，CPU 从 1.301 秒降至 0.109 秒，RSS 从 52445184 到 52183040 字节；跨语言 sink 回调为三十六批，公开逐行 sink 调用仍为 40329 次。空匹配约 0.018 秒、零输出，超长行约 0.019 秒、一个完整结果。注册工件前临时 spool 保留完整结果，持久化期间 spool 与目标工件短暂同时存在；报告中的最终磁盘增量没有包含已关闭 spool 的峰值，峰值应另加当时 spool 的完整字节数。

同 8 MiB 原文补测记录为 `cost-results.jsonl` 与 `cost-results-batched.jsonl`：短行 68759 次命中，两次均读取 8388608 字节、一百三十二次源回调，完整输出 8388598 字节；墙钟 3.538 至 0.038 秒，CPU 2.047 至 0.031 秒，RSS 52510720 至 50429952 字节。超长行两次均一个命中、8388608 输出字节及一百三十次读取，墙钟 0.102 至 0.013 秒。后一次使用最终 release wheel，前一次为 dev，因此这一组同时包含构建优化影响，不能将全部差额归于批处理；上段同 dev 对照才支持批处理贡献判断。shell head 仍先整读 8 MiB 回调文档，范围 read 实际读取 64 KiB，该边界仍明确保留。

## 四、交叉审查

SQL metadata 使用注册字段、SQLite 声明类型、字段说明及查询范例，不扫描正文行；成本描述明确精确 COUNT 与 sample 的遍历语义。授权与依赖水位继续通过原 Information 路由复核。注册者提供的说明与范例属于提供者声明，未被升级为自动推断的领域事实。

记忆提取使用成熟 PydanticAI Agent 输出结构与重试；首轮完整 typed history 延迟到已有提供方许可授予后载入 SDK 历史对象，重试复用相同对象，校验反馈仍写回原 Thread。排队取消不会提前物化历史，相关回归覆盖物理重试与输出纠正。此改动针对记忆提取的排队历史，普通 LLM 激活仍按其完整历史合同执行。静态交叉审查未发现需要新增修补的合同问题，确定性与真实提供方终验由独立验收工序记录。

本轮新增统一文件视图、搜索、扩展挂载和结果身份等合同，代码总量增加。移除了旧调度类型、Runtime 与 Schedule 耦合及重复 data 工具接口，维护面更集中；不能据此声称总代码量缩减。资源结果支持活动索引、范围读与有界传输的具体改善，并保留精确 COUNT、当前已编辑目录列表、超长行与回调整读等成本边界。

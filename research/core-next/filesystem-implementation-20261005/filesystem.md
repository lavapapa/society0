# 文件底座实施证据

本轮把原文文件身份、连续搜索和范围读取接到现有信息与存储服务。正式工具与完整 Thread 结果接线由同目录的统一文件消费者验收补充；这里记录文件底座、社交信息迁移及成本边界。运行日期为 2026-10-05，源码为当前 `society0-core-next` 工作树的未提交候选。

## 一、实现

`InformationFiles` 的原文地址始终是普通文件，正文大小不改变类型。显式 manifest、字节片和文本片继续供传输使用，逻辑目录列举的条目保持原始资料。Bashkit 的 read_file 接口仍整份物化；原文 callback 以范围源取得完整字节再拼接。这保留真实 cat、head、grep、jq 的原文管道语义，其输入成本由所选正文长度决定。

原生扩展固定 `grep-searcher=0.1.17` 与 `grep-regex=0.1.14`，锁文件登记完整依赖。每个逻辑文档独立调用 Searcher 的连续 Reader；Python 单次范围回调最多 64 KiB，UTF-8 和正则的块边界由成熟库处理。逐行命中的行号、原文字节位置和原文立即交给 sink，原生层不累计所有结果。搜索支持普通逐行正则、literal 和 ignore_case，显式跨行模式被拒绝；单行缓冲仍随最长行增长。

`information_fs.search_reader` 是生命周期入口。它 shield 原生任务，取消时停止并取消本调用的 Python 回调，等待回调和原生工作线程结束后传播取消，允许上层随后关闭工件。SQL 查询仍发生在原始 Python 事件循环上的范围回调，原生阻塞线程负责匹配。确定性 Event 屏障验收覆盖 read 阻塞期间取消、回调 finally 完成以及没有后续 sink 写入；源异常传播成错误。

SQL DocumentSpec 继续使用真正的 read_blob(offset,size)。DatasetSpec 和合成社交资料第一次读取产生一个临时原文文件，连续范围复用同一份正文；每次读取重新查询当前授权与依赖版本。缓存为提供者拥有的单槽，交错主体或文档会重新物化，内存成本仍包含 SQL 原记录与 JSONEncoder 的当前编码片，巨字符串编码片可能很大。临时盘占用等于该逻辑记录原文字节，替换和 Information 关闭时清理。实际需要巨正文时，声明 documents 指向 DocumentSpec 可避免记录物化。注册元数据公开 fields、key、order_fields、document_fields 和抽样扫描边界；查询原文引用增加 logical_path，同时保留内部 path 和 source 身份。

WorkspaceLease 的 read_range 直接使用 artifact 范围，目录读取沿(actor,parent,path)索引分页。当前 Bashkit 上层 Overlay 的公共API没有 range；新 Overlay.read_range 首次复制所选当前正文，连续范围复用单槽，任何文件操作使其失效。cold 持久正文应沿 lease 范围访问，上层当前文件通过 Overlay 保持本次修改一致。该限制写入正式工具和性能说明，不能推断上层首次小范围读取拥有 O(range) 成本。

社交机制的两个纯读取动作迁移到 `/world/social/post_details/<id>` 与 `/world/social/profiles/<actor>`。两条目录可发现；帖子保留完整原文、评论、点赞及事件、标签，用户资料保留关系、全部帖子标识及近期预览。原机制与文件视图复用同一查询函数，避免两套语义。带曝光记录的热门读取与消费通知保留 Actions。范围缓存依赖包括原始帖子正文、点赞、评论、标签、关系及主体资料的真实表水位；撤权和资料改变后的续读明确失败。

## 二、验证

`native-red.txt` 记录尚未存在搜索入口时的失败消费者。`base-first.txt` 保留纯读取动作迁移后的旧消费者失败；消费者已改为文件读取并保持全文、关系、帖子等原断言。`focused-green.txt` 是底座最终定向结果，包含 SQL 查询、blob 范围、原文／显式分片、UTF-8 跨块、逻辑文档隔离、异常、取消收束、范围复用、授权及社交恢复。统一 ActorFiles、LLM 工具及例子的组合测试由主任务验收结果补充；本文件中的本地结果不代表已发布。

跨块试验把中文每两字节拆开，并在 64 KiB 边界拆关键词；独立文档“关键”“词”“关键词”得到 0、0、1 命中。原始 file 读回全部字节，显式片重组保持原文及 UTF-8；没有把编码片作为搜索文档。workspace range 测试直接记录 artifact 请求参数，确认只读指定范围。社交测试比较整个合成对象，连续多次读取复用同一临时原文，并验证评论修改后的旧版本失效及完整步骤恢复。

## 三、成本

以 `.venv/bin/python research/core-next/filesystem-implementation-20261005/cost_probe.py` 重跑 `cost-results.jsonl`。每项使用独立进程，同一 8 MiB 生成正文分别构成短行与单超长行；源正文已在计时前生成并留在进程内存。记录墙钟、进程 CPU、数据源返回字节、回调次数、完整结果临时盘及 macOS ru_maxrss 的进程峰值字节。RSS 包含解释器、导入、输入生成峰值和已保留源正文，并非搜索器分配增量；未测磁盘源 I/O、全系统内存或提供方等待。

64 KiB 专用 read 两种输入都只返回一次 65,536 字节。Bashkit head 输出同样为 65,536 字节，却取得完整 8,388,608 源字节；短行与长行分别约 0.029、0.0068 秒，进程峰值 RSS 约 84 MiB。连续 Reader grep 两种输入都扫描完整 8 MiB。短行产生 68,759 条命中、约 8 MiB 完整结果，耗时约 3.54 秒、CPU 2.05 秒；单超长行产生一条约 8 MiB 命中，耗时约 0.102 秒、CPU 0.099 秒，进程峰值约 70 MiB。

高命中正文的逐条跨语言 await 与 sink 调度是当前可见成本，不应归因于正则算法。最小后续路径保持成熟 Searcher，把 Sink 输出交给标准 BufWriter，或以字节预算形成有界结果批次，减少跨语言回调；超长单行须仍明确付出单行成本。此类更改需要同一原文、完整命中内容、行号和偏移的同值对照，并保持取消收束合同。本轮保留逐条入口及原始数字，未引入另一套搜索算法或索引。

当前证据说明专用范围、连续 Reader 与 Bashkit 整读的实际成本分别由何种工作量决定；完整工具授权水位、结果持久登记及恢复由统一文件接口的组合验收承担。

# 跨模块独立验收

本次由文件系统实现者交叉审查调度、Runner、Driver、激活、模型许可、记忆、ActorFiles 与 shell。文件系统底座由另一位作者之外的审查者验收，见 cross-review-filesystem.md。本报告区分确定性软件验收、实际工作台消费者、安装交付与外部模型链。

## 一、独立失败与修复

首轮完整测试发现七项失败。恢复消费者仍传入剩余 timeline，现改为完整时间序列，保留完成步与全部事实断言；真实文件消费者仍调用旧工具，现通过 ls、read、grep、bash data query 获取全部四页数据、完整原文并执行原行动；工作台规则 Driver 导入位置、异步状态机创建边界与测试 Shell 接口也沿新合同修正。

新增六项跨模块用例独立检查普通第三 Driver、扩展退出、搜索结果跨激活与完整点恢复、目录结果分页、同主体跨 Thread 工件身份和工作区保存失败后的可信恢复。分页首次实测读取 4,942,600 字节来取得一页短路径；改用标准库 BufferedReader 共用缓冲后读量有明确上限。工件身份冲突原由数据库唯一约束阻止，新规范写入器给出显式 ValueError，原工件及计数保持完整。

保存失败用例验证诊断 Thread 为 incomplete 且完整点仍为此前一步。尚未发布的诊断中可能有提取记录；从可信完整点恢复后，失败步的记忆行、记忆作业和 Thread 均缺席。这个结论依赖现有完整步骤发布协议。

## 二、消费者与交付

补充优化前的确定性完整测试为 860 项通过，实验测试单独 75 项通过。实际两步会话工件导出后，Node 工作台九项测试通过，真实表格八行、时间序列两点通过消费者断言。

安装交付使用全新 Python 3.12 环境和 base wheel，在仓库外复制官方示例，执行入门文档命令并用完整 timeline 恢复。可选 AI、embedding 和 legacy 模块未安装，示例仍完成两步。补充优化前 wheel 内 50 个 Python 源文件与工作树逐字节一致，未使用摘要校验。共同冻结后重新构建的 metadata-final wheel 同样 50 源文件逐字节一致，纯 base 环境官方教程再次完成。native采用 release 构建，安装的扩展字节与本次 wheel 内扩展一致，证据见 native-release-identity.json。

## 三、外部模型

real-final-01 在密钥段标签解析阶段退出，没有端点请求。real-final-02 使用获授权“硅基流动”段的第一项配置，首次固定 Qwen/Qwen3.8-27B 请求收到 HTTP 401、提供方错误码 30014；测试在 2.19 秒失败，embedding 与后续十四场景未执行。失败身份和脱敏请求事件保留。此结果属于该配置的提供方授权问题。

同段第二项配置在共同产品冻结后尝试一次，仍使用固定模型、embedding 维度和原预算。凭据值没有进入代码、报告、启动参数或工件。

共同冻结后最终确定性全量 865 项通过、零失败、零跳过，用时 37.035 秒；实验 75 项和 Node 九项再验通过。目录计数规范投影新增一个失败先行测试，保存同步维护计数，冷目录分页沿索引读取。最终真实源码快照与当前 50 个 Python 文件逐字节一致。第二项同提供方配置 real-final-03 返回 HTTP 403，响应要求完成身份认证；embedding 同样未执行。用户直接提供凭据通过 TTY 使用后，real-final-04 的十四场景通过，包含记忆写回、召回、跨进程完整点恢复与社会行动。最后文件场景在第八次请求等待 60.0035 秒后失败，前七个工具全部成功，尚有回合和行动预算；配置恰为 60 秒 asyncio timeout，错误正文为空且无部分响应，支持端点请求期限触发的判断。原文、分页与预算未调整。该次尝试保留一项失败，见 real-final-04/real.xml 与 summary.json。最终同合同复测判断见下一节。


## 四、最终判断

冻结产品 ab6469d 的十五个真实场景取得同合同覆盖：real-final-04 十四项成功，最后一项在原 60 秒请求期限失败；real-final-05 对该场景保持原模型、原 20 回合与两次行动上限、原 60 秒期限独立复测成功。两次尝试之间没有产品修改、信息删减或预算提升。该结果是十四加一的覆盖，原失败及其资源成本完整保留。完整价格四页、十二条记录及合计 546、报告全部范围原文、grep 短语和主体行动通过原断言。记忆写回、召回及跨进程恢复由前十四项原断言覆盖。

真实调用物理次数、耗时与修正用量边界见 real-coverage-summary.json，两次原始结果见各目录 real.xml，单次现行摘要见 corrected-summary.json。历史 summary.json 保留原失真测量。原启动合同遗漏 SDK 连续累计流用量配置，模型 token/cache 经累计块相加失真且无原始末块，现行字段为空；物理调用、错误、耗时、嵌入用量与行为 oracle 不受影响。具体纠错见 usage-correction.md。最终确定性 865 项、实验 75 项、实际 Node 九项及纯 base wheel 外目录恢复均通过，源码逐字节绑定 ab6469d，native release 安装字节与构建 wheel 一致。软件与本次短程真实合同验收完成，长期稳定性仍需以持续运行观察判断。

## 一、实现

主体使用 read、ls、find、grep 和可选 bash 探索 /world、/context、/workspace、/results。世界信息仍由 SQLite 当前投影、正文工件及信息提供者按需呈现；虚拟路径无需复制全部世界到真实文件。领域变化经 action_find、action_describe、action_invoke 执行，动态行动范围、参数与预算保持完整。社交中的纯读取能力迁入信息路径，曝光、推荐与通知消费仍保留其业务动作。

Driver 工厂通过普通 Plugin 服务安装，规则、LLM 及第三方驱动可组合异步认知扩展。Memory 使用同一扩展和挂载接口，自动召回、提取写入与主动访问继续分别配置。Schedule 产出 StepPlan，Runtime 执行和发布；SequenceSchedule 按完整时间线和完成步骤身份恢复。

数据集 schema 给出字段类型、含义、时间口径、排序能力、正文引用及可执行查询例，空集合也可发现。通用 SQL 下推查询生成可继续读取的结果文件。记忆提取改由 Pydantic AI Agent、标准结构输出与 SDK 重试承担；独立提取等待模型许可后才加载完整历史，并保留服务重试和纠正轮的全部消息。

真实调用固定使用 SiliconFlow Qwen/Qwen3.8-27B 与 Qwen/Qwen3-Embedding-0.6B（1024 维）。完整测试首次十四项通过，最后文件发现场景第八请求在原 60 秒时限结束；同冻结代码、原二十轮／两次行动预算及原时限复测该场景通过，形成十五场景覆盖。原失败与消耗保留，未宣称单次全绿或长期无故障。工件断言核对全部报价页、完整正文、实际行动、自动记忆及独立进程恢复。纠正后的调用统计见 real-final-04/corrected-summary.json、real-final-05/corrected-summary.json 和 real-coverage-summary.json。累计包括失败尝试的 139 次物理调用，其中模型 112 次、嵌入 27 次；模型成功响应 111 次、错误 1 次。原启动合同遗漏 SDK 连续累计流用量配置，已保存的模型 token/cache 是累计块相加后的失真计量，且缺少原始末块，无法恢复可信数值；现行摘要将相关字段标为空。嵌入用量、物理请求、耗时与行为断言保持有效，原失真数字仅保留为历史测量，详见 usage-correction.md。

## 三、成本

固定活动集合、无关历史从一万增至十万条时，组合查询保持 3890 条 SQLite VM 指令和 640 字节原文读取。冷工作区一千至一万文件、十次五条分页，指令数从随目录增长的 100970/1000970 收敛为两档均 1560。维护计数和索引均在规范写入路径更新。

同 dev 构建、同 1 MiB 原文、同 40329 条完整匹配，搜索批处理把墙钟从 2.237 秒降至 0.111 秒，CPU 从 1.301 秒降至 0.109 秒；跨语言传输为 36 批。匹配仍由成熟 ripgrep 库承担，自有层组织范围回调与结果生命周期。这是单次局部对照，实际社会仿真的整体收益还取决于模型等待及业务负载。

已编辑 Overlay 的目录列举、首次当前巨文件读取、Bashkit 部分整文件命令、超长单行、精确 COUNT 和抽样仍有相应规模成本。完整搜索结果需要磁盘，封存期间临时文件与目标工件短暂并存。资源报告分别记录这些边界，未将范围读取推论为全部操作恒定内存。

# 资源累计投影验收

本组从实际模型与嵌入事实维护查询投影，供外部观察与后续工作台读取。ModelProvider 和 ResourceCalls 原文继续完整保存，投影使用短模型标识、物理调用身份、主体关系与整数计数。

## 一、事实

先失败用例记录在 usage-red-20261004.txt、usage-outcomes-red-20261004.txt、usage-thread-identity-red-20261004.txt 与 usage-generic-resource-red-20261004.txt。它们分别覆盖缺少累计消费者、解码与取消分类、跨Thread物理响应归属、通用资源事件仍可记录。实现采用显式物理Thread写入器，普通诊断事件和请求快照不触发物理统计。原 test_kernel_llm 的两项磁盘故障注入改为专用物理写入器，发送次数与禁止重试断言保持。

最终九文件直接组在 usage-final-direct-green-20261004.txt，94项通过；涵盖真实适配器SDK mock的传输重试、完整响应、两个主体微合批和第三主体缓存命中、全局与主体归属、取消/解码、事务失败、完整恢复、HTTP及历史准备视图。同一共享批次的 actor 统计是关联量，多个 actor 不可相加视作全局。没有报告的token保unknown计数，报告零值可由reports区分。

HTTP新增消费者的第一轮使用错误的测试字段 status 读取准备状态；产品字段实际为 state，修正fixture后通过，原输出保存为 usage-http-fixture-error-20261004.txt，不作为产品红灯。

## 二、成本

test_kernel_usage 的结构性试验以相同一个主体和模型插入100及10000条短调用投影；查询固定主体累计值的SQLite VM指令均为292，见 usage-complexity-green-20261004.txt。该试验验证查询走累计行，无正文历史回放；它不代表真实端点延迟或完整运行目录体积。

Thread与ResourceCalls各有短调用表、主体关系表、累计表。新增物理调用的空间随物理次数增长，主体关系随实际关联次数增长；累计查询随命中的模型行数增长。后续完整运行的磁盘统计需包含这些表、索引、WAL和changeset。当前试验没有压缩、合并或删减权威请求正文。

## 三、边界

live投影保留未完成步骤中已发生的物理事实，恢复到完整步骤时投影和原文共同恢复。物理响应与错误列可能重叠，例如收到响应后发生解码失败；物理尝试总数从requests读取。共享嵌入主体归属在逻辑来源事实落盘后可见，进行中与被提前取消的等待者不会获得推测归属。

本组无需真实端点即可验证调用路径、计数、恢复及有界观察合同。实际费用、长时间稳定性和最终干净发布版本的真实模型全链仍由后续V05/V06验收；独立复验由非作者另行记录。

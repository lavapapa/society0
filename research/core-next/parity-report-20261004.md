# 旧版与新版小世界逐值对照

本次以同一初始账户、同一顺序行动和完整中文材料，比较旧版 `96b1f3b` 的实际 World、行动循环、Chroma Memory、检查点，与新版 Core 的正式 Runtime、LLMDriver、Memory、StageStore。此证据回答三步小世界的业务与恢复语义是否保留；真实提供方参数另由真实服务套件验证。

## 一、运行

每步按 a、b 顺序分别支付 step、2×step，账户余额扣减、累计支付增加，原始事实按发生顺序追加。两条路线分别使用规则调用与固定模型响应。模型路线仍执行各版本真实行动循环，记录实际传入模型的完整消息、完整工具响应，并通过真实 Memory 写入原文和固定四维向量、随后实际召回。

每个版本与路线分别连续完成三步，以及先完成一步、从完整点恢复再完成后两步。旧版运行来自隔离归档，适配脚本在子进程首位加载该归档的 src。新版使用工作树源码，精确身份与唯一待提交说明改动记在 `parity-20261004/manifest.json`。所有子进程使用相同 Python 依赖环境；本次没有网络模型调用。

## 二、结果

八个最终分支的初始值、每步全部账户和事实、六次决策材料、记忆正文、时间、重要性及逐维向量完全相等。实际召回的排列顺序也包含在决策材料中逐项比较。每条模型分支共有六次请求，比较器从实际 provider 输入中解析 PARITY 材料，核对完整内容可达；六条 Thread 的工具消息均包含完整业务原文。

恢复核对发生在各版本的真实恢复消费者：新版从恢复后的 ThreadStore 读取全部既有消息；旧版在目标运行建立来源完整点后，通过目标 ObservationReader 的完整 checkpoint Thread 页读取并对照。两者都保留原先消息的逐值相等。各版本系统提示与工具协议结构不同，完整原文分别留存，本次未声称这些协议文本跨版本逐字相同。

## 三、复验

`benchmarks/core_next_parity.py` 执行十二个独立进程，包括中间一步前缀，并比较八个最终分支。输入适配位于同目录的 `_old.py`、`_new.py`。`parity-20261004` 保存每个分支完整 JSON、实际模型输入、Thread 原文以及比较结果，共约半 MiB。测试 `tests/experiments/test_core_next_parity.py` 验证实际证据，并分别破坏事件顺序、工具原文、模型输入和向量，确认比较器拒绝这些差异；作者五项通过。独立审查再加入八项系统消息、助手正文、工具数值与实际 provider 输入破坏测试，比较器现对同版本连续与恢复的全部 Thread 消息、全部 provider 输入逐值比较，合计十三项通过。

本次覆盖账户更新、顺序事实、完整认知输入、行动、原文记忆与完整点恢复的联合链。产业规则、随机模型决策一致性和不同向量算法的排序等价均需要对应领域或服务实验。本次结果可支持这个小世界的迁移语义判断。

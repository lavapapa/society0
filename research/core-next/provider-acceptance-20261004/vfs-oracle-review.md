# VFS 原文验收的期望纠正

`social-vfs-final-01` 的 VFS 运行已完成并发布完整点，原测试在第一条提交断言处失败。独立读取目标、行动 schema、两次实际正文读取与 SQL 提交后，确认主体提交的“原文校验成功。”保留了报告的完整尾串。

## 一、来源

报告原文精确为“完整信息：报价均为同一计量单位，金额按各行 amount 合计。\n核对短语：原文校验成功。”。任务要求保留核对短语，schema 将 phrase 声明为普通字符串，没有去标点规则。旧 expected“原文校验成功”删掉了源句号；离线脚本提供方还通过 rstrip 删掉句号，掩盖了期望与源的冲突。

修正后的唯一 expected 从报告正文中精确的换行标记“核对短语：”后取得全部尾串，包含句号，不做 strip、不接受两个版本。脚本提供方同样保留该尾串。自然语言中的“短语”可能让模型选择省略句末符号，但本例强调保留原文，现有带句号提交满足这一更严格逐字口径；无需重试随机生成。

## 二、复验

测试内提取 `assert_vfs_artifacts(destination)`，真实测试与离线 `review_vfs_artifact.py` 调用同一断言函数。现有工件复验通过全部后续断言：七种工具均实际使用、四页 cursor 连续且 limit=3/total=12、十二条 id 与 amount 逐条正确、bash jq 退出零且输出 count=12/total=546、最终提交 actor=a/count=12/total=546/phrase=精确源尾串。

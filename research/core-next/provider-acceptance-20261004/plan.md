# 真实提供方与规则负载验收

本组复用当前正式 Runtime、Actions、Thread、Memory 和完整点恢复。所有真实执行由主控注入环境；准备阶段不读取密钥、不访问模型。历史 acceptance-20261004 已证明离线合同，真实请求此前因授权失败留下缺口。本组与既有原始证据分开。

## 一、顺序

先运行既有 endpoint smoke，再运行两主体 round_robin 动作链，最后运行跨进程退出／恢复记忆链。对应 tests/e2e/test_core_next_real.py 的三个原例，保留其预算、独立提取、嵌入、完整 Thread 与失败诊断。正常约 13 次 LLM 请求及 8–11 次嵌入请求；主体自主调用工具会改变实际次数，物理 max_attempts=1，失败不自动重跑整组。每次激活原有 8 轮、4 行动预算不改，独立提取协议允许自身原有纠错次数。

主体效果比较复用跨进程例的 step 1 完整点，两支恢复到同一步并分别开启／关闭自动召回。两支关闭主动记忆工具与自动写入，保留同样的材料、任务和模型参数，仅观察自动召回这一变量；这项明确消融不改变正式默认能力。新时点不会继承旧 Thread 的正文，恢复点中的权威记忆、原始向量完全相同。正常另需 2 次 LLM 和 1 次查询嵌入。保存完整响应与事实命中分数，不要求关闭召回必然答错，也不将单次差异称为统计效果。真实测试实际请求数量以运行内资源计数为准。

## 二、成本

规则负载为共享账户事实：规则主体经 Actions 原子写一条不可变成交事实并修改余额；Thread 留动作正文，Results 保存步骤指标。既有历史使用同事实表预填，热查询使用余额主键与成交主键，没有全历史重放。先活动主体 8 不变、历史 1000／10000／100000，再历史 10000、活动 32／128；每格 5 个完整步骤。分别记录初始化、实际内核步骤、complete 时间、CPU、Session 文件、库／WAL／root 总字节与进程峰值 RSS。恢复在单独解释器进行，验证账户逐值、历史行数、Thread 数量与完整身份。

每格为独立进程，初始化高水位和运行高水位分别报告；高水位差不称为精确新增内存。规则路径无原生计算子进程，ru_maxrss覆盖该进程全部 Python／SQLite／压缩原生内存，操作系统页缓存及服务端不在该值内。这里测业务 fixture 的增长，完整产业经营及 Chroma 记忆运行成本仍引用既有专门证据。

## 三、门槛

确定性准备先验证小负载的业务值、历史不漏、完整点恢复与零提供方调用，再执行矩阵。配置脚本默认只输出不含密钥的命令；显式 execute 才调用 pytest 或效果消费者。所有输出使用新目录，不覆盖旧尝试。源身份记录 Git HEAD 和相关源文件副本，不将未提交树冒充干净提交。

## 四、完整覆盖

先行三个用例通过后，执行 remaining 模式覆盖其余十二项；两种命令均带 -x，首个失败即停，保留产物后逐案判断。十五项最大原配置 LLM 请求数见 request-budgets.json：每次调用物理 max_attempts=1，决策最多8轮，VFS原合同20轮，每个正常记忆激活另计最多2次提取。总保守上限256次，含同时取满多种预算的宽界；预计消耗远低于此值，不当作应消耗额度。先行三项保守54次，另消融两支至多16次，修正最初口头粗估50次。嵌入请求依赖实际提取条数、文本及微批次装箱，保留实际物理计数，不捏造固定上限。

VFS用例从根发现目录，实际取得四页全部12条报价，再由jq计算count=12/total=546；独立原文分段读取保留phrase，并通过动态发现／描述／执行提交。原例逐条验证页游标连续、记录ID与amount顺序、bash真实stdout及SQL提交值。任务指定阅读与计算工作流，行动名和参数答案由资料发现；因此证明工具链与定向任务执行，不能单独证明开放目标下研究判断能力。round_robin目标已经提供业务对象Ref，证明动态行动发现与执行，不声称自发形成行动目标。

执行示例：`PYTHONPATH=src .venv/bin/python research/core-next/provider-acceptance-20261004/real_acceptance.py remaining --output <新目录> --execute`。依赖固定、Agent.iter冻结和环境注入由主控完成；同provider同配置，失败不换模型或提高原预算。长缓存探针为 `endpoint_probe.py --cache-only --output <新目录>`，限定两次约8k前缀请求。

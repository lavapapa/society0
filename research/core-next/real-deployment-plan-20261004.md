# 真实验收部署与对照

本记录用于最终真实 15 项套件的部署及结果收集。当前准备阶段已经确认 simcat SSH 路径连通；已授权 Google 凭据存在且唯一，检查过程未输出或持久化其值。近期 Gemini 工具往返和 bge 双文本探针作为配置依据，完整验收以正式冻结版本的新运行结果判断。

## 一、源码

`benchmarks/core_next_deployment.py --commit <完整提交> --archive <新归档路径>` 将当前分支与 `git ls-remote origin refs/heads/<分支>` 实际返回的已推送 HEAD 比较，再使用 `git archive` 生成源归档。工作树内其他资料修改不进入归档。

源归档传入本任务拥有的新部署目录，解包后执行同脚本的 `--archive <归档> --destination <源码目录>`。逐个比较 src、tests、native、skill/assets、examples/core_next、部署脚本自身、pyproject.toml 和 uv.lock 的实际文件字节及文件集合，按 64KiB 顺序读取。Python 自动缓存不计入源文件集合。依赖安装与原生编译使用独立目录，正式源目录保持固定。归档、核对 JSON、部署命令记录和实际依赖版本与测试结果共同保存。

## 二、运行

既有 Linux 轮子资源入口为 `/mnt/data/l20/qin/runtime-observation-core-native-20261004`，新的 src/tests 使用固定提交归档。实际 Python 路径与依赖版本待环境核对后记录，避免把旧 Ceph 环境冷载时间解释为模型服务时间。凭据通过进程环境传入，公开清单保留环境变量名称和公开模型配置。

正式命令为 `SOCIETY0_RUN_CORE_REAL=1 PYTHONPATH=src <已核实Python> -m pytest -o addopts='' -q -rA tests/e2e/test_core_next_real.py --junitxml=<输出>/pytest.xml`，其余 `SOCIETY0_REAL_*` 参数依据真实套件设计文档在同一新运行目录预先冻结。保留全部失败工件，不在同一次运行中调整预算。记录开始结束 UTC 时间、精确提交、源码字节核对结果、依赖版本、公开模型参数、每项状态、错误类型、完整步骤水位、实际 SDK 区间和工件位置。

## 三、对照

V03 已有证据包括轮转配对顺序、社会网络排序及偏好构建与固定原算法比较，真实大根逐值恢复，以及新 Core Thread、记忆、原向量与工具回执的跨进程恢复。它们分别覆盖算法和持久化风险，当前尚缺同一完整小世界的旧新连续运行联合对照。

后续对照使用固定业务输入和模型假响应，建立纯机制、含 Driver 两条路径，对齐初始事实、逐步动作顺序、最终事实及恢复后继续运行结果。新的动态工具协议改变了请求结构，模型上下文按全部决策资料和原文可达性逐项核对；完整 Thread 分别保持各自规范事实，不要求不同协议的工具消息字节相同。记忆正文、原始向量、主体归属与顺序独立核对。真实套件通过后仍需完成此确定性对照，真实模型输出差异不作为逐值相等的替身。

验收摘要按实际证据报告源码身份、15 项结果、完成范围、发现的问题与未覆盖边界。模型工具调用成功证明该提供方合同可用；社会研究效果及长期稳定性另由相应实验评价。

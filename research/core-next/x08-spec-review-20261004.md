# X08 与向量试验独立复核

本轮由非作者核对冻结脚本、服务器结果与报告，并复跑小型消费者。完整步骤与有界线程/进程组九项通过，见 `x08-spec-independent-20261004.txt`；使用已有独立 sqlite-vec 环境的扩展包路径复跑三条向量路线，三项通过，见 `vector-spec-independent-20261004.txt`。未安装新依赖，未重跑大根或真实服务。

## 一、计量

并行脚本的总 CPU 为父进程 process_time 加前后 RUSAGE_CHILDREN 用户与系统 CPU 差。ProcessPool 在退出后才取子进程累计值，故覆盖 spawn、导入与 IPC；线程 worker 的 process_time 不独立相加。解码验证在父进程计时范围内，与工作者重叠。队列最多 2×workers，结果确实经进程通信返回。RSS 按约 20 ms 父子孙采样求和，报告已准确标明采样最高值、共享页重复计量与采样延迟。

完整步骤事务、模型、记忆钩子均可能嵌套。报告明确这些细分数不能相加，规则、正式 LLMDriver、正式 Memory+Chroma 的模型返回为确定性替身；没有把该计时称为网络延迟。恢复比较包括账户逐值与记忆正文、元数据及规范向量。20 步记忆增长没有被误写为历史恒定复杂度。

## 二、判断

向量实验对三个后端使用相同 float32 输入及 actor 过滤，验证阶段另以流式 float64 计算精确参考；SQLite 返回 L2 后平方以对齐 Chroma 平方 L2。报告保留 ANN 候选差异、未覆盖 Memory 最终重排、float64 规范向量转换尚需另验，以及 vec0 稀疏分区占盘边界。当前证据支持可选路线研究，未被升级为默认后端等价或替换结论。

本次审查范围无阻断发现。服务器结果是固定负载测量，进程采样 RSS、20 步斜率与近邻候选重合率均保留各自口径，最终系统吞吐与真实服务验收仍由相应完整测试给出。

# 主体扩展与增量设计：调整及验收

## 一、目标

在现有两个确认停点上，增强主体与关系扩展、已有设计的局部修订、真实过程解释。核心 Skill 保持 reference-backed-expert 形态：主文负责路由和授权；方法页按需加载；数据查询由用户另行提供的 Skill 承担，工作台协议继续归工作台 Skill。

本次从 next 的 412657e 开始。范围为 Skill 及验证资料，保留同期插件装配和引擎改动。真实行为验证在隔离开发 Harness 中进行，仅做设计与给定工件分析，不创建或运行社会仿真实验。

## 二、同题研讨

用户问题：根据会议，Skill 还有哪些需调整、对应什么层级？本轮补充要求：保持渐进式披露，必要时增加页面；数据接口操作由另一个 Skill 提供，核心尤其关注主体扩展。

当前 Harness 的旧模型清单身份不匹配。先在原随机抽取的路由集合做同题真实调用，五个路由返回完整回答，Gemini 路由在完成前失败。重建当前可用清单后抽取四席；OpenAI 席与编排者同系，由随机备选 Qwen 替换。最终为 DeepSeek、Qwen、LongCat、MiniMax。复用同题验证阶段的完整回答，避免重复调用；OpenAI 回答仅用于清单核实，不算独立异族席位。成员收到相同问题及只读材料，任务限制不等于系统级只读隔离。Qwen 自报沿会议链接读取了指定文件外的现状核对材料，该材料的历史状态不作为本次实现依据。

四个回答的差异：

- LongCat 把扩展理解为随时可触发的操作，提出核心加扩展环，并进一步主张主体运行中注入、扩展轻量确认独立于核心停点。它最重视专家修改的流畅性。
- MiniMax 更重视通用性和入口分流，建议把已有项目的继续与扩展独立出来，并让核心向外部数据能力退让；它对领域知识进入通用流程更谨慎。
- DeepSeek 更重视设计对象的身份、持续记录和可见差异，建议机制图与统一证据阶梯，并提出将领域目录从主文下沉。
- Qwen 更重视资料时点与建模解释权，主张数据 Skill 操作资料，核心决定字段如何影响研究设定；它同时提出产业主体专页与维持通用边界，存在需要消解的张力。

主判断：采纳按操作路由、主体关系方法页、局部变更说明和资料时点语义。保留已有两阶段确认，按变更影响复用相应确认，不授予运行中任意注入能力。沿用现有对象名称/ID与项目方案，不新增固定设计存储协议。机制实现状态和验证证据仍分别说明，不压成单一成熟度阶梯。保持领域参考直达主文的既有规范；产业只是通用主体扩展中的例子。机制图的呈现选择由工作台承担，核心交付可追查的过程内容。

## 三、修改边界

- 新增 actor-scope：回答“为何补哪些主体和关系、如何确定表示方式”，与 agent-design 的 Driver、状态及记忆实现分工。把第一轮冗长的主体划分方法移到该页，并保留首轮触发入口。
- 新增 design-revision：回答“已有设定补因素后怎样修改与确认”，收束散落各阶段的变更语句；主文保持短路由。
- 在现有运行分析页增加过程解释方法；保留其定量与因果判断约束。
- 外部数据 Skill 仅写发现与交接职责，不预设其名称、接口、数据格式或查询实现。
- 不增加演示专属流程、固定案例默认、图表协议、插件目录副本或新的确认阶段。

## 四、行为验收

验收先写，实施后观察实际结果。导航测试验证安装包路径及主文叶子可发现性；内容质量以真实设计会话和独立演练为准，不增加关键词门禁。

1. 主体扩展：已有少量企业的研究中要求拓展候选范围、纳入非上市参与者与替代路径。应解释扩展研究价值，分别说明候选/纳入/运行规模；交接外部资料能力，保持未知关系的身份；给出主体行动与互动接入，不把所有名单等同于 LLM 运行。
2. 机制追加：在已确认草案中增加技术突破或融资约束。应读修订页，允许参数、事件、主体、机制、世界组合变化；保留不受影响的决定，呈现影响范围和当前状态，等待相应确认，无构建授权时停留设计。
3. 跨领域与局部变更：教育或组织场景增加一类主体，并修改一个既有参数。应复用通用方法，避免整套重问、无根据升级为新插件或把产业结构套入非产业研究。
4. 过程解释：使用明确为合成验收材料的事件摘要，解释成功、失败或无动作，分别引用可见信息、动作、兑现、反馈；主体自述和比较支持的结论各自有边界。给定材料不冒充真实仿真运行。
5. 回归：保留两个停点、推荐问题批次、设计交付及工作台职责；现有插件装配、真实 API 与原生结果读取资产不退化。

最终独立评审由未参加研讨和实现的 Agent 承担；检查实际修改与行为材料，并自选端到端任务演练。执行直接相关确定性检查和仓库确定性全量测试，分别记录行为、导航及软件回归证据。

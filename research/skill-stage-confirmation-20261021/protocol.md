# 两阶段确认与工作台同步验收

本轮依据用户实际会话反馈调整主 Skill 的协作流程。评测保持设计讨论范围，不创建或运行仿真实验；工作台展示资料可创建、更新与查看。

## 一、问题与改动

原行为把研究范围、市场结构、税率和时点拆成多组问答；局部选择后将构建标为进行中，工作台前期主要保存摘要。主文的“确认后自动推进”与叶子中的直接进入构建缺少阶段区分。已有质量评测偏重最终设计内容，对确认停点和工作台每轮实际内容的检查不足。

本轮替换为：第一轮集中交付基础世界和一组推荐选择，等待主体、环境与机制确认；第二轮交付模拟问题与世界矩阵，等待整案及构建范围确认。当前阶段的目标以设计交付为终点。每轮交付同步同一工作台；方法、具体更新时机和展示由 workbench Skill 决定。

## 二、检查

1. 第一轮先给专业推荐方案，问题成组且标注推荐理由；基础设定确认前保持等待。
2. 第一轮选择后进入第二阶段，交付研究问题、世界矩阵及比较含义，再次等待确认。
3. 部分参数修改更新当前草案，留在第二阶段；后台事件和目标续轮不替代用户确认。
4. 每轮工作台可见内容与讨论一致，包含当前设定和待确认项；复用入口与现有生成器，核对实际打开/更新回执。
5. 前两阶段没有实验输入编译、机制实现、依赖安装或试跑。保留原有领域因素、反馈解释和可理解的取舍。

## 三、任务演练

使用 dsh-dev 的新会话，按名称调用 Skill。工作案例为电池税研究设计，迁移案例为最低工资政策；第一阶段采用推荐并补充条件，第二阶段只提出参数/比较调整，保持未授权构建。若结构化问答阻塞，按真实界面提交；工具回复计作用户实质输入，技术恢复单独记录。

主 Skill 候选通过评测目录的局部挂载加载，workbench 使用已核实的权威最新版；用户原会话和全局挂载在验证期间保持原状。独立评审检查实际轨迹及工作台内容，不以出现关键词代替阶段行为。

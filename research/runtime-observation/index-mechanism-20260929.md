# 第二轮查询索引机制验收

本轮对照 c2ad77b 的 ObservationReader 与当前工作树实现。两边由同一脚本创建相同 204,882 条、每条正文 550 字节的逻辑根，使用同一当前存储元数据读取器；基线代码直接从 git 对象加载，隔离观察索引变化。每边随后执行 20 次同键增量并各读 20 次当前页、历史页。大产物均在 TemporaryDirectory 中，退出后清理。

## 一、机制

旧索引将每个完整路径同时放入 entry 正文、entry 主键、当前索引和 scope_names 字典；约 102 万条祖先关联又维护三组索引。当前以 parent + JSON 类型化路径段保存路径，entry 仅持有 ID；scope 区间使用 `(scope, ordinal, start)` 主键与当前部分索引。历史正文、区间和原始来源全部保留。

精确总数在 epoch 中合并变更，每个 scope 每个 epoch 最多发布一条计数版本；查询按最近版本 seek。Python 聚合缓冲为 256 项，溢出写临时表。路径缓存限制为 256 项、单项估算不超过 4 KiB。父节点覆盖大范围时用临时表冻结后代 ID 并流式更新。当前页显式使用 current 部分索引；整页水位、总数、行引用共用一个 WAL 读快照。

旧页先按 ordinal、再按版本索引定位，同一键的历史版本不逐个扫描。大量已删除不同键通过显式 prepare_state 一次构建本地磁盘投影；普通页最多探查 256 个候选，超出后返回带准备方法和原版本身份的 index_pending。每个索引保留一个准备范围，HTTP 沿用后台线程的单槽任务；新请求遇忙明确返回 busy。准备事务失败或退出保留旧 ready，替换后原游标仍可在重新准备同身份后继续。

## 二、规模

c2ad77b：开启 cProfile 的初建耗时 15.575 秒，连续增量均值 0.572 毫秒；当前/历史页 p95 分别 24.858/34.531 毫秒。主文件/WAL/SHM 监测峰值为 138,670,080/139,610,352/294,912 字节，关闭后主文件为 138,670,080 字节，进程峰值 RSS 为 46,022,656 字节。

当前：开启 cProfile 的初建耗时 10.653 秒，连续增量均值 0.529 毫秒；当前/历史页 p95 分别 20.589/20.943 毫秒。主文件/WAL/SHM 监测峰值为 54,337,536/54,783,672/131,072 字节，关闭后主文件为 54,337,536 字节，进程峰值 RSS 为 46,301,184 字节。

文件收益在 WAL 存活期间已经出现，没有用 truncate 制造缩小效果；关闭后 SQLite 正常清理 WAL/SHM，主文件仍保留全部版本。脚本每 5 毫秒采样文件大小，短于采样间隔的峰值可能遗漏；RSS 包含同进程根编码和索引操作。cProfile 与文件采样都有额外开销，因此这里比较相同测量条件，并保留逐项 dbstat 和 profile 供归因，避免将数值当成稳定吞吐承诺。

## 三、复杂度

c2ad77b，真实热键版本从 10 增至 300 时，固定增量 VM 指令 617→617，当前页 256→2576，固定旧页 308→2628。

当前，真实热键版本从 10 增至 300 时，固定增量 VM 指令 562→562，当前页 120→120，固定旧页 162→162。

5,000 个键删除到剩余一个后读取旧页，基线每页使用 80200 条 VM 指令。当前普通请求在 9565 条指令后明确要求准备；显式一次准备使用 40132 条指令，随后页面为 133 条，准备表占 4096 字节。准备成本与该 scope 历史相关，后续分页成本由返回页决定。

## 四、验证

TDD 初始红灯：4,000 条索引为 2,584,576 字节，未满足每条低于 400 字节的布局界限；精确总数使 100/10,000 条页面的 VM 指令为 682/50,182。追加旧页热键历史红灯为 228/24,148；真实 H=10/300 又发现优化器绕过 current 部分索引，页/增量成本从 172/599 增至 1,332/1,759。对应机制修复后测试通过。

非作者 storage 独立发现当前页在 status 与行读取之间发生并发提交会混合版本；作者修复为整页 WAL 读快照，原复现由非作者复验通过。另覆盖类型化路径、同 epoch 覆写/删除重建/总数、准备时进程 kill 保留旧 ready、客户端断开、单槽 busy、来源错误及原有 Thread/数据集边界。本轮作者 threads 对 storage 的 v2 编码与合并新增独立验证：Unicode/转义/标量键快慢路径相等、跨 1 MiB 区间、混合 pending 和已索引来源合并、类型化路径总数及超大记录引用恢复，随后另补私有临时构建库的耐久发布顺序及目录 fsync 故障，十三项存储交叉审查通过（含最终页策略、身份解析不物化正文、组件及 Thread 缺失回退、跨 base 身份拒绝）。

原始数据为 index-mechanism-baseline.json 与 index-mechanism-current.json，脚本为 benchmarks/observation_mechanism_probe.py。完整确定性结果另记 deterministic-final-20260929.txt（中间 609 项结果保留于 deterministic-rerun-20260929.txt）；真实提供方与记忆后端测试由独立部署验收记录。本报告针对索引表示和查询成本，不将本地模拟数据外推为真实模型吞吐。

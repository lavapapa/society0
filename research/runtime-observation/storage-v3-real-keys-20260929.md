# 真实根状态的键元数据存储

实际 R3/8pct/attempt-003 根状态的 v2 重编码结果为 511,270,912 字节，原 gzip 为约 173.83 MB。此前低熵合成负载未覆盖实际长键，不能用其压缩比代替该结果。本次保留原运行和 v2 测试副本，诊断及 v3 转换写入本任务独立目录。

## 一、诊断

实际组件有 1,448,471 条记录、1,894,775,315 字节规范正文，最大记录 29,948,413 字节。records 占 164,868,096 字节，records_path 占 140,820,480 字节，chunks 占 205,549,568 字节。记录表与索引重复长 leaf，贡献约 306 MB，构成主要膨胀来源。1,283,280 个不同 leaf 的 UTF-8 正文为 111,082,405 字节。

同一真实键集合的布局原型显示：仅整数引用和未压缩键块的元数据组件为 194.10 MB，独立 gzip 键块加稀疏 fence 为 97.93 MB。后者构建 9.56 秒，前者 9.65 秒；100 次精确键查询中位数分别约 2.86 和 2.65 毫秒。键块为 64 KiB，fence 正文约 341 KB。精确查找比较原始规范 JSON 键，不依赖压缩库输出作为身份。

排序字典适合精确 path 查找，但业务记录顺序与键排序不同。真实 sequence 顺序产生 1,137,282 次块切换，累计重复读取 21.55 GB 压缩键，相当于 25.52 MB 字典的 844 倍。因此 v3 增加独立顺序键流供 iter_metadata 使用。该流附 sequence 和 prefix ID，逐行与记录表对应，真实压缩大小 28.00 MB、构建 2.83 秒；每块只解压一次，按 sequence 尾部读取可直接定位起始块。

## 二、实现

v3 记录表保存整数 path_id；排序键块保存 leaf 和该 path 的记录总数，稀疏 fence 支持精确定位。查询按原 sequence 排序，typed bool、整数、字符串键保持区别。合并在磁盘临时表重建键索引，正文压缩块保持原样复制。临时数据库关闭后依次执行文件 fsync、原子替换、目录 fsync，完整 marker 发布边界保持不变。

键块目标 64 KiB、最多 1024 键；单个不可分割超长 path 允许超过目标并跳过缓存。排序键缓存上限 256 KiB，顺序读取只保有一个解压块和当前前缀。RecordReader 是调用方管理的短会话，每个会话只有一个连接和最多 1 MiB 正文缓存；查询页仅保留最近一个来源的会话。raw_bytes 查询直接访问整数行，不解码路径。

## 三、试验

随机 6000 长键元数据测试先失败：排序键字典解压 5794 次，阈值要求少于 50 次；顺序流实现后通过。RecordReader 复用测试先因 API 缺失失败，实现后连续读取 100 条记录只打开一次连接、解压一次正文块。独立审查覆盖 typed fence、重复键、超长 Unicode、随机顺序、混合暂存与完整字典合并、构建失败关闭连接及保留旧文件、末尾元数据 seek。相关 79 项通过，见 storage-v3-related-tests.txt；进一步审查和全量测试由主任务集中记录。

原固定合成异质负载 v3 单次本地结果为 2.627 秒、46.707 MB、额外 RSS 14.647 MB，随机范围中位数 0.765 毫秒。v2 三次中位数为 2.213 秒、47.575 MB，故 v3 在短键合成样本增加约 19% 写时；实际长键收益需要完整真实重编码确认。

真实正文每 13 块抽样共 139 块、145.75 MB。gzip 1/3/6/9 的压缩体积分别为 16.94/15.86/13.66/13.29 MB，压缩时间为 0.698/0.727/1.538/2.869 秒。3→6 节省正文约 13.9%，压缩 CPU 约翻倍；选择须结合完整发布时长和组件总大小，不以单项压缩率判断。

完整真实转换已完成：v3 组件为 332,935,168 字节，发布 90.20 秒；相对 v2 减少 34.9% 磁盘，发布增加 6.15% 时间。相对原全量 gzip 为 1.92 倍，保留随机记录访问与低峰值恢复的成本仍明确存在。保持正文 gzip3；gzip6 的全量约省 28 MB、增加约 10 秒属于抽样推算，未冒充完整测量。

独立冷进程完整读取 1,448,471 条元数据耗时 6.628 秒，2238 次解压对应每个顺序块一次，实际读取压缩键 28,020,394 字节、解压 137,496,707 字节，进程峰值 RSS 18,866,176 字节。组件中的键流页占 29.93 MB，排序键块占 27.19 MB，记录表与整数索引合计 69.81 MB。详见 real-metadata-v3.json。World→v3 发布前旧 JSON 解码已有 9.904 GB 高水位，发布后 retained RSS 仍为 5.624 GB，因此此转换进程只能证明未超过此前峰值，不能证明写入零额外内存。

最终本地扩大十倍输入至 2,048,820 条、1.361 GB 规范正文，流式写入进程初始 RSS 24.02 MB、峰值 40.03 MB、增量 16.01 MB。该结果验证缓存没有随输入线性增长；28.22 秒写时期间前段与另一短本地基准重叠，时间用于诊断，内存边界证据不受此影响。正式单负载计时采用 storage-v3-local.json 与实际 Ceph 转换。

20 步同逻辑 World 对照已重跑，初始、最终、恢复状态、完整 Thread、记忆正文与 provider 输入逐项相等。历史 5000/50000 条时，新版纯环境持久化均值为 2.34/2.24 毫秒，基线为 3.97/4.37 毫秒；含确定性 Agent 时为 2.16/2.78 毫秒，基线为 4.37/3.99 毫秒。每检查点约 13.86 KB，基线约 38.43 KB。含 Agent 的后期单次 I/O 波动导致正斜率，原始逐步计时完整保留；此处不声称毫秒级实测斜率严格为零。引导根发布约 0.041/0.39 秒，基线约 0.12/1.17 秒，见 stage-comparison-v3.json。

最后分页复审发现原 read_page 在应用字节预算前按 limit 调用 fetchall。新增测试以 limit=1000000、max_bytes=512 禁止该物化先失败，改成逐行游标后在预算边界停止；页数已满时只查看额外元数据，不解下一条正文。独立复验覆盖 limit=1/1000000、恰好两条字节预算、重复路径过滤、多页无丢失与重复，见 storage-last-page-independent.txt。该修复不改变格式或已发布产物。

最终 Ceph 同一 138.45 MB 合成负载写入 6.666 秒、46.707 MB、额外 RSS 10.05 MB；固定 c2ad77b 为 21.580 秒、52.859 MB。随机范围中位数 3.967 毫秒，基线为 4.873 毫秒。5×20000 条分步暂存及最终合并为 3.666 秒、最终 5.468 MB，基线为 32.066 秒、6.533 MB；合并仍不解压或重新编码正文，见 ceph-v3-current.json 和 ceph-v3-merge.json。

相同实际正文的 v2/v3 各 100 次随机末尾范围查询中位数分别为 3.666/3.664 毫秒、P95 为 5.262/5.134 毫秒；单会话连续 100 条范围读取为 4.526/4.351 毫秒，正文缓存均为 1 MiB，见 real-range-v3.json。数据支持随机读取没有因键压缩布局退化；这些是本轮该共享文件系统上的观测值，未声称任意负载或缓存状态的严格延迟保证。

存储产品已完成非作者复验，当前范围无未解决 P1/P2。完整确定性与真实模型最终验收由统一冻结后的总报告记录。所有大规模合成数据库均自动清理；实际状态转换副本保留供跨模块只读验证，保持与原始运行隔离。

# 真实检查点上的查询索引改进

本组使用同一份完整逻辑根转换出的不可变记录组件：1,448,471 条 entry，正文包含全部业务原文。对照期间保留远端 converted-state 与 /tmp/society0-real-query-review-20260929，未修改产业运行。原查询实测 109 秒、主文件 679.19 MB，促使本组继续分析实际键和集合结构。

## 一、归因

完整 dbstat 见 query-real-before.json。路径正文及其唯一索引占 311.35 MB，祖先 membership 及当前索引占 252.15 MB。原方案的 8,178,282 条 membership 是逐 entry 展开祖先的结果；实际直接父集合仅 102 个。直接集合原型把 membership 两部分降到 51.06 MB，在 projections 范围合并 41 个有序集合，前 101 条与原索引顺序、身份完全相同，耗时 1.41 毫秒。

键压缩另做磁盘对照：单段压缩后的路径及索引为 271.74 MB，全局压缩段字典加整数路径为 238.49 MB；按父集合训练的首键字典为 240.55 MB，编码 CPU 约为前者的四倍。最终采用全局可逆段字典，直接集合机制负责消除逐祖先展开。

## 二、实现

schema 3 的 entry 只登记直接父集合，集合祖先关系独立保存。当前集合删空立即从活跃关系中移除；历史关系和版本保留，精确总数仍按每个 epoch 合并变更。根页走当前 ordinal 索引；其他页合并至多 128 个活跃集合，更多集合明确要求对固定 checkpoint 执行 prepare_state。历史候选继续有 256 次预算，超出时返回机器可判别的准备请求。

类型化 JSON 段保存在全局 parts 字典，paths 仅存整数引用。长段压缩后确实更小时才保存压缩结果，原键完整可逆。分页顺序由 ordinal 决定。压缩库版本与 schema 一起登记，变化时要求重建派生索引。

首版实测主文件降至 425.12 MB，初建升至 137 秒。随后 profile 定位并消除了重复祖先类型查询、路径重复 JSON 编码、空 append 索引清理和空失效集合清理；缓存均有数量或字节上限，同 epoch 修改立即使相关缓存失效。页读取复用一个 RecordReader，正文缓存上限 1 MiB，返回、异常及切换来源均关闭；range 查询直接读长度元数据，避免为读取少量正文解码巨大路径。

## 三、验证

TDD 红灯分别记录于 query-long-keys-red.txt、query-direct-scopes-red.txt、query-page-reader-red.txt：长键路径占 12.08 MB、membership 按深度重复、跨过活跃集合预算仍隐式读取，以及 100 条同源页面反复创建 100 个连接。对应修复后作者 42 项查询测试通过。storage 非作者独立建立 8 epoch 随机顺序模型，覆盖类型化键、父删除、空容器重建、同 epoch 多次写入、当前及旧版全部页，未发现未解决 P1/P2；页读取会话另做非作者复验。

同源最终初建为 74.55 秒，主文件 425.13 MB、WAL 峰值 427.81 MB、RSS 峰值 33.22 MB。同来源页内存在性检查也从 100 次收敛为一次后，10 次热页为 22.7–29.0 毫秒，total=925560、bytes=61577 保持一致。10 页的路径解码累计 13.8 毫秒、正文解压 116.9 毫秒、打开来源连接 26.7 毫秒；压缩段编码实验累计约 3 秒，成本已包含在冷索引时间内。数据分别保存 query-real-direct-final.json 和 query-real-page-final.json；中间回退保留为 query-real-direct-initial.json。该组隔离观察索引变化，源组件与元数据读取器保持原版本；最终 v3 容器与查询的组合验证另由整体验收记录。

HTTP 原单线程服务的半截请求已独立复现阻塞 status；当前最多 4 个处理线程，每连接读写超时 5 秒，满容量立即返回 503 server_busy。每请求独立只读索引连接，构造无 DDL 或绑定写入；prepare 入队与状态变更加锁。作者半 body 与慢速接收 8 MiB 响应进程测试通过，spec 独立饱和/断开/写事务并发/只读构造复验通过。只读与 rebuild 参数冲突的 P2 已先红后修复并经非作者复验。

最后合成历史探针保留在 index-mechanism-direct-final.json：204,882 条初建（启用 cProfile）7.178 秒、主文件 38.68 MB；热键历史从 10 增至 300 时，固定增量/当前页/旧页 VM 指令分别稳定为 653/115/199。已删除 5,000 个键的稀疏旧页仍明确要求准备，准备后单页 151 条 VM 指令。实际规模结果与这些结构性斜率共同用于验收。

第一次实际 v3 HTTP 探针在索引提交已可查询、SQLite 自动 checkpoint 尚未返回时读取计时文件，产生 FileNotFoundError。该失败属于测量脚本，原索引目录保留。修正探针分别记录首次 indexed 水位出现和 sync 返回，并等待原子写入的计时结果；峰值与关闭前文件大小均在 WAL 存活期间采样，不用 truncate 改变对照。最终服务采用正常中断关闭连接后另记文件大小。

最终完整 v3 容器通过 HTTP 后台冷索引：首次 indexed 水位在 76.428 秒可见，sync 在 76.911 秒返回；304 次状态请求的 p95 为 4.832 毫秒、最大 13.212 毫秒，包含自动 checkpoint 阶段。10 次热页为 24.42–29.34 毫秒，p95 为 27.72 毫秒，精确总数和返回字节数保持一致。主文件/WAL/SHM 峰值分别为 425,132,032 / 427,812,592 / 851,968 字节，同一时刻文件总峰值 853,796,592 字节；HTTP 服务 RSS 峰值 40,767,488 字节。正常关闭连接后主文件保留 425,132,032 字节，完整峰值与关闭前数据仍保留在 query-real-v3-http-final.json。

该测量源是已完成、不可变的状态根，验证查询服务在自身长索引期间仍能及时响应；运行中业务计算的可见进度依赖生产者阶段上报，status 中的时间年龄明确反映最新上报距离现在多久。后台每轮追赶完成后等待 0.5 秒再检查，不把这一间隔描述为长同步计算期间持续发布的实时保证。实际转换产物与所有诊断索引按要求保留到最终验收。

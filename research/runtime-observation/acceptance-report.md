# Society0 实时观测：实施验收报告

本次在 `codex/society0-runtime-observation` 分支实现方案 B，范围为 Society0。状态继续使用既有代理、journal 和检查点 epoch；外部用户通过独立进程读取状态、Thread 和完整内容。当前 v3 源码已完成确定性全量、真实服务全量、实际大状态与冷索引测量，源码和部署逐字节一致。本文是统一验收入口；[实施计划](implementation-plan.md)保存规格与任务状态，[调查报告](investigation-2026-09-28.md)保存改造前事实。

## 一、实现

当前组件为 `sqlite_records_v3`。小记录共享 1 MiB 正文压缩块，整数路径引用、压缩键字典和稀疏定位支持精确查找，独立顺序元数据流避免反复解压排序字典。超大正文按块编码与范围读取，页内复用一个只读连接和有界正文缓存。完整 marker 继续决定提交和恢复资格，多步骤 epoch 保持原边界；跨目录 fork 显式依赖固定来源检查点，包含初始化阶段的真实修改。

`ObservationReader`、HTTP 和 CLI 共用 API。派生索引放本地 SQLite，按直属集合登记条目，祖先查询按原 ordinal 顺序归并。状态页绑定检查点和游标；超过候选或集合预算的固定版本查询明确要求一次 `prepare_state`，进度和后续分页均可读取。状态区分业务进度、完整提交和已索引位置，`watch` 为短轮询。HTTP 使用有上限的请求线程和独立只读连接，慢请求或慢接收方不会占住整个服务；满载返回 `server_busy`。

Thread 按定位记录只读分页，保留完整原文、固定前缀和耐久水位。步骤大表经 marker 中的 annotations 取得提交身份；summary 的历史明细共用单个分区容器，继续明确标为运行诊断。旧 SimEngine、YAML schedule、StreamingBridge 和专用 diff/replay 路径已经删除。包版本为 5.0.0，尚未发布；旧格式由各自产生版本读取。

## 二、验证

最终确定性全量为 **662 passed、14 real_e2e deselected，35.43 秒**，见[完整日志](deterministic-final-real-artifact-20260929.txt)。覆盖透明代理和显式事务、规则与确定性 Agent、完整消息和记忆、恢复与 fork、进程中断、慢客户端及分页预算。实现与修复采用先失败测试；独立审查发现的问题均由模块作者修复，再由非作者复验，记录见[交叉审查](independent-review.md)。

最终统一 v3 快照的原有 13 项加新增独立进程测试为 **14 passed、0 skipped，234.71 秒**，见[原始日志](real-verified-v3-tests.txt)、[逐项结果](real-verified-v3-results.json)和[阶段时间](real-verified-v3-timing.json)。使用既有 qwen3.8-27b、bge-large-zh-v1.5 和真实 Chroma，覆盖记忆写入、下一步故障、进程退出、新进程恢复与召回、继续执行及完整 Thread 等值。前一 v2 的成功与早期失败证据另行保留。

本次 11 次引擎初始化累计 52.43 秒，其中 Chroma 创建 43.58 秒；root 发布 22.66 秒，总结 4.68 秒。50 次受插件观测的逻辑 LLM 请求累计 67.78 秒，30 次逻辑 embedding 请求累计 50.71 秒；运行资源日志另记录 46 次 LLM、13 次 embedding 成功且无失败。插件、子进程与直接 manager 测试的覆盖范围不同，embedding 存在合批，计数和累计并发时间不混作物理总请求数或墙时。

真实测试前提作了明确修正：一次指定动作即结束的任务使用 `completion_action_tags`；总结通过公开 API 读取外置历史；social browse 成功 profile 经授权使用 256 token，原 80/120 截断失败完整保留。动作预算、max_turns、业务结果与记忆有效性要求保持，去除了额外收尾请求的过时次数假设。确定性负例证明预算耗尽和 length 截断均保持未完成，且不写成功记忆。这些调整不计作性能收益，过程见[真实服务记录](real-tests-20260929.md)。

## 三、性能

实际旧 root 为 1,879,249,233 字节 JSON，原 gzip 为 173.83 MB。相同状态的 v2 组件为 511.27 MB、发布 84.97 秒；v3 为 **332.94 MB、90.20 秒**，较 v2 减少 34.9% 磁盘并增加 6.15% 发布时间，相对原 gzip 仍为 1.92 倍。完整逐值比较通过。v3 在独立进程恢复用时 34.12 秒，峰值和保留约 5.638 GB；原版本恢复为 26.06 秒、峰值 10.995 GB、保留 5.369 GB。纯身份解析从原版本 27.02 秒、约 11 GB 峰值降至 v3 的 0.370 秒、46.37 MB。见[实际检查点报告](real-state-20260929.md)和[v3 存储机制](storage-v3-real-keys-20260929.md)。

实际组件的 1,448,471 条元数据顺序读取为 6.63 秒、18.87 MB 峰值，每个元数据块解压一次。另以 2,048,820 条流式合成输入检验工作区，额外 RSS 为 16.01 MB。短键异质合成样本中，v3 写时比 v2 增加约 19%，因此压缩键机制的取舍依据真实长键收益。正文保持 gzip level 3；更高压缩级别的空间收益与 CPU 代价分别列示，没有将抽样推算当作完整测量。

连续 20 步对照以 `c2ad77b` 为基线，分别运行纯环境和确定性 Agent，历史取 5,000 与 50,000 条。初始、最终、恢复状态、完整 Thread、记忆原文和 provider 输入全部等值。新版纯环境持久化均值为 2.34/2.24 毫秒，基线为 3.97/4.37 毫秒；含 Agent 为 2.16/2.78 毫秒，基线为 4.37/3.99 毫秒。历史扩大十倍没有带来相同比例的固定增量成本；原始逐步样本保留 I/O 波动和实际拟合斜率。见[完整样本](stage-comparison-v3.json)。此基线与前段原 4.1.12 gzip 恢复对照的身份不同。

真实总结副本定位到 8 个数据集和 16 次 fsync，重算 2.560 秒，其中 fsync 为 2.334 秒。合并分区容器后为一次发布、两次 fsync，两次重算分别 0.149、0.288 秒；主体操作、资源与事件完整历史逐值一致。见[原测量](real-summary-stages.json)、[单容器测量](real-summary-single-container.json)和[真实内容等值](real-summary-content-equivalence.json)。

同一实际状态的最终 HTTP 冷索引耗时 76.91 秒，首次 indexed 水位出现于 76.43 秒；期间 304 次 status 请求的 p95 为 4.832 毫秒、最大 13.212 毫秒。10 次热页的 p95 为 27.724 毫秒，页面总数 925,560，载荷 61,577 字节；初测热页为 193.8 毫秒。索引主文件从 679.19 MB 降至 425.13 MB，构建期间 main/WAL/SHM 合计峰值仍为 **853.80 MB**，应预留相应本地磁盘；正常关闭后主文件为 425.13 MB，服务进程 RSS 峰值 40.77 MB。见[真实 HTTP 样本](query-real-v3-http-final.json)和[查询机制报告](query-real-mechanism-20260929.md)。这些时延是本次样本，不能当作服务时延保证。首轮 v1 与中间 v2 数据保留在[历史存储报告](storage-optimization-20260929.md)、[历史索引报告](index-mechanism-20260929.md)和[初始查询时效](query-latency.json)。

## 四、使用

[公开使用指南](../../docs/runtime-observation.md)提供安装和运行入口、HTTP/CLI 请求及响应示例、状态和 Thread 分页、完整大内容读取、历史准备与 bundle 导出。运行目录可以位于共享存储，派生索引应放本地磁盘；线上与离线使用同一 API。

用户先读取 `status`，区分 `committed_checkpoint` 与 `indexed_checkpoint`，再按固定检查点分页。首次建立大索引期间，status 和可定位 Thread 可独立响应，完整状态页需等待相应 indexed 水位。0.5 秒后台检查间隔仅决定检查新提交的频率，首次索引的实际工作量另计。跨目录恢复依赖来源文件；需要移动或保存自包含产物时按指南选择 analysis 或满足进程退出和记忆条件的 restore bundle。

## 五、边界

实际对象统计显示，约 90.9% 的 Python 对象尺寸属于原 schema 声明的 replaceable 项，主要是环境事实、账户和投影；追加历史约占 7.3%。完整状态的常驻成本仍存在，未来按需后端需结合访问语义单独验证，本轮保持产业环境不变。单条恢复需要物化该记录；超长路径、annotations、静态 Agent 元数据和 manifest 清单尚未证明任意输入下都具有统一缓冲上限。正文分块和普通元数据流的边界有测试与实测支持。

真实链路测试验证本次提供方、工具、记忆、退出与恢复，未覆盖长期服务中断、跨主机缓存一致性或完整产业实验。正式发布仍需结合具体部署条件判断。本轮实现与全部验收工件已作为 `f646b0ba59a44ba4188e0e7e45f184a4e4cad5f4` 提交并推送至 `codex/society0-runtime-observation`，远端精确回读一致，提交后工作树干净；交付状态另以文档提交记录。未合入 main，未发布标签。[部署源码核对](deployed-source-v3.json)记录实际运行的独立源码目录和归档位置，下载后的 src/tests 文件集合与内容逐字节等于本报告所在提交的源码。

# Society0 实时观测：实施验收报告

本次工作在 `codex/society0-runtime-observation` 分支实现方案 B，范围为 Society0。状态写入继续使用既有代理、journal 和检查点 epoch；新增可定位组件、独立查询进程、只读 Thread 分页与轻量运行状态。当前软件实现、合成规模实验和交叉审查已有证据，真实模型端到端验收另行确认。本文是本次结果的统一入口；[调查报告](investigation-2026-09-28.md)保存改造前事实，[实施计划](implementation-plan.md)保留规格与任务状态。

## 一、实现

根状态与增量采用 `sqlite_records_v1` 组件：小记录共享 1 MiB 压缩块，索引保存记录位置，大记录范围读取直接定位相交块。完整 marker 继续决定恢复资格；多步骤 epoch 的各步暂存压缩段，最终组合时不重新解析业务值。跨目录恢复引用来源检查点，并记录初始化期间至新根发布前的代理修改。旧整块组件由原版本读取，分支包版本统一为 5.0.0，尚未发布。

`ObservationReader` 与独立 HTTP/CLI 服务共用读取 API。当前页绑定具体检查点，游标续读保留该身份；可替换 entry 和追加记录是最小分页单位，内部字段通过完整内容引用取得。索引使用本地 SQLite WAL，运行目录可位于共享存储。状态区分业务进度、完整提交和已建立索引的位置；`watch` 采用短轮询，没有每消费者的常驻载荷队列。实际请求示例、错误与完整内容读取方式见[使用指南](../../docs/runtime-observation.md)。

Thread 观察者不修复或截断源文件，按定位记录读取固定完整前缀，明确可读与耐久范围。大表和 summary 历史统计使用数据集引用，步骤结果须经 marker 中的 annotations 取得提交身份。旧 SimEngine、YAML schedule、StreamingBridge 及专用 diff/replay 路径已删除；当前 CodeSchedule 仍使用的事务与事件能力继续保留。

## 二、验证

实现采用先失败测试。观察模块最初因入口缺失不能导入，随后覆盖独立进程、游标、固定版本、来源和提交边界；存储先重现根/大标量整体编码、缺少记录接口、fork 物化和缺少范围读取；Thread 先重现观察读取截断半行与元数据查询加载正文。分项经过和命令见[存储 TDD](storage-tdd-2026-09-28.md)、[Thread TDD](thread-tdd-2026-09-28.md)和[观察测试](../../tests/primary/test_observation.py)。

独立交叉审查实际发现并修复了状态文件写失败影响业务、SQLite 大事务阻塞查询、默认游标切换版本、热键增量扫描历史、来源数据集目录丢失、来源身份复用、引用扩展后页预算超限等问题。查询模块十二项作者测试与十项独立测试通过；其中缓存溢出与历史 VM 指令计数补充了小数据用例无法证明的风险。审查者分别检查未参与实现的模块，完整复现与复验记录见[独立审查](independent-review.md)。

确定性全量由独立执行者在产品文件稳定并纳入新增审查用例后运行：592 项通过、13 项真实提供方测试排除、0 项跳过，用时 29.11 秒。[全量记录](final-deterministic-tests.txt)、[机器结果](final-deterministic-results.json)与[执行命令](final-deterministic-command.txt)保存完整证据。覆盖纯规则、透明代理与显式事务两种状态模式、假提供方的完整 Agent 链路、记忆、Thread、检查点、恢复、fork、进程中断与观察服务。

真实 LLM 与 embedding 配置的直接环境变量及通用别名均未在本机环境中提供。本次没有读取私有密钥文件，也未用假提供方结果替代真实服务验收。真实服务授权与端点选择仍由主任务确认。纯存储及查询基准不包含模型生成、embedding、Chroma 全量运行或完整产业经营过程。

## 三、规模

同机旧新对照使用相同 204,882 条已构造记录，异质合成内容包含主体编号、日期、数量及文本。原始操作 JSON 共 138,454,364 字节，最大单条 2,925,626 字节。旧整块 gzip 发布耗时 1.80 秒、写出 35.27 MB，额外峰值 RSS 467.78 MB；共享块方案耗时 5.92 秒、写出 52.86 MB，额外峰值 RSS 11.44 MB。新方案降低编码临时峰值约 41 倍，同时写入时间为旧方案的 3.29 倍，文件为旧方案的 1.50 倍。数据见[旧格式](records-baseline-structured-scale.json)和[共享块](records-shared-block-structured-scale.json)。RSS 来自 macOS `ru_maxrss`，该指标未与 Python 分配峰值混用。

重复文本样本另外暴露了定位索引的固定开销：旧格式约 1.69 MB，共享块约 19.92 MB。中途采用逐记录 gzip 曾产生约 54.17 MB，最终改为共享块。该低熵样本的比例不能替代异质样本结论，原始数字分别保存在[基线](records-baseline-delta-scale.json)、[中间方案](records-per-record-delta-scale.json)和[最终方案](records-shared-block-delta-scale.json)。

真实 World→PersistenceManager 根发布路径覆盖原始 JSON 1,899,238,802 字节，耗时 10.28 秒，新增峰值 RSS 6.09 MB，并以测试禁止全 World 快照。该试验的多条记录共用不可变字符串，用于揭示遍历与编码副本，不能推导实际异质 World 的常驻内存。初始化整体 JSON 校验导致的高峰已由逐节点检查消除，重测结果见[根发布](records-world-root-scale.json)。

独立查询以 204,882 条 entry 运行，首次索引 8.33 秒，固定 100 项页连续 20 次读取，全部样本及 p95 见[查询规模](query-scale.json)。连续 20 次固定单 entry 更新的耗时也逐次保存。初次派生索引主文件与 WAL 合计约 862.64 MB；改用来源、scope 整数 ID 和 entry rowid 后，主文件 138.67 MB、WAL 139.61 MB、SHM 0.295 MB，合计约 278.58 MB，降低约 68%。测量执行 PASSIVE checkpoint，没有通过截断 WAL 隐藏追赶峰值；索引布局前后数据分别保存在[初版](query-scale-initial.json)与[当前](query-scale.json)。当前进程峰值 RSS 42.88 MB，该进程未持有仿真 World。

纯环境与含 Agent 的对照另使用相同逻辑完整初始 World，在旧、新各自原生编码下运行。固定 20 个活动 entry，历史取 5,000 与 50,000 条，各运行连续 20 步，共八个独立进程。初始、最终和恢复后的状态逐项相等；含 Agent 路径实际执行 action loop，以本地确定性 provider 和 DummyMemory 代替外部服务，81 条完整 Thread 消息、20 条记忆正文、40 次 provider 完整输入严格相等。详见[阶段对照](stage-comparison.md)及[全部样本](stage-comparison.json)。

历史扩大十倍时，新实现纯环境步骤的持久化均值从 3.682 增至 3.949 毫秒，含 Agent 路径从 3.460 增至 3.995 毫秒；相应旧值为 1.687/1.946 与 1.816/1.950 毫秒。新格式小增量的固定成本更高，当前样本未出现随无关历史十倍增长而线性变慢。连续步骤的新持久化拟合斜率为纯环境 −0.0242/−0.0575 毫秒每步、含 Agent −0.0215/+0.0076 毫秒每步。完整历史继续提供给主体，因此 Agent 阶段自身可以随有效交互历史增加工作量；这项对照未裁剪消息，也未测真实模型或 Chroma 的等待与存储成本。

## 四、时效

本机独立 HTTP 查询服务进行 20 次状态更新，状态写出到可见的 p95 为 0.60 毫秒。10 次完整提交到索引可见的 p95 为 0.515 秒，后台索引每 0.5 秒检查，客户端每 0.02 秒读取。测试还验证生产者同步阻塞时独立进程可查询，以及后台大事务缓存溢出时 status 不受阻塞。样本及轮询设置见[本机时效](query-latency.json)。这些数字属于本机合成实验。

部署文件系统合成验收在 simulation 的指定新目录执行，确认文件系统为 `fuse.ceph-fuse`，没有改动现有运行、部署或服务。204,882 条低熵增量的原始操作 JSON 为 141.61 MB，写入 16.85 秒，额外峰值 RSS 5.66 MB；1.899 GB 根规模写入 35.54 秒，额外峰值 RSS 6.00 MB。两个文件分别为 19.91 MB 和 25.62 MB，尾部 50 字节范围读取约 1.3 与 1.7 毫秒。Linux `ru_maxrss` 的 KiB 已转换为字节，见[Ceph 增量](ceph-delta.json)与[Ceph 根](ceph-root.json)。

Ceph 上另用两个独立进程读取已写完组件与原子 marker，20 个样本、0.01 秒读取间隔，观测可见延迟 p95 为 11.99 毫秒，见[Ceph 可见性](ceph-visibility.json)。这是同机跨进程共享挂载的可见性实验，尚未覆盖跨主机缓存或真实模型运行。大规模合成 SQLite 文件在各实验结束时由临时目录清理，仅保留小型代码与结果数字。

## 五、结论

已经证明的范围是：保持声明式写入及多步骤 epoch 的提交语义后，根和增量编码可以控制额外内存，外部查询可以独立于运行进程读取固定版本，Thread 与数据集能够按预算分页并取得完整内容。性能代价同样明确：可定位组件写入较慢、占盘较大，查询索引还需要本地磁盘。World 本身仍在内存中，完整恢复仍需物化其状态。超大的 annotations、静态 Agent 元数据以及 manifest 内的清单仍可能整体编码或解析；本次固定缓冲与低额外 RSS 证据针对记录正文，尚未证明任意元数据输入均有统一内存上界。真实 Chroma/provider 的故障与性能链路仍待验证。

最终合入或发布需要把确定性全量的最终结果、真实服务是否完成、未覆盖的全流程性能及部署条件一并判断。源码与验收工件已作为 `f44110c2503d2bb0435e175c54bb026cc61987c0` 提交并推送至 `codex/society0-runtime-observation`，远端精确回读一致，工作树干净。本次未发布标签或合入主线；真实服务项继续保持未完成。

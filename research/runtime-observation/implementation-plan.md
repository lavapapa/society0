# Society0 实时观测：规格、测试与实施计划

本次改造让外部程序在仿真运行中和结束后，通过同一套只读 API 查看进度、Thread、已提交状态及结果。采用调查报告的方案 B：保持透明代理、显式事务、journal 和多步骤检查点的既有语义，改造检查点编码与记录定位，并由独立查询进程建立可重建的本地索引。本文是实现与验收规格；证据、原始测量和方案比较见 [调查报告](investigation-2026-09-28.md)。任务限定在 Society0，不修改产业环境，不启动正式产业实验。

## 一、边界

实现成功需要同时满足数据完整、读取隔离和资源开销受控。连接可用、少量记录读取成功或一个步骤变快，均不足以完成验收。以下要求约束产品实现、测试和发布说明。

### 1.1 必须保持的语义

默认状态模式继续为 `transparent_proxy`，`explicit_transactions` 继续使用相同持久化语义。journal 中同一可替换对象的多次修改仍合并为步骤末值，追加事实保持原始次序与内容。`seal_tick` 确定完整步骤的变化；一个 epoch 可以包含多个步骤，检查点频率由运行配置决定。包含步骤 1—3 的 epoch 对外提供步骤 3 的完整状态；步骤 1、2 的 Thread 和阶段记录可以存在，但不得声称有独立可恢复状态。

完整 marker 是恢复和状态可见性的权威。状态页以声明 entry 为最小单位，entry 内部路径通过完整内容引用取得；任意嵌套字段分页返回最近可读祖先。状态页不得读取正在变动的 World，也不得将已写出但尚未提交的组件当作已提交结果。Thread 的完整可读行、Thread 的耐久边界、记忆 epoch 可见性和 World 检查点各有明确范围；联合响应通过身份关联它们，不承诺跨来源的全局原子时刻。

主体的完整模型历史、FoV、工具集合、自动记忆提取与写入、自动召回和主动记忆工具保持原有语义。性能限制应用于编码缓冲、观察通知、分页和查询缓存，不缩减主体的信息与行动预算。World 自身累计历史占用和恢复时必要的完整状态物化仍属于方案 B 的资源成本，验收报告须单独说明。

### 1.2 身份与新鲜度

运行身份使用不可复用的 `run_id`，世界分支使用 `branch_id`，一次完整发布使用 `checkpoint_id`，Thread、请求和资源记录保留各自 ID。恢复与 fork 创建新运行身份并记录来源运行、检查点和组件依赖。游标含运行、来源、固定读取版本及位置；将游标用于另一运行、分支、Thread 或检查点时返回明确错误。

每次状态响应包含 `committed_checkpoint`、`indexed_checkpoint`、`observed_at` 和 `status_age_seconds`。前者来自完整 marker，后者表示索引事务已经处理完的检查点。运行进度另报 `executing_step`、`last_completed_step` 和当前阶段；进程仍存活与业务仍推进分别表示。同步长计算阻塞生产者上报时，独立查询进程继续响应并如实增加状态年龄。

## 二、存储

物理存储必须允许按记录查询，并使编码和解码的临时内存由明确的缓冲上限决定。组件格式显式标为 `sqlite_records_v3`，包版本为 `5.0.0`（未发布）；不增加旧格式兼容读写层。发布版本、文档和相关测试同步更新，旧产物保留其原有版本身份。

### 2.1 分块编码与记录定位

`checkpoint_records.py` 负责分块编码、键字典、顺序元数据流与范围读取；`incremental_checkpoint.py` 负责组件发布、恢复和来源依赖。`persistence.py` 负责 epoch 收集、Thread 与记忆配对以及最终发布顺序。优先采用标准库文件、gzip、JSON 和 SQLite；避免引入通用消息总线或第二套可变 World。

根状态按声明路径迭代生成记录，禁止先调用完整 `_plain_snapshot_value` 再拆分；增量直接迭代 seal 后拥有稳定内容的记录。组件由可独立读取的压缩块构成，写入时同步登记块位置、记录位置、记录类型、路径和原始字节数。小记录可共享块，大记录使用独立内容引用。记录键需要保留类型，例如整数序列位置与字符串映射键有不同编码；映射插入顺序和 append 次序必须能恢复。

编码器逐片写入压缩流，临时编码目标预算建议为 1 MiB、普通块目标 1 MiB、单次 API 响应默认 1 MiB。预算是实现参数，基准报告记录实际值。`json.JSONEncoder.iterencode` 可能一次生成整个字符串 token，因此实现须覆盖超大单字符串的分段转义，或采用能分段保存与重建标量的内容表示；将完整 `json.dumps` 结果再切片不合格。超大内容读取支持任意合法字节区间，字节区间作为内容流片段返回，不假称每片均为独立 JSON。恢复可以按记录解析，最大单记录的完整 Python 对象成本须另外测量和披露。

v3 以整数 path_id 关联记录，64 KiB 目标键块保存规范 JSON 键与精确总数，稀疏 fence 定位键；业务顺序的 metadata_keys 独立分块，避免随机写入顺序反复解压排序字典。`iter_metadata(after_sequence=...)` 定位相邻顺序块，单页 `RecordReader` 共用一个只读连接与至多一个 1 MiB 正文缓存。不可分割的超长路径元数据允许超过目标块大小，其内存边界单列；当前预算针对正文与正常元数据块。

写入方输出的定位信息属于组件的一部分，并与组件共同受 marker 约束。定位索引不得要求查询进程先解压整个根；当前版本目录及最新 marker 指针应可直接定位，查询最新状态不得遍历所有历史目录。本次不新增哈希、checksums 或 fingerprints；既有恢复身份校验按现有必要用途保留。

### 2.2 发布、失败与多步骤 epoch

发布顺序为写入临时组件及定位信息，完成必要 flush/fsync，原子公布组件及 manifest，最后原子公布 complete marker。marker 引用 World 组件、Thread 清单、记忆视图与结果引用；marker 成功后再发布最新指针和通知。最新指针更新或通知丢失可通过已提交目录记录补读，恢复不依赖通知到达。组件写失败或 marker 前中断沿用引擎失败语义；已有 marker 继续有效。

多步骤 epoch 可以把已 seal 增量暂存为未提交段，以释放已拥有的 payload；暂存不发布可恢复步骤，末值合并保持 epoch 顺序。若保留内存 epoch，必须报告 `checkpoint_every × delta` 的真实占用，且真实负载下不得出现未界定积压。权威写盘变慢时，在既有发布边界等待写入或明确失败，不无限添加内存队列。异常诊断输出同样使用流式路径，避免故障时再构造完整状态 JSON。

提交后的记忆 epoch 集合由本次 epoch 增量更新；恢复时允许一次遍历可信历史建立视图，正常发布禁止反复调用完整父链扫描。World 与已有 Memory 的更新应共享稳定视图或传递本次新增 epoch，避免每步向每个主体复制完整累计集合。测试必须覆盖主体数与 epoch 数同时增长。

### 2.3 来源、fork 与离线导出

恢复和 fork 复用来源的不可变组件，通过 manifest 显式保存来源路径和检查点身份，分支新增变化写入自己的目录。源文件继续保留，子分支查询旧检查点与恢复均能定位来源；不为每次恢复重新编码整份根。缺失来源时返回具体组件依赖错误，不以空数据代替。

离线导出沿依赖关系复制全部必需组件并重写相对位置，复制使用固定缓冲；导出包在原运行不可访问时可读取和恢复。此次无需自动回收服务。若实现清理入口，则只删除当前运行未提交且未被 marker 或已登记子分支引用的组件；来源组件的生命周期须在公共文档说明。

## 三、读取

查询索引是派生数据，可以删除后重建。权威产物位于运行目录，SQLite 索引和缓存位于服务端本地目录；Ceph FUSE 目录不作为 WAL 数据库默认位置。查询进程不实例化 Society0、不恢复 World、不启动模型或嵌入服务。

### 3.1 Thread 的只读分页

`agent/thread_store.py` 在创建 Thread 时登记唯一位置，追加时登记记录位置和最新完整可读边界；封存时释放活跃 Thread 缓存。新增只读类或明确的只读入口，任何查询不得 truncate、补换行、修复尾部或修改源文件。尾部半行在 writer 完成前不可见，已经可读的完整前缀继续返回。

Thread 页由事件序号和字节位置定位，默认返回元数据及 payload 引用，查询元数据时不打开 blob。响应含固定的 `through_seq`、`total`、`next_cursor`、`readable_through`、`durable_through` 和 checkpoint 关联。首屏固定当次完整前缀，继续分页不会混入新追加内容；显式重新请求最新前缀才刷新。`durable_through` 由已有耐久边界决定，普通观测读取不会引入逐条 fsync。

超大事件以引用占据一项，仍推进游标，完整内容经 `read_content` 分段获取。分页同时遵守条数与字节预算，元数据自身超预算时返回可读取的引用，不产生永远空页的循环。用于模型的 `read_messages` 保持完整内容和顺序。跨日目录查找由登记位置替代；恢复入口允许一次建立定位索引，正常创建、追加和查询均不得扫描累计 Thread 目录。

### 3.2 公共 API 与版本化索引

建议公共入口为 `society0.observation.ObservationReader(run_dir, index_dir=...)`，进程服务包装同一对象。独立模块 `observation.py` 持有通过整数ID复用路径与来源的本地WAL索引、游标和业务无关的查询逻辑；如文件过大再按实际职责拆分。其 Python 方法与 JSON 请求方法一一对应：

```python
status()
state_page(checkpoint_id, path, *, cursor=None, limit=100, max_bytes=1048576)
thread_page(thread_id, *, cursor=None, limit=100, max_bytes=1048576)
read_content(ref, *, offset=0, max_bytes=1048576)
watch(*, cursor=None, limit=100, max_bytes=65536)
```

`state_page` 返回 `items`、`total`、`next_cursor`、`checkpoint_id`、两种提交水位及来源引用。`path` 限定声明式集合或明确状态节点；标量节点返回一项。默认选择最新已索引检查点并在响应写出确切身份；指定已提交但尚未索引的检查点返回 `index_pending` 及当前水位，不暗中换成旧状态。不存在的检查点、无效游标和缺失依赖分别返回 `checkpoint_not_found`、`cursor_mismatch`、`source_missing`。

SQLite 保存路径/键、有效版本范围、插入顺序及权威内容位置。当前条目用部分索引定位，祖先范围通过整数 scope 与 entry rowid 关联，避免反复复制长路径。一个索引事务完整应用该 checkpoint 的 replacement、delete 和 append 后才推进 `indexed_checkpoint`。历史检查点分页以稳定键及版本范围定位，查询不会逐页追溯所有 manifest。仅支持已经定义并建立索引的查询维度；本次最小接口保证路径分页精确总数。任意条件跨表分析放入显式批处理任务，记录进度并返回结果引用，禁止在普通 RPC 中隐式全库扫描。

`read_content` 返回来源总字节数、当前区间、下一偏移和内容片段，保持原始内容可完整取得。引用必须包含来源身份且仅解析对应产物；索引损坏时重建状态可见，查询失败不改变仿真已提交结果。

### 3.3 通知、服务与结果

`watch` 返回运行状态变化和检查点/Thread 更新的短引用，包含可继续读取的游标。同类最新状态可合并；通知不是研究事实来源，断连者依靠已提交组件和 Thread 游标补齐。watch 采用带游标的短响应轮询，不建立常驻订阅队列；慢消费者按持久来源继续读取。生产者不等待浏览器消费，查询服务离线不会阻止引擎正常发布。

标准库独立进程入口提供 JSON 请求响应；可使用 HTTP JSON 与短轮询或 stdio JSON 请求，先落地一个传输即可。运行中和结束后方法、游标和错误语义一致，服务重启从索引水位继续。查询状态最多读取小型状态文件及最新 marker，默认 1 秒轮询可作为本机实验设置；同步长计算期间不承诺业务状态刷新。

`schedule.py`、`society.py` 和 `logging/context.py` 写出小型最新运行状态，静态配置保留在一次性元数据中。summary 保留汇总值和历史数据引用，批次明细分页读取；输出体积统计覆盖检查点、Thread 和记忆目录，并明确逻辑大小及重复来源口径。`StepResult` 大表支持迭代写出数据集并返回引用，marker 前已写出的结果仍标记未提交。实时阶段状态允许失败诊断，不能冒充已完成步骤结果。

## 四、验证

TDD 按实际风险组织：先提交可重现旧行为或缺失能力的失败测试，再写实现，再做大规模实验。测试记录保存命令、提交、环境、失败原因和通过结果；不得用跳过、xfail 或放宽语义断言消除最初失败。

### 4.1 先失败的确定性测试

存储组先证明现有全量编码和根快照会触发禁止整份物化的探针，再验证 10,000 次同对象修改仍为一个末值、两种状态模式恢复逐项等价、append 顺序不变以及多步骤 epoch 仅最后步骤出现 marker。通过文件访问计数测试 10、100、1,000 个历史检查点后相同空增量发布的读取量；正常发布的历史 manifest 读取数应保持常数上界，不能随步数增长。

Thread 组先重现只读读取截断 20 字节半行和元数据读取打开 blob，再以源文件字节及大小不变、blob 打开次数为零验收。覆盖边读边追加、超大单行、跨目录 Thread、关闭后缓存释放、固定前缀分页、全部内容重组以及模型消息全文等价。固定页读取的历史字节访问量不得随 Thread 总长线性增长。

查询组先写索引滞后、两页间新提交、delete/recreate、整数键与字符串键、fork 后旧版本查询和服务重启用例。所有页拼接后与同一检查点的恢复状态逐项比较，同时验证顺序、总数、引用内容和来源身份；读 API 不得调用 World 恢复。慢消费者与断连测试固定队列上限，并通过补读得到全部权威记录。

故障注入覆盖根组件写入、定位文件写入、manifest 前后、marker 前后、最新指针更新、索引事务中断、通知发送和 Thread 关闭。每个位置检查旧 marker 可恢复、未提交数据不可见、索引能幂等继续、Thread 未被读取方修改以及失败步骤未被纳入记忆成功视图。分别杀死 writer 与 reader 进程，进程内异常测试不足以替代退出场景。

### 4.2 大规模实验与通过标准

独立基准进程至少构造 204,882 条 replacement、137,117,466 字节原始增量、2.79 MiB 以上单记录，以及原始展开不少于 1,879,249,233 字节的根。补充一个远超普通块的单字符串，验证编码缓冲确有上限。大工件在有足够资源的指定实验位置生成；本机不留下完整产业世界。实验数据是等规模合成负载时，报告明确区分与真实产物验证。

固定活动状态与单步增量，历史取 1、10、100 倍；分别固定历史扩大当前增量，连续至少 20 个步骤。报告根发布、seal、epoch 合并/暂存、编码、压缩、写盘、索引初建、索引增量、分页、恢复和关闭的时间、I/O、Python 分配峰值、RSS 峰值和文件数。RSS 与 tracemalloc 分开测量，同数据同机器同配置比较基线和实现；测量脚本最终全量对账不计入产品阶段。

正确性门槛为逐项恢复等价和所有分页内容完整；复杂度门槛为固定页、固定本步增量的历史读取计数不随无关历史线性增长。资源门槛为编码临时峰值不随根/增量完整 JSON 字节数线性增长，观察队列和解码缓存不超过配置上限；总 RSS 单独解释 World、seal 对象和恢复对象的占用。通过不同规模的峰值斜率及实际缓冲计数共同判定，不能以单次 RSS 降低作结论。

实时性实验目标为生产者已上报状态到本机查询可见的 p95 不超过 2 秒；报告轮询间隔、样本数、生产吞吐、索引吞吐与积压字节。查询平均处理能力须超过实验产生速度，故意减慢查询器后积压可以增长，但引擎与连接队列内存保持上限，恢复消费后所有引用可补齐。Ceph 上需要另测写入和可见延迟，本机结果不替代部署文件系统验收。

### T17 补充：紧凑索引与显式历史准备

派生索引将路径保存为 parent + 压缩的 JSON 类型化单段字典，entry 版本引用路径 ID。每个 entry 只登记直属 scope 的版本区间，以 `(scope, ordinal, start)` 定位历史；当前行使用部分索引。祖先关系按实际集合登记，祖先页对活跃直属集合进行有界多路归并，保留原 ordinal 顺序。超过候选或集合预算时显式要求 prepare，不为每个 entry 复制所有祖先 membership。每个 epoch 对同 scope 的计数变更合并一次，版本 total 通过最近 `version <= V` 定位。聚合缓冲限定 256 项，溢出写本地临时表，避免初建时把所有 scope 计数留在 Python 内存。

普通历史页先按 ordinal 再按版本索引定位，每页最多检查 256 个候选。大量已删除条目需要显式 `prepare_state(checkpoint_id, path)`，在本地磁盘一次构建指定范围的可见 ordinal → entry 引用投影。超预算返回包含 code、method、checkpoint_id、path 的 index_pending；不会返回空页循环。`prepared_state()` 提供准备身份、总数和后台请求状态，`clear_prepared_state()` 清理；一个索引只存一个结果。后续页面在一个 WAL 读快照内确认身份并取条目，原游标在缓存替换后仍绑定原版本。

HTTP 准备复用后台索引线程与单槽请求，前台立即返回 queued；已有请求时返回 preparation_busy。事务提交前保留旧投影，进程崩溃后旧 ready 和 indexed 水位保持。派生格式版本变化明确要求 --rebuild-index。验收包括同 205k 根的 dbstat、main/WAL/SHM 峰值与关闭后稳态、20 次连续 delta、当前/历史页面 p95、热键多版本 VM 指令斜率、删除条目显式准备、进程 kill 与断开客户端。

### T17 实际产物驱动的直接集合索引

实际 1,448,471 个 entry 的旧祖先展开产生 8,178,282 条 membership，直接父集合仅 102 个。派生 schema 3 将 membership 改为直接父集合；集合到祖先的闭包单独保存，当前闭包在直接集合删空时同步移除。历史闭包保留以支持旧版本准备。精确总数继续按祖先、版本增量合并，不依赖翻页扫描。

当前根范围使用全局活跃 ordinal 索引；其他范围合并相关活跃直接集合的有序流，并单独纳入该路径自身的 entry。单页最多打开 128 个集合，工作量为 O(K + page log K)，K 是活跃相关集合数量；超预算可对当前固定 checkpoint 显式 prepare_state。旧版本继续遵守 256 次候选探查预算。准备投影优先于直接读取，保持固定身份、单槽、失败保留旧 ready 和重新准备后旧游标可继续的语义。

全局 parts 字典只存一份类型化 JSON 段，paths 保存 parent 与 part ID；长段采用 zlib level 1 且仅在变小时压缩，短段保留原始 UTF-8。编码可逆、分页仍按业务 ordinal 排序；schema 或 zlib runtime 版本变化要求显式重建。阶段内的路径、祖先类型、活跃集合缓存均有项数上限，路径另有字节上限；修改、删除和重建立即使相应状态缓存失效。

### HTTP 慢消费者验收

服务使用 4 个有界处理名额，不建立无界请求队列；饱和时及时返回 503/server_busy，读写 socket 超时为 5 秒。每个请求打开独立只读索引连接，构造路径不写 schema 或绑定身份；后台索引保持独立写者连接。准备队列、准备状态检查及入队共用互斥锁。真实 TCP 子进程覆盖半截 body、暂停接收大 response、四连接饱和、断开后的名额恢复及长写事务期间的 status 查询。

# 刷新与资料更新

页面通过重新生成同一入口并刷新来更新。不依赖实时订阅或代码热更新。

## 一、流程

```bash
# 1. 修改项目数据
$EDITOR <project>/workbench/data.json

# 2. 重新生成同一入口
python3 <skill>/scripts/render_workbench.py --project <project>/workbench

# 3. 提示用户刷新
```

生成失败时保留上一份可打开文件，不要覆盖成半成品。

## 二、刷新后要保留什么

- 所选配置版本、运行、世界、时点、主体，按稳定 ID 恢复；
- 面板布局、折叠状态、过滤条件；
- 参数草稿，按 study + 配置来源保存；
- 用户已经滚到的位置（尽力恢复，不强制）。

原选择已被移除时给出明确说明和重新选择入口，不要静默跳到另一个世界。

## 三、草稿冲突

源配置变化时保留三方信息：

| 字段 | 含义 |
|---|---|
| 原值 | 草稿建立时的资料 |
| 当前值 | 新资料里的实际值 |
| 草稿值 | 用户此前编辑的值 |

由用户决定保留或放弃；页面不自动采用草稿，也不静默覆盖新资料。

## 四、资料版本

每次生成在 `study.dataRevision` 写一个显式序号，并在页面显示。旧版 HTML 作为独立工件保留即可，不需要兼容层。

## 五、浏览器存储不可用

隐私模式或受限环境可能禁止本地存储。此时阅读可以继续，但草稿无法在刷新后恢复：提示用户导出或复制草稿，并说明当前状态不会被保存。

# 空态、骨架与渐进资料

资料是逐步到来的。页面上任何区域都可能处于八种状态之一，界面必须能分辨它们。

## 一、状态

| availability | 含义 | 页面表现 |
|---|---|---|
| `unconfigured` | 还没有确定要提供什么 | 居中引导：用途 + 下一步 + 一个可复制入口 |
| `awaiting` | 已确认要提供，资料还没到 | 稳定占位轮廓 + “待提供资料” |
| `loading` | 正在读取已经存在的资料 | 短时骨架，保留布局 |
| `empty` | 查询范围内确认没有记录 | 明确“这个范围没有记录”，保留筛选 |
| `partial` | 部分字段、对象或时点已提供 | 呈现已有内容，在缺口处说明 |
| `ready` | 当前范围资料完整 | 正常组件 + 来源 |
| `error` | 读取或格式失败 | 局部错误与更新建议 |
| `stale` | 当前展示来自更早的资料版本 | 保留内容并标注版本 |

未配置与待提供都不应伪装成加载中。确认无记录不等于未采集。数值零保持为零，不用空值填补。

## 二、初始空白页

空实验允许整页打开：

- 顶栏显示标题与资料版本；
- 左侧保留实验配置入口，插件第一、平行世界第二；
- 中间显示当前分区的用途和下一步；
- 右侧“待发送变更”为明确的空态。

不要为了填满屏幕而创建假主体、假运行或示例曲线。

## 三、渐进填空的顺序

典型进入顺序是：标题 → 插件 → 世界计划 → 主体 → 运行条目 → 部分结果 → 多世界与完整资料。资料可以跳过阶段，也可以只给其中一部分。

每补一类资料，重新生成同一 HTML 并刷新；已就绪的区域保持不变，新区域出现真实内容，未到区域继续显示等待状态。

## 四、引导文字

引导最多包含三部分：这块区域用来做什么、现在缺什么、下一步可以做什么。入口按钮的行为是复制一段可以发给 Agent 的自然语言请求，或切换到已有页面；它不触发实验运行。

示例（插件为空）：

> 还没有确定实验需要的机制。先和 Agent 讨论这次实验需要哪些机制，例如环境、主体认知、记忆或市场规则。资料更新后，插件与参数会出现在这里。

## 五、骨架屏的使用边界

骨架只用于读取真实存在的资料。读取完成后必须立即替换为内容或空态。无资料、无网络或未配置时不要留下持续动画；`prefers-reduced-motion` 下停止动画。

# 猎龙：以环境验证 Core 可组合性

本文是本轮实施规格。交付目标是通过实际环境消费者检验并改进 Core 的组合边界、依赖表达、信息消费和资源生命周期。基础环境的功能对齐提供反例与对照；其功能范围见 [基础环境迁移验收](../../docs/core-next/basic-env-migration.md)。实施清单见 [TODO](TODO.md)。

## 一、目标与边界

空间组合：多个机制共享权威存储和主体目录，子插件可独立安装、被其他组合复用，服务通过显式引用连接；两个显式命名的同类组合可以共存。时间组合：阶段调度、信息呈现、异步等待、步骤回调和完整点遵守业务顺序，恢复后继续执行保留相同事实与主体可见信息。组合既包含领域数据与计算，也包含输入输出的旁路消费者。

本轮由 plain、round-robin、social-network 及独立推荐观测插件消费这些能力。稳定版、产业环境、现有部署不变。外部模型使用录制或确定性替身；不进行付费请求。接口可调整，调用方随之更新，避免兼容分叉。运行中的插件热替换、持久化格式迁移及通用事件总线不属于本轮；策略在显式运行装配或完整点恢复时选择。

## 二、已验证的问题

起点是 Next `7320b13`；旧功能参照 `v4.1.14`。首轮只读探针已复现以下问题，实现须先把这些反例变成自动测试。

| 编号 | 发现 | 决策与公共价值 |
|---|---|---|
| C1 | `Plugin` 仅表达平铺安装图；复合产品缺少统一展开与预检入口 | 静态子插件纳入同一预检，保持显式实例名与服务引用；配方不复制子插件运行状态 |
| C2 | `requires` 同时支配初始化与服务安装；主体驱动依赖环境输入时，两个真实机制均形成 actors→driver→mechanism→actors 环 | 区分数据先决与服务借用；把主体数据目录从驱动工厂装配中分离。分别拒绝两个图中的真环 |
| C3 | `Information.close` 对同一对象多次挂载重复关闭；首个关闭失败遗漏剩余资源 | 明确挂载借用与所有权，复用 Host/AsyncExitStack 的逆序完整清理；生命周期由实际资源创建者负责 |
| C4 | RR Python 服务可访问的小组、计划及历史缺少主体公开信息路由 | 先复用 SQLInformation 的授权、分页、原文和版本规则；出现第二个相同缺口后再扩大 Core 抽象 |
| C5 | Social 混合状态、事务写入、计分、候选、向量、排序、曝光与信息 | 按真实依赖拆子插件；推荐策略可替换；复用输入输出的第三方消费者不依赖全能 Social 对象 |
| C6 | Social 只读 feed 被当成实际呈现，曝光入口悬空；热门 top2 使用推荐活动池 | 分开查询、呈现及其效果；全局热门用索引查询，推荐保留有界活动池 |

已有能力继续复用：默认空 install 已允许纯数据插件；原生 SQL 提供跨插件事务；Host 已支持依赖逆序清理、quiesce 和步骤回调；prepare 在创建时执行而恢复不执行；schema 的规范比较允许独立 DDL 调整顺序。以上无需另建框架。

## 三、接口方向

### 3.1 Core 与主体

`Plugin` 增加静态子插件集合与独立数据先决声明。展开后统一检查名称冲突、缺依赖、数据图与服务图的环，在创建目录和取得资源之前完成。服务 `requires` 仍约束 `ctx.require` 与生命周期。子插件实例名、表前缀、动作名由工厂参数明确产生，不通过字符串替换闭包重命名。

主体目录承担记录、persona、主观状态及选择索引；运行映射承担 driver 工厂。环境借用目录即可读取资料和更新参与状态，driver 则能显式借用环境信息构建服务。既有便利工厂可以组合这两者，独立目录工厂允许没有 driver 的纯领域运行。

Information 路由挂载的资源归属必须单一且可追溯。共享 provider 多挂载、部分安装失败、关闭失败均不应泄漏或重复释放。对于随主机创建的机制，优先由创建它的插件登记清理。

### 3.2 社交子插件与策略

按依赖组织领域数据、关系、内容互动、通知、曝光、候选/排序、语义索引和信息呈现。文件数量由实际实现决定，验收针对服务和数据的实际所有权。根配方聚合子插件、绑定默认策略；子插件可以独立装配。

一次行动由同一个 `store.transaction` 调用各领域事务内写入器，事实、计数、索引和通知原子提交。互动事实与推荐排序分开：点赞/评论/转发计数是领域事实，engagement 是配置化投影，策略替换不修改这些事实。固定的默认投影可以被多个排名消费者借用。

推荐输入包含 actor、时点、候选元数据、关注关系、可选语义分数和来源版本，不包含全能服务定位器或帖子全文。排名输出保留候选身份、分数、稳定次序和完整总数。加权与时间排序是两个实际策略；外部插件通过具名 `rank` 服务替换默认绑定。独立观测插件消费候选及两种排名输出，将对照结果写入自己的数据表，不改内容模块。

候选源分别提供活动推荐池和全局热门索引 TopK。语义索引独立管理异步任务、SQL 原始向量与可重建外部索引；无语义策略不装配它。结果的完整正文仍由范围入口提供。

### 3.3 呈现与时间

Information 预览保持只读。实际认知呈现由显式消费者选择结果并登记曝光：展示哪些 id，才为哪些 id 产生曝光；同 Moment 的重复激活使用已有认知游标并保留完整 Thread。实际 feed、热门预览与热门行动分别验证。曝光和通知在规范步骤边界提交，失败步骤不发布完整点；恢复后继续结果一致。

## 四、验收门槛

1. **实际组合**：真实 RR 与 social 驱动工厂依赖本机制输入服务仍能初始化、运行、恢复；两个独立显式命名组合共存。
2. **可替换与复用**：加权↔时间策略通过装配引用切换，信息呈现与内容写入无修改；独立纯数据观测插件消费其输入输出并恢复。
3. **先失败后修复**：保存具体红例命令与失败原因；禁止用删断言、跳过用例或减少主体资料通过验收。
4. **等价**：旧基线与 Next 在隔离进程中执行相同脚本，比较逐条动作、配对、消息、计数、通知、曝光、原文及恢复后继续结果。时间戳/id仅在确无语义的字段显式标准化；主动损坏结果证明比较器能报错。旧空配置或缺陷另列合同差异。
5. **真实信息入口**：通过 Session/Information、ActorFiles、完整 LLMDriver+scripted provider 读取和行动；直接 Python 服务测试作为补充。
6. **故障与生命周期**：两个依赖图、名称冲突、安装失败、初始化失败、恢复跳过初始化、异步等待中版本变化、关闭取消与逆序清理、步骤回调失败不发布均有明确结果。
7. **成本**：固定活动集，扩大历史；记录 SQL VM/实际读取字节、计算/外部等待/完整点/恢复、内存和增量磁盘。多主体交错推荐分页单独测量。全量读取和全图算法按实际规模记录；不以省略曝光或信息形成性能收益。
8. **集成**：焦点测试后执行全部离线测试、实验和 workbench 测试；非作者独立挑剔审查；明确证据范围后合入 next。旧 stable/tag/main ref 保持不变。

## 五、推进顺序

A：固定反例与接口边界，交付本规格及测试矩阵。B：Core 组合、主体数据分离、资源归属并行实现；RR 信息路径先行。C：Social 子插件与替换策略、外部观测消费者接入。D：实际呈现/曝光、跨进程恢复及旧新对照。E：分项性能、完整回归和非作者审查。每阶段更新问题清单，新的共性能力由至少两个实际消费者或清晰的资源所有权问题支撑。

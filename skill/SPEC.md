# society0 Skill 维护合同

## 目标与边界

把用户问题转成可选择的仿真设计、可执行的实验配置和真实运行结果，适用于社会、教育、组织、政策、市场等领域。主入口保持 `name: society0`，沿用仓库 `skill/` 布局。Skill 为实验使用方提供方法；引擎负责机制与运行，现实有效性按具体实验评估。

执行形态为 reference-backed-expert：主文保存阶段路由和关键约束，领域知识按需读取。两轮检索采用宿主可用的并行搜索工具；工具能力不足时清楚报告实际覆盖。无需新增编排服务或专用 UI。世界知识负责提出因素和因果路径，搜索负责锚定当前问题及核实关键事实。

## 行为合同与验收

| 阶段 | 应交付的行为 | 验收方式 |
|---|---|---|
| 安装 | 复用或克隆正确源码、依赖与目录准备、模型配置、初始化/真实试跑/恢复分开报告 | 命令与实际 API 核对；小型确定性消费者；真实服务执行另行留证 |
| 第一轮 | 有预算的资料整理与研究先例；推荐主体、环境、机制、互动与反馈；一组带推荐理由的关键选择 | 同一回复中完整说明并集中提问，工作台呈现当前设定；交付后等待基础设定确认，资料整理不连续追加问卷 |
| 第二轮 | 沿用已确认基础设定，交付模拟问题、平行世界矩阵、初始化、观测和时间尺度的完整配置 | 工作台同步当前方案；再次停止等待用户确认比较安排及构建范围，确认后才进入第三步 |
| 构建与运行 | 可见 todo，资料/实现/检查/真实试跑/正式执行/监督/恢复逐项推进 | 实现失败与结论不符合预期分开；保留真实模型、原文、行动和完整点语义 |
| 结果与迭代 | 按实验问题读实际结果、解释比较边界、交付来源、提出有增量价值的后续方案 | 已有结果任务直接取数；追加费用和科学设定变更获得授权 |
| 工作台 | 按最新版 society0-workbench 快速起步，低成本维护同一入口，每轮设计交付均同步当前设定与待确认项 | 核实打开和更新回执、每轮内容变化及草案身份；具体方法、时机、布局与协议由工作台 Skill 决定 |
| 设计协作 | 两阶段分别确认；集中推荐；增量修订保留已有决定，按影响范围复用相应停点 | 真实宿主验证两个等待点、部分回答、基础设定扩展及纯比较变更；todo与持久目标止于获准交付 |
| 主体扩展 | 沿作用路径发现遗漏的参与者与关系，说明裁量、初态、互动和表示取舍；区分候选覆盖、设定纳入、实际运行 | 产业与非产业任务均能解释增补价值；具名资料、假设连接和未知项各有身份；不以试跑规模代替研究覆盖 |
| 外部资料交接 | 数据接口、名录、画像与关系查询由用户提供的资料 Skill 操作；核心保留研究需要、资料时点与建模判断 | 按实际可用入口交接，入口未提供时沿用已有材料并标缺口；核心无预设接口名或查询实现 |
| 过程解释 | 从原始工件串起可见信息、动作、兑现与反馈，解释实际发生与预期路径的关系 | 保留失败、等待与缺失环节，主体自述与事实分别引用，机制归因遵循实际比较范围 |

## 披露与维护

每个 references 叶子由主文直接提供按需入口。第一轮加载社会仿真设计经验、设计指南及最相关领域先例；模型和编程细节在执行准备时读取。安装后的包内链接仍可解析；仓库资料通过已定位源码根或明确在线地址访问。宿主问答工具可用时使用单选/多选；普通文本提供等价选择，已有决定不重复询问。

维护源、安装副本与发行分别标识。保留现有 starter、原生结果读取与导出资产的测试；工作台布局和导出协议归 society0-workbench。独立最终验收由未参与实现的 Agent 演练任务并报告缺陷；关键词出现、文件存在和测试数均不单独证明流程完成。

## 触发样例

应触发：从问题设计仿真；选择影响因素；已有方案补主体、关系或机制；局部修订比较安排；配置平行世界；安装 Society0；构建与运行确认过的实验；解释或恢复已有 Society0 运行；从论文改编仿真。
不触发：普通事实问答而无仿真目的；纯企业资料查询或清洗（交由用户提供的资料 Skill）；通用网页制作；其他项目部署；仅操作工作台资料且无需仿真设计/执行（交由 society0-workbench）。

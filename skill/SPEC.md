# society0 Skill 维护合同

## 目标与边界

把用户问题转成可选择的仿真设计、可执行的实验配置和真实运行结果，适用于社会、教育、组织、政策、市场等领域。主入口保持 `name: society0`，沿用仓库 `skill/` 布局。Skill 为实验使用方提供方法；引擎负责机制与运行，现实有效性按具体实验评估。

执行形态为 reference-backed-expert：主文保存阶段路由和关键约束，领域知识按需读取。两轮检索采用宿主可用的并行搜索工具；工具能力不足时清楚报告实际覆盖。无需新增编排服务或专用 UI。世界知识负责提出因素和因果路径，搜索负责锚定当前问题及核实关键事实。

## 行为合同与验收

| 阶段 | 应交付的行为 | 验收方式 |
|---|---|---|
| 安装 | 复用或克隆正确源码、依赖与目录准备、模型配置、初始化/真实试跑/恢复分开报告 | 命令与实际 API 核对；小型确定性消费者；真实服务执行另行留证 |
| 第一轮 | 有预算的检索及研究先例；因素与作用路径；主体裁量、环境、互动、时间与推荐取舍；具体实验问题 | 提问前已有可见的设计说明；主动发现重要因素，解释为何选择此种世界及替代方案的适用性 |
| 第二轮 | 吸收新条件形成连贯设定；比较政策、机制或适用条件；初始化、过程与结果观察、时间和规模理由 | 前两轮能构成可讨论的完整世界；共同起点与外生条件明确，政策后行为自然分化；用户能理解各比较回答什么 |
| 构建与运行 | 可见 todo，资料/实现/检查/真实试跑/正式执行/监督/恢复逐项推进 | 实现失败与结论不符合预期分开；保留真实模型、原文、行动和完整点语义 |
| 结果与迭代 | 按实验问题读实际结果、解释比较边界、交付来源、提出有增量价值的后续方案 | 已有结果任务直接取数；追加费用和科学设定变更获得授权 |
| 工作台 | 正式使用开始先按 society0-workbench 指引创建并打开空壳；渐进传递设计/配置/运行证据 | 核实打开状态；候选、Agent 提议与用户确认有来源；布局/协议使用对方实际合同 |
| 设计协作 | 方案确认与执行授权分开，回应新增条件并同步受影响设计 | 真实宿主多轮测试核对选择是否生效、修改是否一致、是否维持设计身份；未经授权保持尚未构建/运行 |

## 披露与维护

每个 references 叶子由主文直接提供按需入口。第一轮加载社会仿真设计经验、设计指南及最相关领域先例；模型和编程细节在执行准备时读取。安装后的包内链接仍可解析；仓库资料通过已定位源码根或明确在线地址访问。宿主问答工具可用时使用单选/多选；普通文本提供等价选择，已有决定不重复询问。

维护源、安装副本与发行分别标识。保留现有 starter、原生结果读取与导出资产的测试；工作台布局和导出协议归 society0-workbench。独立最终验收由未参与实现的 Agent 演练任务并报告缺陷；关键词出现、文件存在和测试数均不单独证明流程完成。

## 触发样例

应触发：从问题设计仿真；选择影响因素；配置平行世界；安装 Society0；构建与运行确认过的实验；解释或恢复已有 Society0 运行；从论文改编仿真。
不触发：普通事实问答而无仿真目的；通用网页制作；其他项目部署；仅操作工作台资料且无需仿真设计/执行（交由 society0-workbench）。

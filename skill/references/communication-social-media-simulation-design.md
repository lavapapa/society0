# 传播、社交媒体与信息扩散

## 适用问题

- 推荐、热榜、关注或好友背书如何改变信任、极化、沉默和误解？
- 新闻、谣言、更正信息如何在网络中扩散？
- 平台干预、标注、限流、删除或桥接推荐如何改变暴露和态度？
- 群组、意见领袖、潜水者和版主如何共同影响讨论？

## 环境

优先从 `social-sqlite` 开始，按研究问题选择组件：

- `social-repository`、`social-init`：成员、关系、帖子、投递和通知。
- `topology-edges`：显式边、随机、小世界、无标度、完全图或目标变异系数网络。
- `social`：发帖、回复、转发、反应、关注、偏好、通知消费；配对配置开启私信和群广播。
- `propagation-neighbors`：邻居传播。
- `social-ranking`、`social-recommendations`：排序、推荐准备、来源版本和呈现。
- `social-perception`：资料、动态、通知和推荐进入感知。
- `social-measurement`、`measurements`：排名比较和结构化测量。

推荐研究要显式写出：

- 推荐池从哪里来，规模多大。
- 评分权重、剪枝阈值和展示条数。
- 是否使用嵌入相似度或网络关系。
- 曝光和点击/反应如何记录。
- 原文与展示截短的关系。

这些是实验条件，不是中性管道。

## 主体与可见范围

常见主体：

- LLM 读者、分享者、意见领袖、潜水者、版主、事实核查者。
- 规则账号作为平台基线或固定信息源。

每个主体的可见范围要区分：

- 推荐流、关注流、热榜、通知。
- 帖子原文、作者、时间、来源标签。
- 好友背书、反应数、回复数、转发链。
- 平台标注、更正、限流或删除状态。

不要让主体看到研究者的条件标签或“这是处理组”的说明。推荐权重和暴露规则通过环境体现，不要写进提示。

## 行动

- `social.publish`：发帖，可带 tags、id、metadata。
- `social.reply`、`social.repost`：回复和转发。
- `social.react`：反应，可移除。
- `social.follow`、`social.unfollow`：关注关系。
- `social.preferences`：主体偏好。
- `social.consumeNotifications`：消费通知。
- `social.sendPartnerMessage`、`social.broadcastToGroup`：配对或群组开启时使用。
- 不行动也是行动，要能记录为“没有发布/没有反应”。

行动要窄到可以审计。不要给一个“参与讨论”的宽泛入口，否则无法判断主体到底做了什么。

## 测量

- 立场或态度分布。
- 信任、可信度、分享意愿。
- 跨群体暴露和回音室指标。
- 帖子和回复的数量、长度、情绪或主题分布。
- 更正信息的到达和接受。
- 推荐池、曝光、点击、反应和传播路径。
- 定性理由和话语模式。

测量题项和展示材料分开。主体看到的帖子可以截短，测量和排名使用完整正文。

## 最小实验

- 两到三种信息条件。
- 6–20 个主体，5–10 个 tick。
- 一个网络结构，一个推荐或传播规则。
- 先看一条曲线或一张对照表。
- 推荐研究先固定推荐池和展示条数，再改权重。

## 常见坑

- 同时改推荐权重、主体人格和帖子内容。
- 只记录最终立场，不记录暴露和行动。
- 把推荐分数当成主体态度。
- 用展示截短后的文本做测量。
- 忽略失败、未完成和没有行动的样本。
- 把一次扩散路径当成稳定机制。

## 有效性检查

- 曝光记录是否支持“谁看到了什么”。
- 推荐条件是否在控制组和处理组之间只改了一个因素。
- 网络结构和种子是否固定。
- 多个种子下方向和分布是否稳定。
- 定性理由是否与行动回执一致。
- 结论是否超出了模拟平台和主体构成。

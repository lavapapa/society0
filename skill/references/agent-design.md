# 主体设计

主体是环境里的参与者。它的差异来自人格、状态、角色、可见范围和可用行动，而不是来自一段越来越长的提示。

## 先决定驱动

### 规则主体

适合：

- 确定性基线和对照。
- 已知的算术、结算、权限、调度和状态转移。
- 平台、机构或流程角色。
- 参数扫描中需要排除模型波动的部分。

Core 的 `driver-rule` 通过 `society/rule-handler` 槽位获得规则。`rule-passive` 提供空动作基线；`plain` 提供 `plain/update`，把主体属性更新写入世界并留下行动回执。规则主体同样走 actions、receipts 和完整点路径。

### LLM 主体

适合：

- 解释模糊文本、冲突叙述和情境线索。
- 访谈、问卷、评分和开放式回答。
- 说服、信任、身份、情绪和规范判断。
- 需要记忆、计划和自然语言互动的行为。

`driver-llm` 维护完整 Thread、感知读取、行动发现、参数 schema、预算和完成判定。它适合行动循环；测量用结构化提交，不要用普通行动假装测量。

## 人格

好的人格文本具体但不过载：

```text
一位中年家长，经常看社区社交平台，关心学校安全，对匿名来源持怀疑态度。
```

避免：

- 在人格里写处理组标签。
- 把许多无关心理特质堆成一段。
- 用刻板印象替代研究构念。
- 在运行中途改人格，除非研究的就是身份变化。

人格应该解释“这个人会怎样理解材料”，而不是替研究者宣布结论。

## 状态

用少量数值或分类变量表示需要随 tick 变化的状态：

```json
{
  "trust": 0.45,
  "attention": "medium",
  "topic_familiarity": 0.2
}
```

写清：

- 取值范围和单位。
- 初始值来源。
- 哪些状态对主体可见。
- 哪些状态只对研究者可见。
- 状态什么时候更新，由谁更新。

LLM 主体的状态会进入自我描述。它适合注意力、信念、情绪、资源和当前角色；不适合隐藏条件、真值或研究者的分组标签。

## 记忆

记忆不是一个开关，而是三件独立的事：

- **写入**：什么经历会被保存，什么时候保存。
- **召回**：当前激活是否读取记忆，读取多少。
- **主动工具**：主体是否可以主动查询或写入记忆。

这三项应分别配置。关闭召回不应删除当前感知材料；记忆为空也不应导致主体看不到本轮输入。需要显式经验提取时，在完成钩子里写入，并保留原 Thread 和提取结果的关系。

公开的 `@society0/extras/memory`、`memory-repository`、`memory-write-experience`、`vector-*` 提供记忆和向量检索组件；使用前核对实际 profile 是否装配了对应服务。没有装配记忆时，不要把“记得”写进主体提示当成已实现机制。

## 感知与行动预算

- `driver-llm` 的 `perceptions` 决定显式感知来源；`defaultPerceptions` 为真时还会追加声明了默认 driver 的来源。
- `maxRequests`、`maxToolCalls` 和 `maxTurns` 控制单次激活的预算。
- `requiredActions` 决定完成所需行动；只有成功回执才算完成。
- 预算耗尽、输出截断、提供方失败和工具失败都要保留为未完成或明确警告，不能悄悄当成成功。
- 模型输出预算要按实际提供方设置。`maxTokens` 太小会在拿到工具调用前被截断。

## 主体数量和异质性

第一版：

- 每个群体至少一个主体，但总数能逐个检查。
- 异质性只放在研究需要的维度上。
- 规则主体和 LLM 主体可以混用，但要在分析时分开。
- 不要把每个角色都做成 LLM；先问这个角色是否真的需要语言判断。

扩大规模的条件：

- 小规模运行中，主体看到的是预期材料。
- 行动成功率、拒绝率和未完成率可以解释。
- 结果变量的分布在少量主体上已经能读出方向。
- 增加主体不会改变环境的业务顺序和测量口径。

## 主体检查表

```text
[ ] 每个主体有明确的可见范围和行动集合
[ ] 隐藏条件没有进入人格、状态或公开表
[ ] 规则主体负责确定性机制，LLM 主体负责语言判断
[ ] 记忆的写入、召回和主动工具分别配置
[ ] 预算、截断和失败有明确处理
[ ] 主体数量与 tick 数匹配当前研究阶段
[ ] 主体差异能在结果中被识别，而不是混成一个总数
```

# 第二轮：把选择变成实验配置

读取第一轮确认的设计简报。围绕具体实验问题选择比较方式，再决定运行规模；已有配置或用户给定参数直接沿用。

## 1. 世界与对照

平行世界是控制变量、机制比较和反事实推演的组织方式。逻辑上的世界可以按资源顺序执行，物理并行需符合服务容量。

| 问题结构 | 合适的初始化 | 要明确的比较边界 |
|---|---|---|
| 比较不同起点、历史或制度体系 | 各自独立初始化，说明真实差异或假设差异 | 多因素一起变化时解释总体情景差异，谨慎归因于单一机制 |
| 隔离一个干预的影响 | 同一人口/初态参数配对生成，按需控制随机种子 | LLM 即使同 seed 仍可能随机，配对初态不等于轨迹相同 |
| 看两个因素及交互 | 如可见性×奖励的 2×2 因子设计 | 每一项主效应及交互的比较对象、固定条件与测量相同 |
| 同一已发生过程之后施加不同干预 | 从可信完整检查点创建分支，验证代码与合同兼容 | 干预之前状态与信息可信；按实际引擎支持的合同执行 |
| 观察单一机制能否形成某种过程 | 一个世界加过程测量；必要时随后增加对照 | 单世界描述过程，进一步归因需要有区分力的比较 |

不要要求所有世界共享历史。也不要通过改写运行中的状态去伪造另一段历史。对于两个有不同历史的社区，可以分别在各自背景中比较可见性规则；跨社区比较另说明历史差异的影响。

世界矩阵至少列出：世界 ID、回答的实验问题、比较对象、初始化方式、实际变化因素及值、保持固定的条件、测量对象与时间窗、需要的机制。从矩阵实际字段逐对列差异，核对声称固定的条件是否真的相同。同时改变内容、渠道、对象或资源的方案，归因到组合策略；单因素归因用匹配对照或因子设计。若声称同预算，明确相等的预算维度，并列出费用、人员职责和时间占用的实际差异。结论按实际对照描述，并指出仍混合了什么。新机制在第一轮已选中才进入配置；用户新增要求回到相关设计决定。

技术路径按实际 API 核对：逻辑上可比较的世界无需强行套入 checkpoint restore；运行合同拒绝的变更用独立初态或明确的情景工厂实现。工作台的页面/管理入口能否表达该方案由 society0-workbench 核对。

## 2. 时间、主体与测量

一起明确以下配置，并解释会改变结果的选项：

- 仿真起止日期或轮数，准备/适应期及其用途；Tick 的业务含义。
- 环境推进粒度、主体激活频率、记忆处理与测量时点；公告、可见与生效时间分别记录。排队、到期、资源到达与失败发生的先后能改变结果时，用相应事件/阶段表达；日度汇总数据不足以确定日内顺序。
- 主体列表或人口生成规则，LLM / 规则 / 非主动主体的分工；规则行为必须有领域含义。
- 每个问题对应的结果变量、单位、分母、事件与主体范围。分开定义意图、请求、实际完成、受限/未完成，以及真实状态与记录值；兼顾总体结果、关键亚组和代价，保留可重算的原始行动与解释材料。
- 隐藏的条件标签和真值不得进入主体可见输入；主体获得的信息按该世界当时状态生成。
- 模型提供方、决策模型和提取模型、独立的自动写入/自动召回/主动记忆工具开关、嵌入需求。
- 世界数与重复次数。先判断问题是否需要分布、方差或稳定性证据，再安排重复；引擎验收与研究重复分开。
- 方案值、业务上值得重视的差异、统计判定分别说明依据。业务阈值表达决策偏好；统计显著性与区间依赖估计不确定性及其假设。用确定性计算核对世界/重复数量、指标分母和关键资源账。

每个问题对应一项实际比较或过程观察。用户要求概率、改善幅度或方案排序时，先明确事件、分母、时间窗、假设分布与现实校准依据。跨期成功或存活事件按完整路径判定；单期流量分位数、累计量与路径事件的概率分别计算，核对它们各自的时间窗和随机过程。模型内重复的成功比例、参数敏感性区间与现实预测概率分别解释；重复次数增加能改善模拟误差，关键机制与参数的不可识别仍需处理。数据缺口优先按“会改变哪项决定、最小需要什么、向谁取得”排序。

## 3. 资源与执行授权

采用代表性已有运行或计划中的 pilot 估计请求与耗时，包含记忆提取、嵌入、重试和分析成本。没有可靠费率时报告调用量/时间的范围及金额未知项；价格从用户提供或核实的提供方信息取得。估计值与实际账单分开。

粗估请求数可按“各步激活主体×每激活预计模型请求”求和，再加独立提取、测量和重试。费用按各类实际 token 与其费率分别计算；并发改变重叠和排队，不能直接当作费用折扣。为控制规模，应把减少主体/轮次等改动作为用户可选的实验方案，保留信息、行动和语义。

给出推荐资源安排、预计范围、允许支出/调用预算、停止条件及实际可执行的监督方式。已有工具或运行器能限制预算时按合同配置；只有事后用量时明确检查频率和可能超额的窗口，避免把估计写成硬上限。发生规模跃迁、费用超出授权或服务限制时暂停受影响项，说明可选措施。

## 4. 配置确认

用一页配置摘要集中呈现：模拟问题与世界矩阵、共同条件及实际差异、时间与决策频率、主体和观测结果、资源范围、剩余假设与待实现机制。沿用第一步已确认的主体、环境与机制；需修改基础设定时集中说明影响。

默认工程设置附推荐值，把本阶段需要决定的比较方案和执行范围一次提交给用户。同步工作台中的完整配置草案，明确请求“确认这组模拟问题与平行世界，或提出调整”，并区分仅保存设计、进入构建、获准试跑及正式运行的范围。随后停止，等待用户回复。

收到针对该完整方案的确认与构建授权后，更新确认记录并进入[构建与运行](build-and-run.md)。个别参数的回答用于修订当前草案；修改后的完整方案再次交付确认。既有两阶段确认记录可复用，新研究仍经过本阶段的确认停点。

# 第三步：构建与运行

进入本阶段前，核对基础设定确认、模拟问题与世界矩阵确认，以及构建/试跑/正式运行各自的授权范围。确认记录齐备后，由 Agent 在批准范围内自动推进，直到得到可解释的结果或具体阻塞。先读取配置摘要、环境记录与已有工件，避免重复安装或覆盖旧运行。

## 1. 建立任务与执行现场

创建可见 todo list，逐项标为待处理、进行中、已完成；计划已经确定的下一步直接执行。典型任务如下，按实际已有成果删除已完成部分：

1. 定向补齐实现需要的资料与参数，记录来源或明确假设。
2. 核对插件能力，编译输入，装配已有机制并实现缺失机制。
3. 确定性检查、输入白盒检查和初始化预检。
4. 小规模真实模型试跑，核对工具、记忆、测量与恢复。
5. 按资源计划执行世界与重复，监督进度及失败。
6. 校核实际结果，分析、工作台交接和收尾。

每个任务有具体产物与完成条件。沿用项目目录约定，分开配置版本、运行目录和分析产物；本地空间不足时使用获准的执行设备。记录实际命令、环境与代码身份。后台任务保存任务 ID/进程归属、日志位置、最新完整点、下一次检查条件和停止方式；重连先核对这些记录。

## 2. 构建世界

核对“选定因素→状态/信息/行动/规则→观测结果”的映射。依据实际接口与示例复用插件；缺失机制先写输入、输出、时序与失败边界的规格和失败用例，再实现。环境承担客观约束，模型承担所选主体的裁量。

按[插件集与装配](<plugin-sets.md>)建立并消费组合清单：逐项记录实现入口、实例与服务绑定、分图依赖闭包、时间/空间映射、状态写入所有者及字段消费者；把待实现项转成明确开发任务，再将清单落实到真实工厂和Schedule。目录或自然语言配置经实际消费者接线后才产生运行行为。用清单选择字段白盒、组合与恢复检查；真实端点试跑针对本次实际使用且需要验证的模型链，规则路径采用确定性与恢复验收。

参数缺失时先查有影响的资料。已接受假设可直接采用并标注；不能改变问题含义的工程细节自行决定。若资料迫使改变主体边界、机制或比较逻辑，返回相应选择说明影响。保存用户排除的因素，使用模板时显式关闭不属于方案的默认组件。

研究字段是否生效直接检查输入构建器、FoV、领域服务或调度：例如决策日期进入主体认知与行动的日期必须一致，隐藏条件不会泄漏，世界之间只有声明差异。字段白盒验证不调用模型。业务机制检查逐笔权限、数量、来源、成本、税/账务或本领域对应不变量。

用当前公开 Plugin/compose、Actor/Driver、Information/Actions、Schedule 和 RunPlan/run_plan 组合。先读[运行起步](runtime-quickstart.md)，按需查[组件](engine-components.md)、[调度](step-dsl.md)和已克隆源码中的实际 API。示例代码按当前接口核对后使用。

## 3. 预检与真实试跑

完成依赖和初始化预检，确认输出目录独立、输入身份完整。预检只证明其实际执行的检查。随后使用获准真实端点在小规模代表性区间验证：

- 主体得到选定信息、可以发现行动、读取参数并实际调用；自然结束、拒绝和未完成分别留证。
- 自动写入、自动召回、主动记忆工具各按配置工作；提取、嵌入和决策请求分别记录。
- 结果与原始事实一致，完整步骤正常发布；独立进程从可信完整点在新目录恢复并继续。
- 记录纯环境计算、模型/记忆等待、工具、持久化、内存与状态增量；同一条件下测量有限 scaling，避免用全周期长跑代替定位。

试跑保持正式方案的关键机制和信息，缩短规模的部分明确列出。发现实现错误则在本阶段修复并重验；模型给出不符合直觉的行为先检查约束与输入，真实不利结果保留为观察。

安装阶段已验证的提供方和恢复链可复用其证据，但本次新增的机制、信息和测量仍须验证。模型预算与费用授权由已确认方案提供，避免逐命令重复询问。

## 4. 正式执行与监督

按批准的世界矩阵创建独立运行，记录初始化/分支来源及实际代码、依赖、模型参数。独立模型请求在服务承载范围内并发；共享可变业务状态的执行顺序按领域合同保持。未证实容量前先用小批次测量；逻辑上的平行世界可顺序运行。

监督依据真实 runner 状态、阶段计时、完整步骤和日志，低频检查或订阅完成事件，避免忙轮询。向用户报告新增进展、异常和需要改变安排的事实。进程仍存在但没有新进展时按阶段预期与服务状态调查；暂时等待期间继续可独立完成的分析和准备。

停止条件包括批准范围完成、预算触及、服务故障、无法维持既定机制、用户停止。只停止本任务拥有的运行与依赖队列，共享服务保持原状。通过 society0-workbench 传递真实运行引用与状态；接入未完成时保留本地证据与待交接状态。

## 5. 故障与恢复

按[运行与分析](run-monitor-analyze.md)定位首次受影响的事实、认知和完整点：

- 中途故障且之前可信：修复后从最近可信完整点新建运行；验证恢复后继续的业务与 Thread/记忆一致性。
- 起始设定错误：判断能否保留可信部分；无法保留时停止受影响运行并重新初始化，保留诊断证据。
- 纯分析/展示错误：原始事实未受影响时重算派生结果。
- 科学设定改变：明确变更、影响与费用，按用户选择建立新实验。

触及回合/上下文预算、输出截断或 provider 失败按实际未完成原因记录。恢复保留原消耗和失败身份。禁止通过新目录、增加硬上限、删除上下文或减少行动权限掩盖问题。

## 6. 结果与收尾

运行完成后继续做结果校核与解释，而非停在启动成功。按实验问题对齐预定测量窗口/群体/单位，允许不同世界拥有不同历史，说明共同比较口径。核对统计与原始事件，保留异常、零效应和失败样本。

交付每个问题的实际结果、作用路径证据与替代解释、资源用量、模型依赖和未覆盖因素，提供可重读的代码/配置/完整点/分析入口。按 society0-workbench 合同交接，核实回执；未接入部分明确列出。收集已结束后台任务结果，停止失去用途且属本任务的任务，保留原始运行。

可提出有新增价值的下一轮因素或测量选择；已批准的重复继续执行，新实验获得授权后返回设计或配置阶段。所有 todo 完成或有明确责任与恢复条件后，给出最终完成范围。
